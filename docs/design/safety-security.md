# Fors design: safety-security

> **Status: design-panel draft, 2026-09-19.** Produced by one subsystem architect working alone. Where this conflicts with `docs/PLAN.md` (section 4, Resolutions), PLAN.md wins. Cross-design conflicts are catalogued in `reviews.md`.

## Summary

Fors gets its safety from structure, not from annotation burden or runtime checks: mutable value semantics with four parameter conventions (let/inout/sink/set), destructive moves for heap resources, and strictly second-class (non-storable, non-escaping) projections, which together make lifetime variables and region inference unnecessary — the cost is that all aliasing graphs must go through branded arenas with index handles, and there is no Rc/RefCell port path. Race freedom is a second, orthogonal axis: four reference capabilities (iso/mut/imm/ro) with viewpoint adaptation, checked at zero runtime cost, gating what may cross a spawn/sync or actor boundary; determinism is a separate opt-in (@deterministic) because race freedom does not imply reproducibility. Error handling is register-returned typed failure (payload + tag) with no unwinder and no EH tables, plus a non-catchable cold trap path for contract, bounds and overflow violations — cheap, FFI-friendly, and small. Authority is module-declared (needs fs/net/exec/ffi/clock/rng/env) checked over the acyclic module graph and re-checked at link from signed binary module interfaces, narrowed at runtime by unforgeable capability values; FFI is itself a capability that taints its subtree as unguaranteed. The build system is declarative data with no executable build steps, so the xz-utils class of attack (payload only in build output) is structurally impossible; minimal-version selection plus a lockfile that pins each dependency's capability set turns "dependency silently gained net in a patch release" into a hard, human-approved build error, and the registry rejects such publishes. Contracts exist in the syntax from day one, are runtime-checked by default, and are statically discharged by our own VC generator feeding first a built-in abstract-interpretation discharger and only then an optional external SMT solver — a justified non-LLVM external tool, with content-addressed proof caching and timeout fallback to runtime checks. Side-channel resistance is a secret type qualifier whose guarantees are enforced not by trusting the optimizer but by a post-register-allocation constant-time verifier that both backends must pass, covering branches, secret-derived addresses, variable-latency instructions, and spill scrubbing. The whole thing is measured: a security conformance suite (Juliet subsets, adversarial package suite, race corpus, dudect timing, UB differential fuzzing) plugs into the Milestone 0 benchmark harness as a first-class benchmark family with pass-rate and false-positive metrics next to the performance numbers. Honest costs are flagged throughout: no interior mutability, arena-shaped graph code, no catchable exceptions, in-process plugins are integrity-checked rather than sandboxed, and speculative-execution side channels are explicitly out of v1 scope.

## Decisions

| Decision | Choice | Rationale | Risk |
|---|---|---|---|
| Core memory model | Mutable value semantics with four parameter conventions (let, inout, sink, set) + destructive moves for heap resources + explicit allocators; references are strictly second-class (scoped, non-storable, non-returnable). No lifetime annotations, no region inference in v1. | All accesses to a parameter are visible at the call site, so exclusivity is a local, near-linear flow check with no constraint solving — this is the only ownership design compatible with G3 (fastest compiler). Second-class references are what actually removes the need for lifetimes: a reference that cannot be stored cannot outlive anything. | Users cannot write Rust-style APIs that return borrowed views stored in structs; iterator/view-heavy code must be expressed via subscripts and yielding accessors, which is unfamiliar and will produce 'why can't I do this' friction. Mitigation: branded arenas (below) plus a generous set of built-in projection subscripts. |
| How users express graphs, doubly-linked/intrusive and self-referential data without lifetimes | First-class branded arenas: `with arena A: Arena<Node> { ... }` introduces a comptime-generated nominal brand type A; `Ref<Node, A>` is a 32/64-bit index usable only with that arena. Mutation goes through inout subscripts (`a[r]`), and a stdlib `a.pair_mut(i, j)` intrinsic (traps if i == j) covers link updates needing two mutable nodes. | The brand is an ordinary type parameter, not a region variable — zero inference cost, and it statically prevents cross-arena index confusion, which is the real bug class in index-based designs. Indices are only produced by that arena's allocate and the arena never shrinks, so bounds checks are eliminated structurally rather than by unsafe. Arena reset bumps a generation carried in the brand (debug-checked). | Arena code is more verbose than pointer code and cannot express 'free one node' without a free list; cross-arena graphs (two arenas referencing each other) need two brands in scope and get noisy. pair_mut is a runtime check on a hot path in list surgery. |
| Interior mutability policy | None in the safe sequential subset. Aliased mutation is expressed by (a) branded arenas, (b) `atomic<T>` fields, permitted only inside `shared`-capability types, (c) `@lazy` pure memoized fields whose initializer is comptime-proved pure and only on non-shared values. | Interior mutability is the single feature that would force either runtime aliasing checks (cost, dynamic failure) or a global aliasing analysis (compile time). Keeping it out is what makes both G1's structural aliasing facts and G2's race freedom sound by construction. | No direct port path for Rc<RefCell<T>>-shaped code and for observer/callback patterns; these must be restructured as arenas, event queues or actors. This will be the most common migration complaint. |
| Race-freedom mechanism and how it composes with MVS | Four reference capabilities as type qualifiers — iso (isolated/unique/sendable), mut (exclusive-mutable, non-sendable), imm (shared-immutable, sendable, freely copyable), ro (read-only view, non-sendable) — with Pony-style viewpoint adaptation and a `recover` block that promotes mut to iso when no non-sendable alias exists in the lexical scope. Conventions are the *access* axis, capabilities the *sharing* axis; only iso and imm cross a domain boundary (spawn, channel, actor message). Data-parallel `inout` sharing goes through a `split` combinator returning N provably disjoint inout views. | Zero runtime cost, no annotations on types (only on positions where sharing happens), and the check is a local lattice join — again compatible with G3. Orthogonality to conventions means the two systems do not multiply into a combinatorial mess: a position has one convention and one capability. | Two qualifier systems is a real learning-curve tax; Swift 6 shows even a single Sendable axis is hard to retrofit and still leaks races. `recover` scope rules are subtle and are the most likely place for an unsoundness bug. `split` is the one unsafe kernel the whole data-parallel story rests on. |
| Error handling model and failure ABI | Three disjoint mechanisms. (1) `trap`: contract, bounds, overflow, arena misuse — abort via a cold noreturn path with a static message table, not catchable, no unwinding. (2) Typed `throws E`: a function returning `T throws E` returns {payload, tag} in registers per platform ABI (sret when oversized); `try`/`or`/`?` sugar compiles to a cold conditional branch. (3) Option/explicit values for expected absence. No unwinder, no landing pads, no EH tables. Error values are move-only and may carry payloads; error sets are per-function declared, never globally inferred. | Unwinding is the single largest hidden cost in binary size, codegen quality, backend complexity and FFI friction — and implementing a personality routine and DWARF EH for aarch64/Mach-O ourselves without LLVM would be weeks of work for a feature that harms G1. Register-returned failure is what C, Zig and Go-ish results do well, is trivially callable from C, and lets the optimizer see the failure edge as ordinary control flow. | No recovery from traps inside a process: a contract violation in a long-running server kills it. Mitigated by actor/process supervision and by `--release` demoting internal contracts. C++ exceptions crossing FFI must be stopped by a generated `@catches_cxx` shim linking against the platform unwinder, which is a small but real external dependency; unwinding *through* Fors frames is unsupported and must be diagnosed. |
| Shape of the unsafe subset | `unsafe` is a declaration attribute with obligations, not a block: `@unsafe(invariant: "...")` on a function; raw pointers, reinterpret and assume intrinsics are only nameable inside such declarations. A module may only contain unsafe declarations if its manifest says `uses unsafe`, which propagates into the audit ledger and is visible transitively in the lockfile. | Making unsafety a declared, named, counted, module-level property turns it into the same kind of reviewable artifact as a capability — which is the differentiated claim. Block-level unsafe encourages sprinkling and defeats accounting. | Coarser than block-level unsafe: an otherwise-safe module needing one pointer trick must declare uses unsafe, which pushes people to dump unsafe helpers into a single 'sys' module (arguably good) or to over-declare (bad). Per-declaration granularity plus the audit report mitigate it. |
| Capability enforcement across dynamic linking and plugins | Two explicitly labelled tiers. Tier A `dylink`: a Fors dynamic module carries a signed binary module interface with its capability set; the loader verifies signature and refuses to resolve if the set exceeds what the host granted — an *integrity* guarantee, not a sandbox (same address space). Tier B `isolate`: plugin runs as a separate process with a typed IPC stub generated from the interface declaration and an OS-level sandbox (seatbelt/pledge-class), with per-plugin capability grants — the only real enforcement. Default for everything is static linking. | The module-graph check is a link-time guarantee; pretending it survives dlopen would be dishonest, and this is precisely the gap the research flagged. Naming the two tiers keeps the marketing claim truthful and gives users a real sandbox when they need one. | Tier B costs IPC latency and serialization, so it is unusable for hot-path plugins (exactly where HPC users want plugins). Tier A's honesty means we cannot claim 'capabilities survive plugins' unqualified. |
| Build system and package manager semantics | Declarative manifest data only — no build scripts, no executable build steps; code generation only via comptime with declared, content-hashed inputs. Minimal version selection (Go-style, no SAT solver). Lockfile pins per dependency: version, source-tree Merkle hash, capability set, unsafe-declaration count, publisher key id, toolchain hash. A resolved package whose capability set exceeds the locked set is a hard build error requiring explicit `fors grant`; the registry additionally rejects at publish time any patch/minor release that expands capabilities beyond the previous release's set (verified by re-running the module-graph check in the registry's own hermetic builder). | No build scripts removes the entire xz-utils attack class (payload present only in build output) and the entire ambient-authority-at-build-time class in one stroke. MVS keeps resolution fast and deterministic and — crucially — makes capability diffs small and reviewable, which a solver's churn would not. Registry-side enforcement is what makes semver mean something for authority. | No build scripts means legitimate needs (vendored C libraries, generated bindings, platform probing) must all be served by comptime + declared inputs + a first-party C-header importer; if any real need falls outside that, users will be blocked with no escape hatch, and we must add one carefully rather than in a panic. MVS gives older-than-optimal dependency versions and needs good tooling to surface available upgrades. |
| Contract static-discharge architecture | Our own VC generation from the mid-level IR into an internal VCIR, then a two-stage discharger: stage 1 is a built-in abstract interpreter (intervals, congruences, linear integer relations, non-nullness, ownership facts) with no external dependency and hard step budgets; stage 2 emits SMT-LIB 2.6 to an *optional external* solver (Z3 or cvc5) only for what stage 1 cannot close. Machine-typed semantics (bitvectors, wrapping/trap behaviour explicit, Verus-style), with ghost `int`/`nat` for specs. Obligations are content-addressed (hash of VC + solver id + options) into a proof cache that may be committed as a proof ledger; timeout or failure falls back to a runtime check plus a diagnostic, never to silent trust. | Writing an SMT solver is off-mission and not what NO-LLVM was about (a solver is not a codegen dependency and is not on the dev-build critical path). Stage 1 closes the overwhelming majority of real obligations — bounds, overflow, simple ranges — instantly and hermetically, so the common case needs no solver at all; that also keeps `fors verify` out of the incremental build budget. | Two dischargers means two places for soundness bugs, and a VC generator at IR level must model our own IR's semantics exactly — a divergence here produces unsound 'proofs'. External solver version changes invalidate proof caches and can flip results; the cache key must include the solver build. |
| Secret / constant-time guarantees and where they are enforced | A `secret` type qualifier forming a two-point taint lattice with join on operations. Static rules: no control flow on secret (only `@ct_select` and masked ops), no address or index derived from secret, no secret in contract/assert conditions, no secret through logging capabilities, and declassification only via audited `@declassify(reason)`. Per-target variable-latency instruction denylist (aarch64 SDIV/UDIV forbidden on secret; DIT bit set on entry to ct regions where available). Enforcement is by a post-register-allocation constant-time verifier that BOTH backends must pass, not by trusting passes: ct attributes ride the IR, `@ct_select` may never be lowered to branches, secret spill slots live in a dedicated scrubbed stack region whose stores are exempt from DSE and store-forwarding, and PGO/BOLT-class layout passes may not use secret-derived profile data or reorder inside ct regions. | Optimizers break constant-time code by doing their job correctly; the only durable design is verify-don't-trust at the end of the pipeline, which is affordable precisely because we own both backends and the final MIR. Owning the backends turns the usual LLVM constant-time headache into an advantage. | The verifier must model per-microarchitecture instruction timing, which is documentation-dependent and will be incomplete (Apple silicon timing details are not fully public). Speculative-execution leakage (Spectre-class) is out of scope for v1: `@spectre_hardened` adds barriers/masking opt-in with a stated cost. Claiming 'constant time' therefore needs the qualifier 'architecturally'. |
| Parallel determinism | Race freedom is guaranteed; determinism is an opt-in `@deterministic` region that (a) forbids lexical `@fastmath` and FP reassociation, (b) requires reductions to use a fixed deterministic tree shape whose chunking is part of the region's specification, (c) forbids work-stealing-order-observable operations. | The research correctly flags that these are conflated everywhere. Making determinism a named, costed opt-in lets HPC users choose reproducibility per kernel instead of paying for it globally, and lets the marketing claim be precise. | Deterministic reductions cost measurable performance (fixed tree shape defeats some scheduling freedom) and interact with the autotuned-schedule artifacts owned by the parallelism subsystem; the two must agree that a tuned schedule for a deterministic region is itself part of the contract. |
| UB-free semantic rules for the safe subset | Trap on integer overflow, division by zero and out-of-range shift in all modes, with explicit wrapping_/saturating_ ops and `unchecked_` only inside @unsafe declarations; no type-based strict-aliasing rule at all (aliasing facts come from conventions and arena brands, encoded structurally in the IR and never droppable metadata); an explicit provenance model separating `ptr` from `addr()` with exposed/synthesized casts; uninitialized storage is a distinct type `raw<T>` rather than a value of T, with `set` conventions as the only initializers; no invalid bool/enum bit patterns reachable from safe code; strict IEEE-754 with no FMA contraction or reassociation unless lexically enabled; and in the unsafe subset, races are defined as hardware tearing, never as a licence for the optimizer to derive facts. | Zero UB in the safe subset is also the only way two backends can be held to the same semantics — every piece of UB is a place where dev and release tiers are permitted to disagree, which for a safety-marketed language is fatal. The reference interpreter can then be a total oracle for differential testing. | Trap-on-overflow costs a compare-and-branch per arithmetic op unless the contract discharger proves ranges; on tight integer kernels this is the most likely place to lose the 5%-of-best-of-C target, which makes the stage-1 range discharger load-bearing for performance, not just for verification. |

## Design

## 1. Memory model

**Conventions.** Every parameter has exactly one: `let` (read-only access, no copy), `inout` (exclusive mutable access, caller's storage), `sink` (ownership transfer, destructive move), `set` (initialize an uninitialized `raw<T>`). Locals are `var`/`let`. Returns are always owned values. **No stored references anywhere in the safe subset** — this is the axiom that removes lifetimes.

**Exclusivity.** Checked per function over *projection paths* (`a.b[i].c`). A path and any prefix/suffix of it may not be simultaneously accessed with conflicting conventions. The check is one forward dataflow pass over the flat SoA IR with a small path-trie; no constraint graph, no fixpoint over calls (call effects are fully described by the signature). This is what keeps the safety check off the compile-time budget.

**Projections and accessors.** Interior access is exposed only via `subscript`s with convention-specific variants:

```fors
subscript(index i: Int) -> Element {
  let    { yield storage[i] }          // read projection
  inout  { yield &storage[i] }         // mutating projection
  sink   { ... }                       // consuming projection
}
```

A `yield`ed value is *scoped*: its type carries the `scoped` bit, so it cannot be stored in a field, put in a container, returned, or captured by an escaping closure. `Span<T>` / `MutSpan<T>` are scoped types. Two-level escape kinds (`escaping` | `scoped`) replace lifetime variables entirely: the rule is syntactic and decidable locally.

**Heap resources.** `Box<T>`, `Buffer<T>`, `File`, arenas are affine: moved destructively, deinitialized deterministically at end of scope or last use, never implicitly copied (`Copyable` is an explicit, derivable capability). At CFG merges each path must agree on liveness; disagreement is an error fixed with `consume x` or `discard x` — no dynamic drop flags, so no drop-flag codegen tax.

**Allocators.** `Buffer<T>` and `Box<T>` are parameterized by an allocator *value* (`inout A: Allocator`), passed explicitly. No global allocator, no hidden allocation anywhere; `@no_alloc` functions are checked transitively.

**Graphs, intrusive and self-referential structures.** Branded arenas:

```fors
with arena nodes: Arena<Node> {
  let a = nodes.alloc(Node{ next: none, prev: none })
  nodes[a].next = some(b)                 // inout subscript, one at a time
  nodes.pair_mut(a, b) { na, nb in na.next = some(b); nb.prev = some(a) }
}
```

`Ref<Node, nodes>` is an index branded by a comptime-generated nominal type. Brands make cross-arena confusion a type error; monotonic allocation makes bounds checks provably redundant (discharged by the stage-1 range analyzer, not by unsafe); `reset` bumps a generation checked in debug. Intrusive/SoA layouts are the same pattern with `Arena<SoA<Node>>`. Self-referential structs are arena refs. This is the whole graph story — no `Rc`, no `RefCell`, no weak pointers.

## 2. Reference capabilities

Qualifiers `iso | mut | imm | ro` with the lattice `iso ≤ mut ≤ ro`, `imm ≤ ro`. Field access performs viewpoint adaptation: reading a `mut` field through a `ro` receiver yields `ro`; through `imm` yields `imm`; `iso` fields may only be extracted by move. `recover { }` promotes `mut` to `iso` when no non-sendable alias of the result exists in the enclosing scope. Sendability = `iso | imm` only.

Interaction with conventions is orthogonal: a position is (convention, capability). Defaults: `let p: T` means `ro T` for non-Copyable T; `inout p: T` means `mut T`; `sink p: T` preserves the argument's capability.

Parallelism boundaries: `spawn`/`sync` (first-class IR instructions from the parallelism subsystem) require every capture to be `sink iso`, `imm`, or a disjoint `inout` view produced by `Span.split(n)` — the single audited unsafe kernel that mints N non-overlapping `MutSpan`s. Actors, channels and data-parallel combinators are libraries above this. Cost: zero runtime, no atomics in the stdlib's sequential paths.

## 3. Unsafe subset and its audit tooling

`@unsafe(invariant: "...")` on a declaration unlocks `rawptr<T>`, `reinterpret`, `assume`, `unchecked_*` arithmetic and `volatile`. A module containing any such declaration must say `uses unsafe` in its manifest; that fact is recorded in its signed BMI and in every downstream lockfile. Tooling: `fors audit unsafe` emits a signed inventory (per declaration: module, invariant text, callers, whether a differential test exists); the reference interpreter executes unsafe code with full provenance and aliasing checking; `--secure` build profile denies dependencies whose unsafe declarations lack an accompanying `@fuzz` entry point.

## 4. Failure ABI

`fn parse(s: ro Span<U8>) -> Node throws ParseError`

Lowering: result class is computed per (payload, error) pair — both small and register-passable ⇒ `{x0 = payload, x1 = tag}` on aarch64 (tag 0 = success); otherwise `sret` for the payload plus a register tag. `try f()` is `cbnz tag, .cold`. Error values are move-only and may own heap payloads. No unwinder, no `.eh_frame`, no personality routine, no cleanup landing pads — cleanup is ordinary straight-line deinit on the cold edge, visible to the optimizer. Traps (contract, bounds, overflow, arena generation) call `__fors_trap(site_id)`; site metadata lives in a separate section keyed by id, so the hot path carries one branch and no strings. C interop: `extern "c"` functions may map error tags to `errno`/negative returns declaratively; C++ exceptions are stopped at a generated `@catches_cxx` shim (the only place we link the platform unwinder) and converted to tags.

## 5. Capability system

Manifest per module:

```
module img.decode
imports core.mem, core.simd
needs   { }                     // pure compute: no authority at all
```

Checked set of a module = declared ∪ transitive(imports), with explicit `grants net to http` required to pass authority down. Violations are compile errors at the module-graph level (cheap: a set union over the DAG the frontend already builds) and re-checked at link from signed BMIs, so a swapped-in prebuilt module cannot smuggle authority. Runtime narrowing uses unforgeable values: `main(p: sink Program)` receives the roots; `p.fs.open_dir("data") -> Dir` narrows; `Dir`, `Socket`, `Clock`, `Rng`, `Exec` are `sealed` (no public constructor). `ffi` is a capability; an `ffi` module is marked `unguaranteed` and taints its subtree in the ledger. Plugins: tier A `dylink` (signature + BMI capability check at load — integrity only, same address space) and tier B `isolate` (separate sandboxed process, typed IPC stubs generated from the interface — real enforcement). Both are labelled as such in documentation and in `fors audit`.

## 6. Comptime sandbox

Bytecode VM, deterministic by construction: no capabilities, no addresses observable, no FP nondeterminism, fixed hash-map iteration order, no clock, no RNG. External data enters only via declared inputs (`@comptime_input(path)`) that become content-hashed edges in the build graph. Per-evaluation step and allocation budgets, declared in the manifest, with the error naming the offending declaration. Results are content-addressed and cached, so comptime is a pure function from (code hash, input hashes) to bytes — which is also what makes reproducible builds trivial.

## 7. Build system, package manager, registry

Manifest and lockfile are **data**; there is no build-script mechanism at all. Resolution is minimal version selection. Lockfile entry: `{name, version, tree_hash, caps, unsafe_count, signer, attestations}`. Rules:

- Resolved `caps ⊋ locked caps` ⇒ hard error; `fors grant <dep> <cap>` records human approval with a reason string.
- Registry re-runs the module-graph capability check in its own hermetic builder at publish time and **rejects** patch/minor releases that widen capabilities.
- Publishes are immutable and append-only, signed (keyless OIDC or maintainer key), recorded in a Merkle transparency log; clients verify inclusion proofs offline.
- Audits are in-repo data (`audits.toml`, delegable to trusted orgs' published audit sets — cargo-vet's model, built in rather than bolted on).
- Reproducibility: fetch and build are separate phases; build is hermetic (no network, no ambient env, normalized paths, no timestamps, pinned toolchain hash); `fors build --check-repro` double-builds and diffs; the registry publishes its own rebuild hash so a source/artifact divergence (the xz pattern) is detectable and, with no build scripts, not expressible in the first place.
- `fors audit` prints the ledger: dependency, hash, signer, capabilities (with diffs vs previous version), unsafe count, audit status.

## 8. Contracts

```fors
fn dot(a: ro Span<F64>, b: ro Span<F64>) -> F64
  requires a.count == b.count
  ensures  result.is_finite() or a.has_nonfinite() or b.has_nonfinite()
```

Plus `invariant` on types, `decreases` for termination, `ghost` declarations erased in codegen, `pure` for spec-usable functions. Runtime-checked by default; `--release` keeps public-boundary preconditions and drops obligations that were discharged. Pipeline: mid-level IR ⇒ VCIR ⇒ stage 1 (intervals/congruences/linear relations/ownership facts; no external dependency; step-budgeted) ⇒ stage 2 (SMT-LIB 2.6 to Z3/cvc5, optional external tool, per-obligation timeout) ⇒ unresolved obligations fall back to runtime checks with a diagnostic. Proof cache keyed by `hash(VC, solver_id, options, machine-type model)`, storable as a committed proof ledger. `fors verify` is a separate tier — never on the incremental build path. Stage 1 doubles as the bounds/overflow-check eliminator, which is how trap-on-overflow stays affordable.

## 9. Secret types and backend obligations

`secret U64`, `secret Span<U8>`. Static: no branch/loop/match on secret; no index or pointer derived from secret; no secret in assertions or contracts; no secret through a logging or I/O capability; `@declassify(reason)` audited like unsafe; division/modulo/`memcmp` on secret forbidden in favour of `ct_div`, `ct_eq`.

Both backends must guarantee, and a **post-regalloc CT verifier** must independently confirm: `@ct_select` never lowered to control flow; no if-conversion or branch synthesis inside ct regions; secret spill slots allocated in a dedicated region, stores marked `secret_volatile` (exempt from DSE/store-forwarding), zeroized in the epilogue; no variable-latency instruction on secret operands per a per-target denylist (aarch64 SDIV/UDIV; DIT bit set where available); no constant folding across declassification; PGO/layout passes may not consume secret-derived profile data or reorder within ct regions; inlining/CSE must propagate ct attributes. Speculative leakage is explicitly out of v1 scope; `@spectre_hardened` adds masking/barriers opt-in with a documented cost.

## 10. Security conformance suite (plugs into the Milestone 0 harness)

New benchmark family `security`, same stdlib-only Python runner, same JSON schema plus `pass_rate` / `false_positive_rate`:

- **S1 Juliet subsets** — CWE-121/122/124/126/127, 190, 401/415/416, 476, 134, ported kernel-by-kernel; expectation per case is `rejected-at-compile` or `traps`, with the "good" variants scoring false positives. Reported alongside C/C++ and Rust baselines.
- **S2 adversarial package suite** — ~40 malicious dependencies: build-time exfiltration attempt, comptime file/network read, transitive capability escalation in a patch release, typosquat, dependency confusion, unsigned artifact, tampered transparency log, source/artifact divergence, FFI shim opening a socket, plugin requesting ungranted authority. Target metric: 100% confined.
- **S3 race corpus** — known-racy programs (Go/Swift-6 corpus ports) that must fail to compile; plus race-free-but-nondeterministic programs that must compile and be flagged only under `@deterministic`.
- **S4 constant-time** — AES, X25519, RSA blinding kernels under dudect statistical timing plus the CT verifier, on both backends.
- **S5 UB differential** — IR random-program generator, reference interpreter as oracle, three-way diff across interpreter / dev backend / release backend; any disagreement is a release blocker.

CI gates on regression in any suite; the report renders security pass rates next to compile-time and runtime numbers, so G2 is measured rather than asserted.

## Interfaces other subsystems must honor

- Frontend/IR: the flat SoA IR must carry, as non-droppable structural fields (not optional metadata), per-operand parameter convention, reference capability, escape kind (escaping|scoped), arena brand id, secret taint bit, and ct-region membership. Any pass that drops these must fail the IR verifier. This is also the mechanism G1 relies on for aliasing facts.
- Frontend: module manifests are part of the module graph; the capability set union and the acyclicity check run in the same pass, and the per-declaration query DAG must key capability results so LSP can report authority errors incrementally.
- Frontend: binary module interfaces must include capability set, unsafe-declaration count, contract signatures (requires/ensures), secret-qualified signatures, and a signature over all of it; the link step re-verifies.
- Backends (both tiers): must implement the failure ABI class computation identically, must preserve @ct_select and secret_volatile semantics, must not synthesize branches in ct regions, must support a dedicated scrubbed secret stack region, and must pass the shared post-regalloc CT verifier. Identical semantics for trap-on-overflow in both tiers is non-negotiable.
- Backends: no UB means no pass may derive facts from absence of races, from strict type-based aliasing, or from uninitialized memory; the only aliasing facts available are the structural ones the frontend supplies.
- Parallelism subsystem: spawn/sync IR instructions must enforce capture rules (sink iso | imm | disjoint inout from split); autotuned schedule artifacts for @deterministic regions are part of the region's contract and must be reproducible, not machine-dependent.
- Parallelism subsystem: reductions inside @deterministic regions must use the fixed tree shape and may not be reassociated; fast-math scopes are forbidden there.
- Toolchain/driver: build phases are fetch (network, capability: net) and build (hermetic, no network, no ambient env); the driver must expose --check-repro, and comptime declared inputs must appear as build-graph edges.
- Reference interpreter (correctness infra): is the authority for provenance, initialization, arena generation, and unsafe-code checking; must be able to execute contracts and report which obligations were exercised, feeding the verification coverage report.
- Benchmark harness (Milestone 0): add a `security` family with pass_rate and false_positive_rate fields in the existing JSON result schema, plus a per-suite baseline column for C/C++/Rust; reuse the checksum correctness gate for kernels that also appear in the performance families.

## Top risks

- No interior mutability and no first-class references means whole familiar API shapes (observer patterns, cached views, Rc<RefCell<>> graphs, returning iterators over owned data) have no direct translation. This is the single largest adoption risk in my subsystem and it is a design consequence, not a bug — the mitigation is an excellent arena/subscript/accessor stdlib and a written porting cookbook, and honest documentation that some designs must be restructured.
- Two orthogonal qualifier systems (conventions x reference capabilities) plus branded arenas is a lot of surface for one developer to keep sound. The recover-scope rule and the split combinator are the two places where an unsoundness bug would silently invalidate the entire race-freedom claim; both need adversarial test suites written before the implementation.
- Trap-on-overflow in all modes puts the stage-1 range discharger on the performance critical path for G1. If it underperforms on real integer kernels, Fors loses the within-5%-of-best-of-C target on exactly the workloads HPC users care about, and the temptation will be to add release-mode wrapping — which would recreate the dev/release semantic divergence this design exists to prevent.
- No unwinding means a contract or bounds violation is fatal to the process. For long-running services this is worse than Rust's catch_unwind story; the actor/process supervision answer is real but not free, and some users will consider this disqualifying.
- The capability guarantee is a static-link-time guarantee. In-process plugins (tier A) are integrity-checked, not sandboxed, and real enforcement (tier B) costs IPC. Any marketing that blurs this line will be correctly attacked, and the adversarial suite must include an in-process plugin case that we openly score as 'integrity only'.
- Constant-time enforcement depends on per-microarchitecture variable-latency instruction data that is incompletely documented, especially on Apple silicon. The verifier will be conservative in some places and wrong in others; the claim must be scoped to 'architecturally constant time' with speculative channels explicitly excluded, and dudect must run on real hardware as a backstop rather than being treated as redundant.
- Zero build scripts is the strongest supply-chain lever and also the biggest ecosystem bet. If a legitimate need (vendoring a C library, probing a platform, generating bindings from a non-Fors source of truth) falls outside comptime-with-declared-inputs, users will be hard-blocked and the pressure to add an escape hatch under deadline is exactly how this class of protection dies. Enumerate the needs now and serve them first-party.
- Our own VC generation against our own IR semantics means an IR semantics bug produces unsound proofs that then remove runtime checks. Proofs must only ever remove checks that the reference interpreter also validates on the differential corpus; any obligation discharged statically should remain runtime-checked in the interpreter tier forever.
- Scope: this subsystem alone is roughly 60-80 developer-weeks of exit-criteria work before v0.1, on top of frontend and two backends. The realistic ordering inside v1 is M-S1/2/3 (semantics and ABI, everything else depends on them), then M-S4/5 (the most differentiated claim), then M-S6/7. If schedule pressure comes, contracts' static discharge and secret types are the only parts that can ship later without invalidating earlier semantics — and saying so now is cheaper than discovering it under pressure.

## Decision points for Marc to code personally

- crates/fors_sema/src/refcap.rs :: fn viewpoint_adapt(receiver: Cap, field: Cap) -> Cap — the 4x4 lattice table. Trade-off Marc decides personally: whether reading a `mut` field through an `imm` receiver yields `imm` (deep immutability, stronger guarantee, forces recover in more places) or `ro` (shallower, more permissive, weaker sendability). 6 lines, and it sets the character of the whole capability system.
- crates/fors_sema/src/exclusivity.rs :: fn conflicts(a: Access, b: Access) -> bool — the convention conflict matrix over (let, inout, sink, set). Trade-off: whether two simultaneous `let` projections into overlapping paths are allowed (yes = ergonomic, but then `let` cannot imply no-alias for the optimizer; no = better G1 aliasing facts, more rejected programs). 8 lines that decide how much aliasing information the backend gets for free.
- crates/fors_abi/src/failure.rs :: fn failure_class(payload: &Layout, error: &Layout, triple: &Triple) -> FailureClass — the threshold where {payload, tag} in registers gives way to sret. Trade-off: a larger register budget means fewer memory round-trips on the happy path but more register pressure across every call. 10 lines, directly measurable in the benchmark harness.
- crates/fors_pkg/src/capdiff.rs :: fn classify_cap_change(locked: &CapSet, resolved: &CapSet, bump: SemverBump) -> Verdict — the policy function for 'a dependency gained a capability'. Trade-off: hard error on any widening (safest, most friction) vs. error only for fs/net/exec/ffi and warn for clock/rng/env (usable, smaller guarantee). 7 lines that define what Fors's supply-chain promise actually is.
- crates/fors_sema/src/secret.rs :: fn join(a: Taint, b: Taint) -> Taint plus the declassification predicate. Trade-off: whether comparison results on secret operands are themselves secret (yes = correct but makes every ct algorithm mask-based; no = a leak channel unless the branch rule catches it). 5 lines at the heart of the side-channel guarantee.
- crates/fors_backend/src/ct_verify.rs :: fn is_ct_safe(target: &Target, op: &MachineOp) -> bool — the per-target variable-latency denylist for aarch64. Trade-off: conservative (ban variable shifts and multiplies too, costing performance in ct code) vs. precise (trust Apple's DIT bit, risking a gap on cores without it). 10 lines where honesty about unknown microarchitecture beats cleverness.
- crates/fors_comptime/src/budget.rs :: fn charge(&mut self, steps: u32, bytes: u32) -> Result<(), BudgetExceeded> — the comptime budget policy. Trade-off: a fixed global default (predictable compile times, blocks legitimate heavy metaprogramming) vs. a per-module declared budget (flexible, but a dependency can declare a huge one and tank your build). 6 lines that keep G3 safe from metaprogramming.
- crates/fors_sema/src/arena.rs :: fn brand_compatible(r: &RefTy, a: &ArenaTy) -> bool and the generation rule on reset. Trade-off: whether `reset` produces a fresh brand (statically invalidates all old Refs, maximum safety, but arenas cannot be reused across a loop body without re-branding) or keeps the brand and relies on a debug-only generation counter (ergonomic, release-mode UAF risk becomes a logic bug rather than a trap). 8 lines, and it is the honest crux of arena safety without lifetimes.
