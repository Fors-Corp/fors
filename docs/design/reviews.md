# Fors design: adversarial reviews

> Three reviewers read all five subsystem designs together (2026-09-19). Resolutions adopted are in `docs/PLAN.md` section 4.

## Lens: coherence

**Verdict.** Coherent enough to proceed, but not coherent enough to start coding. The five designs agree on mechanisms to a genuinely unusual degree — Tapir fork/join, conventions-plus-affine-moves, trap-everywhere, capability-confined declarative builds, one interpreter as oracle — and every one of the twenty-one blocking conflicts I found reduces to the same structural defect: six cross-cutting facts have two or three claimed owners with different values. Those facts are (1) the qualifier/capability set, (2) the failure ABI and trap mechanism, (3) the reduction-determinism constant, (4) the comptime engine and its budget policy, (5) the capability declaration site and what `ffi` taint means, (6) which IR level owns tiles, secrets and alias-class sources. Fix ownership with six normative spec chapters and a CI rule that other documents may only cite them, and most of this list evaporates. Three conflicts are not bookkeeping and will change designs: the escape rules forbid returning the scoped values that `split_at` and the entire stdlib depend on, so either a single-parameter scoped-return rule is added or there is no slice API and no storable string; shape-based generics cannot express an indirect call inside a lane-masked region, so `@specialize` must become mandatory in vector and device code, which spends G3 margin to buy G1; and 'domain abort at a spawn boundary' is a claim with no mechanism — no unwinder plus pooled fibers plus scope arenas means abort-only, and the compiler architect asked for the restart story and did not get one. On sequencing: the roadmap plans a sea-of-nodes mid-IR the compiler architect rejected, gates the riskiest milestone at a number the compiler architect would call success, builds the dev backend before the semantics it lowers, freezes the semantics after the optimizer that depends on them, and schedules the constant-time spill class five years after the allocator it must live in. Three of those four are free to fix today. The plan's largest single coherence risk is not any individual conflict: it is that the sequence of record was built against the roadmap architect's model of the other four designs rather than against the designs themselves.

### Blocking issues

1. **The type qualifier set is specified three incompatible ways. safety-security defines FOUR reference capabilities (iso/mut/imm/ro) with a 4x4 viewpoint-adaptation table and a `recover` block. surface-language explicitly collapses to THREE qualifiers (iso/imm/secret) on the grounds that conventions already give exclusive-mutable and read-only — and puts `secret` (a taint axis) inside the same lattice. parallel-heterogeneous's hard requirement on the memory model demands FOUR ('isolated / exclusive-mutable / shared-immutable / read-only as first-class types, not attributes'). Every function signature in the language, the whole stdlib, and the spawn-capture rule depend on which is true. safety's headline Marc contribution point (`viewpoint_adapt(receiver: Cap, field: Cap)`, a 4x4 table) does not exist if surface is right; parallel's capture rule does not typecheck if surface is right. Separately, safety's own text references a `shared` capability ('atomic<T> permitted only inside shared-capability types') that appears in none of its four.**
   - Where: safety-security, surface-language, parallel-heterogeneous
   - Fix: Adopt surface's TWO sharing qualifiers (iso, imm) — conventions genuinely supply exclusive-mutable (inout) and read-only (let) at function granularity — and make `secret` a strictly orthogonal one-bit taint that is never joined with the sharing lattice. Rewrite safety's viewpoint adaptation as a 2x2 table plus an iso-extraction-by-move rule; add `recover` to surface's grammar and keyword table (it is currently absent, so safety's mut->iso promotion is unexpressible). Delete safety's phantom `shared` capability; aliased-mutable-with-atomics becomes surface's stdlib `Shared[T]` with an atomic-only API, declared as a third sendable form in the sendability rule and as one audited unsafe kernel. One normative spec chapter owns the qualifier set; the other four designs may only cite it.
2. **The reduction-determinism constant — the single most differentiated claim in the whole plan, and a results-visible constant that cannot be changed after publication — is parameterized three mutually exclusive ways. compiler: `reduce.tree(width=W)` where tree shape is fixed by the DECLARED width 'not by the machine's actual vector length', giving bit-identical results on a 128-bit and a 512-bit machine. parallel: fixed leaf blocks of `B = 4 * native_lanes` — which IS the machine's vector length, so parallel's default tier is explicitly only run-reproducible (D1), and portability across widths is a separate opt-in tier (D2). surface: 'bit-reproducible for a given (n, grain)' — a third parameterization, where grain is the compiler-computed, cost-model-derived, `.fmach`-calibrated scheduling grain, meaning a machine-calibration data change silently changes floating-point results. On top of that, safety makes determinism an OPT-IN `@deterministic` region while parallel makes D1 the DEFAULT and surface makes `order: tree` the default with `order: any` as the opt-out.**
   - Where: compiler-architecture, parallel-heterogeneous, surface-language, safety-security
   - Fix: Reduction tree shape is a function of (n, B) only, where B is a target-independent literal declared in the IR op (default e.g. 256 elements), never derived from native_lanes, never from grain, never from thread count. Then D1 == D2 for reductions and compiler's cross-width claim becomes true. Vector width and grain may vary freely without changing results. Determinism is default-on via the reduction operator's default order; delete safety's `@deterministic` region attribute as a redundant second mechanism with undefined precedence (as written, `@fastmath` inside a `@deterministic` region is simultaneously forbidden by safety and lexically permitted by compiler/surface). Merge the three duplicate Marc contribution points (parallel's `reduction_block_size`, roadmap's `reduction_order()`, surface's ch07 clause) into one decision in one file. Additionally: `fastmath(reassoc)` must be forbidden on hand-written scalar accumulation loops (surface's own nbody example does exactly this), because reassociation there makes the result depend on the vectorizer's chosen width — reassoc is legal only inside `reduce`/`simd` regions where the shape is declared.
3. **The failure ABI is specified four times with four different mechanisms, and one of the specifications is arithmetically impossible. compiler: errors in 'the normal register set via Fors's own internal calling convention'. safety: `throws E`, `{payload, tag}` with tag 0 = success in x1, sret when oversized, and traps via a `__fors_trap(site_id)` CALL. surface: `raises E`, error in 'a second return register (aarch64 x1 / x8-sret + flag)'. roadmap: a Marc point in `fors-sema/src/failure.rs` that re-opens unwinding as a live option after three designs excluded it. Impossibility: on AAPCS64 a 16-byte-or-smaller aggregate return already occupies x0 AND x1, so `fn f() -> Vec2 raises E` where Vec2 is 16 bytes has no register left for safety's tag; and x8 is the sret POINTER register, so surface's 'x8-sret + flag' names no register for the flag. Also compiler's one-instruction `brk #1` trap and safety's `__fors_trap(site_id)` call are materially different costs — the call needs site_id materialization plus a branch-with-link, which destroys the 'one instruction per check' property that makes trap-on-overflow-in-all-modes affordable, and trap-everywhere affordability is load-bearing for G1.**
   - Where: compiler-architecture, safety-security, surface-language, roadmap-execution
   - Fix: One crate (`fors-abi`), one file (`failure.rs`), one normative chapter authored by surface and implemented by compiler. Keyword: `raises` (surface owns syntax). Status tag goes in a register OUTSIDE the C value-return set — x9 is caller-saved, unused by the C return convention, and `raises` functions are never `extern "c"` anyway — so error returns compose with any payload size including 16-byte aggregates. Note that compiler's stated reason for rejecting a reserved error register ('conflicts with C ABI interop') is wrong for exactly this reason. Traps are `brk` plus a pc-keyed static side table, never a call. Delete roadmap's `FailureAbi` Marc point; it re-litigates a settled decision in a third crate.
4. **`secret` and constant-time have no home anywhere in the compiler architecture. safety requires the secret taint bit and ct-region membership as non-droppable structural IR fields all the way to post-register-allocation, a dedicated scrubbed secret spill region exempt from DSE and store-forwarding, `@ct_select` that may never be lowered to a branch, a per-target variable-latency denylist, and a post-regalloc CT verifier that 'BOTH backends must pass'. The compiler design's six-level IR table mentions secret at no level, its pass list contains no CT verifier, its frame layout has no scrubbed region, its SSA chordal register allocator has no tainted spill class, and its interfaces_to_other_subsystems list omits secret types entirely — while it DOES include an aegraph constant-folding mid-end, if-conversion ('arm64 csel is cheap'), Ext-TSP PGO block layout and cold outlining, every one of which safety constrains and none of which knows it.**
   - Where: compiler-architecture, safety-security
   - Fix: Add `secret` (one bit) and `ct_region` (region id) as mandatory operand/region fields at every level from FMIR through LIR, verified by `--verify-each` exactly like alias classes. Add a spill-class parameter to the register allocator. Make the CT verifier a mandatory post-regalloc pass in `fors-lir` shared by both tiers. Critically, do this WITH the allocator (compiler C6 / roadmap M5), not at roadmap M12: retrofitting a tainted spill class and non-reordering regions after PGO and layout passes exist costs multiples of designing it in. Also forbid `secret` inside `kernel`/`@device` and `@tensor` code outright — constant-time cannot be guaranteed through a vendor source compiler (MSL via `newLibraryWithSource`) or a vendor graph compiler, and no design currently says so.
5. **The tile level has no home in the compiler's pipeline. parallel defines `tile.load/store/dot/reduce/scan/sync` plus a tiling / shared-memory-staging / coalescing pass as the core of the GPU story (explicitly 'most of Triton's value'). compiler says `kernel` regions are outlined 'at OIR level' — but OIR is defined as pure CFG-SSA with LOW types ('scalars/vec<T,N>/ptr+provenance') and fixed comptime vector widths. You cannot run a tiling and shared-memory-staging pass on an IR where arrays have already been lowered to pointer+provenance and vector widths are already fixed. As written, roadmap M9 and parallel M5 are unbuildable on the compiler's pipeline.**
   - Where: compiler-architecture, parallel-heterogeneous
   - Fix: `tile.*` lives in FMIR, which still has arrays, layouts, conventions and isolation domains. The device pipeline forks from FMIR BEFORE OIR lowering: tiling, staging and coalescing run on FMIR tile ops, and OIR is used only for the host side plus the scalar bodies inside an already-tiled kernel. Correspondingly, the `kernel` region's capture list must be typed with conventions and qualifiers at FMIR and carried as an explicit operand (exactly like `detach`'s capture list), because by OIR the isolation-domain facts that make device memory safety work have been erased into alias classes. Also reconcile the level naming: parallel's `pir` and compiler's FMIR are the same IR under two names; pick one before either team writes a verifier.
6. **The keystone primitive of all safe parallel mutation returns a value that the memory model forbids returning. safety's escape rule is absolute: a scoped value 'cannot be stored in a field, put in a container, returned, or captured by an escaping closure', and `Span`/`MutSpan` are scoped types — this two-level escape kind is precisely what replaces lifetimes. surface's `split_at` signature is `fn split_at(inout self: SliceMut[T], mid: usize) -> (SliceMut[T], SliceMut[T])`, i.e. it returns two scoped values, and surface names this the keystone on which 'everything in std.parallel is built'. The same violation hits the whole stdlib: surface's `Str = imm Slice[u8]`, so `struct Person { name: Str }` stores a scoped type in a field, and surface's own example returns `Own[Slice[u8]]`, which stores a scoped type on the heap. Under safety's rules, no slice-returning API exists at all — no subscript range, no `iter`, no `chunks` — and `map`, `json` and `fmt` are unwritable.**
   - Where: safety-security, surface-language, parallel-heterogeneous
   - Fix: Add exactly one narrow, locally decidable scoped-return rule: a function may return a scoped value iff every scoped derivation in the return flows from exactly one designated parameter, and the return is marked `scoped`. That is one bit of provenance, not a lifetime variable, and it is checkable in the same forward pass as exclusivity. Then `split_at`/`chunk_mut` are legal as written. Separately, `Str` as a storable type must be an OWNING type distinct from the non-owning scoped `Slice[u8]` — decide this before the stdlib signatures are authored, because it changes every string-bearing struct in the language.
7. **No design defines exclusivity for a varying index, which is the core access pattern of every kernel in the benchmark suite. safety's exclusivity check operates on projection paths and rejects conflicting simultaneous access to overlapping paths. surface restricts safe mutation inside `parallel for` to 'disjoint-by-construction projections (chunk_mut, split_at)' and explicitly refuses general index analysis. Yet surface's own mandelbrot example writes `out[x] = it trunc_as u8` inside `simd for x in 0 ..< w` with `out: inout SliceMut[u8]` — many lanes writing overlapping paths of one `inout` at a varying index. The same hole exists for every GPU kernel (`y[i] = ...` at `gpu.gid.x`) and for the tile ops. There is no rule that makes these legal and no rule that makes them illegal.**
   - Where: surface-language, safety-security, parallel-heterogeneous
   - Fix: Specify one rule used identically by `simd for`, `parallel for` and `kernel`: a varying store to an `inout` slice is legal iff the index is the region's induction variable or an affine `a*i+b` with compile-time-nonzero `a` (injective by construction, no index analysis required); every other pattern requires a `split`-minted disjoint view or an explicit scatter API with defined conflict semantics. This is the same rule that answers surface's own 'hardest checker in the design' risk, and it must be in the spec before the SPMD lowering is written, not discovered by the first user.
8. **Shape-based generic lowering and the SPMD model are incompatible in exactly the code that G1 and G4 depend on. surface's default lowering is shape-based: a generic call goes indirect through a witness table, and `dyn T` has the identical representation 'so there is no perf cliff'. parallel writes `fors.math` (the entire scalar+vector libm) in Fors using `spmd`, and its reduce/scan combinators are generic. But a witness-table indirect call inside a `varying` (lane-masked) context is not merely slow — it is not expressible: different lanes would need different callees, and neither design has a per-lane indirect-call mechanism. Nobody noticed this; surface flags shape-based lowering as its top G1 risk but frames it as a percentage, not as an expressibility failure.**
   - Where: surface-language, parallel-heterogeneous
   - Fix: Make `@specialize` mandatory and compiler-enforced on any declaration containing a `simd`/`spmd`/`vector_for` region, a `Vec[N,T]` operation, or a `tile.*` op: shape-based lowering is ILLEGAL in vector and device code, and a generic call with an unspecialized witness inside a varying context is a compile error with its own diagnostic code. Document the consequence that all std numeric and SIMD combinators are monomorphized, and that this eats directly into the G3 compile-time margin — which is the real G1-vs-G3 tension and should be stated once, honestly, rather than three times as a risk.
9. **Two incompatible stories for graph-shaped data, with opposite public claims. safety designs first-class branded arenas (`with arena A: Arena<Node>`, `Ref<Node, A>` branded by a comptime-minted nominal type, `pair_mut`, generation-on-reset) and claims the three reference data-structure programs 'type-check with zero unsafe declarations outside the stdlib kernels'. surface has only an unbranded `Handle[T]` (no `with arena` construct in the grammar, no `pair_mut`, no brand) and states in its own risk list that 'doubly-linked structures, back-pointers, observer graphs and intrusive lists need `unsafe` or index indirection'. One of these is the language's answer to 'memory safety without lifetimes' and the other concedes the hole. Also, safety's example writes `Ref<Node, nodes>` — a VALUE name in type-argument position — for which surface's context-free type grammar has no production.**
   - Where: safety-security, surface-language
   - Fix: Adopt safety's branded arenas wholesale (they are the only designed safe-graph story) and retract surface's concession. Spell the brand as a qualified type path so the grammar stays context-free: `with arena nodes: Arena[Node]` introduces both the value `nodes` and the type `nodes.Brand`, and the handle type is `Handle[Node, nodes.Brand]` — a declaration, not an inference. Add the `with arena` binder and the qualified-type-path production to surface's grammar file; resolve the reset-vs-fresh-brand question once (safety's own Marc point) rather than in two places.
10. **'Domain abort at a spawn boundary' is a claim with no mechanism, and the compiler architect explicitly asked for the mechanism and did not get it. surface states `panic` 'aborts the process, or the isolation domain at a spawn boundary'. compiler's risk section says the no-unwinder decision 'needs an isolation-domain-level restart story from the parallelism/runtime architect'. parallel provides none: it has no supervision or restart design, and its runtime makes domain abort impossible — a `brk` trap on a stolen continuation running on a pooled fiber, with no unwinder and no CFI, cannot unwind that fiber's stack, cannot run deinits, and cannot release the worker's per-scope bump arena or any `Shared` state. safety points at 'actor/process supervision' while both safety and parallel classify actors as libraries, so nobody owns supervision.**
   - Where: surface-language, parallel-heterogeneous, compiler-architecture, safety-security
   - Fix: Delete domain abort from v1. Trap = whole-process abort, stated plainly and prominently (it is a genuine disqualifier for some users and pretending otherwise is worse). The only supported partial-failure unit is a separate process, which both designs already have: safety's tier-B `isolate` plugin and parallel's locale-per-process. That makes the distributed layer the supervision story, and it is implementable. Then close the follow-on gap: the error ABI has no representation for 'peer locale died', and parallel's 8-byte frame header has epochs but no liveness/death detection — specify both, or `on loc { ... }` hangs on the first trap.
11. **Two independent check-elimination engines with overlapping authority and contradictory soundness rules. compiler puts check elision in OIR ('symbolic range + dominating-predicate analysis kills bounds and overflow traps... This is where safety is free is actually earned'). safety puts it in the stage-1 abstract interpreter over VCIR, with an exit criterion of '>=90% of bounds checks and >=80% of overflow checks' eliminated by stage 1, and a hard soundness rule that 'proofs must only ever remove checks that the reference interpreter also validates' and that statically discharged obligations 'remain runtime-checked in the interpreter tier forever'. compiler's OIR pass removes checks with no proof artifact and no interpreter cross-check at all. Both claim to be the mechanism that makes trap-on-overflow-everywhere affordable, i.e. both are load-bearing for G1.**
   - Where: compiler-architecture, safety-security
   - Fix: One code-removal authority: the OIR pass is the only thing permitted to delete a check, it is local and fast and stays on the incremental path. The stage-1 discharger runs on VCIR for CONTRACT obligations only, never deletes code, and instead emits `assume` facts carrying a content-addressed proof-cache key that the OIR pass may consume — which also keeps `fors verify` off the build budget exactly as safety wants. Restate safety's M-S6 exit criterion accordingly; as written it measures the wrong engine.
12. **Comptime is one engine in one design and two in three others, and the performance fix for it breaks reproducibility. compiler's self-described highest-leverage decision is a SINGLE FMIR interpreter serving comptime, const-eval, Miri-class reference semantics and the differential oracle. safety describes a separate 'bytecode VM'; surface says comptime runs on 'the pure budgeted VM'; roadmap M1 lists 'comptime bytecode VM' AND 'reference (Miri-class) IR interpreter' as two deliverables. Worse, compiler's fix for Zig-class comptime slowness is tier-up to the dev backend running natively in-process, which directly contradicts safety's comptime determinism requirements ('no addresses observable', fixed step budgets): native execution makes allocation addresses observable, so a comptime result can depend on ASLR, which breaks bit-identical rebuilds — the flagship supply-chain claim — and the step budget cannot be enforced without instrumenting the generated code.**
   - Where: compiler-architecture, safety-security, surface-language, roadmap-execution
   - Fix: One engine (compiler's). Edit roadmap M1 and safety §6 to say so. Permit tier-up only for comptime bodies whose FMIR provably contains no pointer-to-integer exposure and no address observation (a syntactic op-set check), with the step budget charged per back-edge and per call in the generated code (one add+cmp per back-edge) and the deterministic allocator retained — so the JIT and interpreter tiers are observationally equivalent, which is also what makes compiler's own 'JIT entitlement may be unavailable' fallback safe. Merge the two duplicate `charge()` Marc points, which currently state different trade-offs in different crates.
13. **Capability declaration has two authoritative sites with no stated precedence, the runtime narrowing it promises is unenforced, and the stdlib taints every program. surface's module header declares `needs { io.stdout, clock }` while surface's manifest ALSO declares per-target `capabilities: .{ fs.read: .{ roots: .{ "./data" } } }` — two declaration sites for the same fact, and nothing says whether the manifest set is a union, an upper bound, or both. Nobody enforces the path roots: `World` is constructed by the runtime, and reading the manifest at runtime would itself require fs authority, so 'a Dir rooted at ./data' is currently decoration. Worst: safety makes `ffi` a capability that taints its subtree 'unguaranteed', while parallel states 'on macOS raw syscalls are unsupported, so libSystem is a mandatory link dependency' — therefore every program that prints a checksum transitively depends on an `ffi` module and every program is `unguaranteed`, which makes the audit ledger's guarantee level vacuous on hello-world and collapses the most differentiated G2 claim.**
   - Where: surface-language, safety-security, compiler-architecture
   - Fix: Manifest declares the POLICY (an upper bound per target and per dependency); module `needs` declares the REQUIREMENT; build fails if requirement is not a subset of policy. Bake the root policy set, including path roots, into a read-only section at link time so `World`'s constructor can consult it without authority, and print it from `fors audit`. Define a distinguished trusted-FFI root: the toolchain's own libSystem/POSIX shims, pinned by content hash in a toolchain allowlist, do not taint; taint applies only to non-toolchain `ffi`. Without this the flagship claim fails on the first program. Also note that the 'capability re-check at link from signed BMIs' must be a Fors driver step run before invoking ld64 — ld64 knows nothing about BMIs or signatures — which no design currently says.
14. **The schedule of record plans the wrong mid-level IR. roadmap M5's deliverable is a 'sea-of-nodes mid-IR consuming the frontend's structural alias/ownership facts'. compiler's decision #1 explicitly REJECTS sea-of-nodes because it 'dissolves loop structure and program order — exactly the things HPC transforms (tiling, unroll-and-jam, SPMD widening) and Tapir's serial-elision rule need', and is hostile to debug info; it chooses CFG-SSA plus an acyclic e-graph. Since roadmap owns milestone sequencing and effort, this is not cosmetic: the largest, riskiest milestone in the program is currently budgeted and gated against an IR the compiler architect has ruled out. roadmap's crate list is likewise inconsistent with compiler's workspace (`fors-ir`/`fors-backend-opt` vs `fors-fir`/`fors-mir`/`fors-oir`/`fors-lir`), including hyphen-vs-underscore naming that differs across all three designs.**
   - Where: roadmap-execution, compiler-architecture
   - Fix: Resolve in compiler's favour (CFG-SSA + acyclic e-graph) and rewrite M5's deliverable and pass list to match compiler's C6. Adopt compiler's workspace and hyphenated crate naming as canonical, and re-home every Marc contribution point that names a crate path into it — three designs currently assume three different layouts.
15. **The structural-aliasing thesis — the named mechanism by which Fors closes the codegen gap to clang without LLVM — has too few information sources to cover the code it is supposed to win on. compiler derives alias classes only from 'parameter conventions and affine ownership'. But the disjointness facts that matter in data-parallel code come from elsewhere: arena brand identity (two handles into different arenas can never alias), split-token provenance (the N views minted by `Span.split` are disjoint by construction and are the sole basis of safe parallel mutation), SoA field identity (`b.pos` and `b.vel` are separate allocations), and allocator identity. None is a source in compiler's design, so `a[i]` vs `a[j]` inside an arena, and the two halves of a split, get conservatively merged into one class — losing vectorization in precisely the kernels G1 and G4 are staked on. Marc's `may_alias()` contribution point mentions only 'two distinct inout parameters are unconditionally disjoint'.**
   - Where: compiler-architecture, safety-security, parallel-heterogeneous
   - Fix: Define alias-class computation over five sources — parameter conventions, affine ownership, arena brands, split-token provenance, and SoA field identity — with the split-token lattice explicit in `may_alias`. Extend Marc's `may_alias()` line to cover the split rule, since that is where the vectorization actually comes from. Track the alias-precision CI metric per source so a regression tells you WHICH source a pass degraded.
16. **Scalable vectors are simultaneously in and out of v1. compiler states flatly: 'Scalable vectors (SVE/RVV) in v1 are handled by choosing a width at compile time plus predicated tails, not by sizeless types — honest cost: no width-agnostic binaries until vec<T,?> lands post-v1', and its interface section says 'No sizeless/scalable vector types in v1'. parallel makes sizeless `vec<T>` a v1 decision with a `@sizeless` marker requirement on the type system. surface includes `SVec[T]` in v1, legal only inside `simd` blocks. Three different v1 scopes for a type that appears in every SIMD signature. There is also no mask type in surface's type list at all, though parallel requires `mask<N>` as a distinct type and safety requires `@ct_select`, so `select`, masked tails and constant-time selection are currently unspellable.**
   - Where: compiler-architecture, parallel-heterogeneous, surface-language
   - Fix: Adopt surface's scoping rule — `SVec[T]` legal only inside `simd`/`spmd` regions, never in aggregate fields, never on the heap, never in generic containers — which is exactly what removes compiler's stated objection, since a sizeless type that never appears in a layout costs nothing in the ABI or in binary width-agnosticism. Overrule compiler's 'not in v1'. Add `Mask[N]` and `@ct_select` to surface's type list and keyword table. Fix the three spellings and two argument orders (`vec<T,N>` / `vector<T,N>` / `Vec[N,T]`) and the three region names (`vector_for` / `spmd(W)` / `simd for`) now, before any of them appears in a test or a spec clause.
17. **The gate on the program's riskiest milestone is set at two different values, and the roadmap's crisis trigger equals the compiler's success condition. compiler's C6 exit criterion is 'geomean within 1.6x of best-of(clang -O3, gcc -O3, rustc -O)', consistent with its published forecast (~1.6x at m15, ~1.2x at m24, 1.05-1.10x at m36-48). roadmap's M5 exit criterion is 'within 30% geomean' — i.e. 1.3x — and roadmap's own risk gate says '>1.6x off clang geomean after 12 months of M5 forces re-sequencing'. So at exactly 1.6x the compiler architect declares the milestone complete and the roadmap declares a scope crisis.**
   - Where: roadmap-execution, compiler-architecture
   - Fix: Adopt compiler's forecast table as the plan of record and set roadmap's gates to it: 1.6x at the release-backend-v0 exit, 1.3x as the following milestone's gate, 1.05-1.10x as the long-term goal. Set the pivot trigger strictly above the exit criterion (e.g. >2.0x at 12 months) so a success can never read as a failure. Publish the forecast table before anyone benchmarks Fors, exactly as compiler recommends.
18. **`Own[T]` can be freed with the wrong allocator in the SAFE subset. safety parameterizes heap types by an allocator value (`Buffer<T>`/`Box<T>` with `inout A: Allocator`). surface defines `Own[T]` as 'affine, one pointer, allocator passed to `deinit`' — so nothing in the type ties the pointer to the allocator that produced it, and surface's own example returns `Own[Slice[u8]]` from a function that received `let a: Allocator`, leaving the caller to remember which allocator. With no lifetimes and no stored allocator, passing the wrong allocator to `deinit` is a safe-subset memory-corruption path, in a language whose first claim is zero UB in the safe subset.**
   - Where: surface-language, safety-security
   - Fix: Brand allocators exactly like arenas: `Own[T, A]` where A is the allocator's brand type, minted at the allocator's binding site. Zero runtime cost, zero extra words, consistent with the arena design, and it supplies a sixth structural disjointness source for the alias classes. Reject the alternative of storing the allocator pointer (two words in every owning value) and reject the status quo.
19. **Contracts are dropped at `--release`, which is the exact dev/release semantic divergence that the same design calls fatal. safety states that `--release` 'keeps public-boundary preconditions and drops obligations that were discharged', and elsewhere states that 'every piece of UB is a place where dev and release tiers are permitted to disagree, which for a safety-marketed language is fatal' and rejects release-mode wrapping as 'exactly the Zig failure mode'. A contract that traps in dev and silently passes in release is that divergence. Separately, surface makes invariants 'checked on entry/exit of every pub method taking inout self' with no cost bound, and permits quantified `forall i in a ..< b` in invariants — so an O(n) invariant turns every O(log n) container method into O(n), silently.**
   - Where: safety-security, surface-language
   - Fix: Contract checks are never dropped by optimization level. They are removed only by proof (identically in both tiers) or by an explicit per-module `contracts: .runtime | .proved | .off` policy that applies to both tiers identically and is recorded in the build provenance and the audit ledger. Quantified invariants are `ghost`-only — checked by the interpreter tier and the prover, never at runtime — unless explicitly marked `@runtime_checked`; only O(1) invariants are runtime-checked by default.
20. **The C++ interop shim requires the unwinder machinery that the compiler says it will never emit. safety specifies a generated `@catches_cxx` shim that catches C++ exceptions at the FFI boundary and converts them to tags, 'the only place we link the platform unwinder'. Catching requires a landing pad and a personality routine in that function, which on Mach-O means compact-unwind/`__unwind_info` for it. compiler states 'No exceptions, no unwinder, no landing pads, ever', emits 'no CFI at all', and specifies the opposite behaviour: 'C++ exceptions crossing an FFI boundary abort, documented'.**
   - Where: safety-security, compiler-architecture
   - Fix: The shim is a hand-written C++ translation unit compiled by the system clang and shipped as a prebuilt object in the stdlib, never Fors codegen — then 'Fors emits no EH tables' stays literally true, `--no-cxx-interop` drops the object, and Fors frames are still never unwound through (diagnosed, not attempted). Pick this or pick abort-on-crossing, and delete the other from the spec.

### Resequencing

- Move semantics before the dev backend. roadmap orders M2 (dev backend, Mach-O, incremental link) BEFORE M3 (memory model, zero-UB semantics, error ABI, contracts), while compiler orders C3 (FMIR, ownership/isolation/contracts, reference interpreter, differential harness) BEFORE C4 (dev backend), and safety states plainly that M-S1/2/3 come first because 'everything else depends on them'. roadmap's own M2 exit criterion ('1M generated programs agree between interpreter and dev backend') presupposes the interpreter and the semantics it is built on. You cannot write trap lowering, the failure ABI or alias classes against unfrozen semantics. Swap M2 and M3.
- Pull parallel's M1 — the language-independent CPU runtime (Chase-Lev deque, fiber switch, PAC decision, two-class worker pool, parking layer) — into year 1, immediately after M0, instead of roadmap's M6 in year 3-4. It has ZERO dependency on the compiler (it is driven through a C ABI by the harness), and its top risk, `pacibsp` signing with SP versus resuming a continuation on a different fiber stack, can invalidate continuation stealing and therefore the space bound, serial elision and the whole determinism story. Discovering that in month 4 costs weeks; discovering it in year 3 costs the design.
- Land the secret/ct machinery with the register allocator, not at the end. The IR fields (secret bit, ct-region id) belong with FMIR, before the dev backend; the tainted spill class, the non-reordering region rule and the post-regalloc CT verifier belong with the SSA chordal allocator in compiler C6 / roadmap M5. roadmap currently schedules 'secret types hardening' in M12 (year 6-7) and compiler never schedules it at all, which means retrofitting a spill class and region constraints after PGO, Ext-TSP layout, cold outlining and if-conversion already exist. Only the crypto kernels and dudect validation should stay late.
- Freeze the optimization-visible semantics BEFORE the optimizing backend, not after it. roadmap's semantics freeze is M7, which is the second optimizing-backend milestone; the FP rules, trap set, failure ABI, provenance model and reduction constant are exactly what every pass in M5 is written against. Move the optimization-visible freeze to the M3/M4 boundary and keep M7 for the surface-completeness freeze that gates self-hosting.
- Re-baseline roadmap M1+M2 to the compiler architect's own estimates. roadmap allots 3.5 months for M1 (lexer, parser, query DAG, inference, module interfaces, comptime VM, reference interpreter, spec skeleton) and 4 months for M2; compiler's equivalent C0-C4 is 3wk + 2.5mo + 3mo + 2.5mo + 3.5mo ≈ 12.5 months nominal. The public v0.1 date (Dec 2027) is built on the optimistic figure. Restate it now, at the optimistic-to-realistic delta of roughly five months, rather than letting the 1.6x contingency absorb it silently.
- Move roadmap M3's 'safety-check cost <=6% geomean on Tier-A with bounds checks eliminated structurally' to M5/M7. At M3 there is only the dev backend (-O0-plus) and no check-elision pass, so the criterion is unmeasurable and the geomean-vs-clang-O3 comparison is meaningless. Replace it with 'checks-on vs checks-off delta measured and reported under the dev backend, no numeric gate'.
- Move registry-side capability enforcement out of safety's M-S5. Its exit criterion requires the registry to re-run the module-graph check in its own hermetic builder — a hosted build service — at roughly year 2, while roadmap schedules the public registry at M12 (year 6-7). M-S5 ships local enforcement only (lockfile capability assertions, `fors grant`, transparency-log client), and the v0.1 claim must be worded 'a dependency's capability gain is a hard local build error', not 'the registry rejects it'.
- Unbundle safety's M-S8 security conformance suite and attach each family to the milestone that can actually run it: S5 (UB differential) with the reference interpreter, before the dev backend; S1 (Juliet) with the semantics milestone; S2 (adversarial packages) with the capability/build milestone; S3 (race corpus) with the capability-checker milestone; S4 (constant-time) with the CT verifier at the register-allocator milestone. A single six-week late milestone means the security claims are unmeasured for years while the code that must satisfy them is being written.
- Cut M0's kernel count, not its schema. Three designs each add to the same three-week harness (roadmap: 8 kernels x 8 languages; parallel: 10 kernels x 9 baselines plus determinism gate, capacity table and roofline; safety: a whole security family with Juliet ports). Ship 5 kernels x 8 languages with the COMPLETE frozen schema and parallel's determinism gate with teeth (it must demonstrably fail for C+OpenMP and Rust+Rayon float reductions before Fors can pass it). Kernels are additive later; the schema is not.
- Move surface's Bench Subset freeze into days 1-5 of M0, ahead of kernel authoring on days 6-12, so the baseline kernels are written in shapes whose Fors translation stays inside the subset.
- Keep self-hosting where all three designs already agree — after the surface freeze — but make the gate explicit and single: compiler's C8 ('semantics freeze document signed off before any self-hosting work starts'), surface's M6 ('the gate that unlocks self-hosting') and roadmap's M7->M12 are the same gate under three names and two dates. One named artifact, one date, one owner.

### Missing

- Distributed failure semantics. A locale is a process and a trap aborts it, but the error ABI has no representation for 'peer died' and parallel's 8-byte frame header carries epochs with no liveness or death detection. `on loc { ... }` currently hangs on the first remote trap.
- An owner for actor supervision. safety points to 'actor/process supervision' as the mitigation for uncatchable traps; both safety and parallel classify actors as libraries; no design specifies the supervision mechanism, the restart unit, or what state a restarted unit inherits.
- The device memory model. With no heap allocation on device, `Box`/`Buffer`/arenas/allocators are unavailable inside kernels, so the only model is value semantics plus scoped projections into device buffers — nobody wrote this down. The kernel-legal type predicate (Copyable, no `deinit`, no allocator parameter, no scoped field) is also unspecified, so a value with a destructor can currently be moved into a kernel with no way to run it.
- The `unsafe` surface syntax. safety specifies `@unsafe(invariant: "...")` as a declaration attribute plus a `uses unsafe` manifest key; surface's module header grammar has only `module`/`needs`/`use`, its keyword table has no `unsafe`, and its declaration-form list omits the attribute. The unsafe subset — which allocators, FFI, `split`, `pair_mut` and atomics all require — is currently unspellable.
- `recover` has no grammar. It is the only route from `mut` to `iso` in safety's design and appears nowhere in surface's syntax, keyword table or declaration forms.
- A scoped-return rule. Without one, no function may return a slice, span, iterator or subview, so `split_at`, `chunk_mut`, range subscripts, `iter`, `chunks` and every container view in the stdlib are unwritable — and `Str = imm Slice[u8]` cannot be a struct field.
- `Mask[N]` and `@ct_select` in the surface type list. Required by parallel's masked tails and `zip_simd`, by safety's constant-time select, and by the merged-per-block masked trap rule; present in none of surface's type inventory.
- The exclusivity rule for varying indices, used identically by `simd for`, `parallel for` and `kernel` regions. Every benchmark kernel in the plan needs it and no design states it.
- FMIR-level typing of `kernel` capture lists, carried as an operand into OIR. compiler outlines kernels at OIR, by which point the convention and qualifier facts that make device memory safety work no longer exist.
- Alias-class sources beyond conventions and affine ownership: arena brands, split-token provenance, SoA field identity, allocator brands. The structural-aliasing thesis is the stated mechanism for closing the LLVM gap and it currently has no information about the data-parallel code it is meant to win on.
- A spill class for secret values in the register allocator, and a home crate plus pass slot for the post-regalloc CT verifier. safety requires both from 'both backends'; compiler's allocator and pass list have neither.
- How statically discharged proof facts reach the code-removal pass: an `assume`-fact representation plus proof-cache key from VCIR into OIR. Without it there are two check-elimination engines with contradictory soundness rules.
- The comptime budget as a hashed query input, and root-vs-dependency precedence. Budgets live in the manifest (safety, surface) while comptime results are memoised on (decl, args, declared inputs) (compiler), so a budget change does not invalidate the cache; and safety's own risk — a dependency declaring a huge budget tanks your build — has no rule. Effective budget should be min(root policy, declaring module's request).
- Enforcement of manifest-declared capability path roots. Nothing constructs the root `Dir` from the declared roots, and reading the manifest at runtime would itself need fs authority, so `fs.read: .{ roots: ... }` is currently unenforced. Needs a linker-baked read-only policy section consulted by `World`.
- A trusted-FFI allowlist for the toolchain's own libSystem/POSIX shims. Without it, `ffi` taint reaches every program that performs I/O and the guarantee-level ledger is vacuous on hello-world.
- Two distinct freezes with two scopes and two dates: a surface/static-semantics freeze (syntax, typing, conventions) and an optimization-visible-semantics freeze (FP rules, trap set, failure ABI, provenance, determinism constant B). Currently 'the freeze' is one event that surface dates ~2 years earlier than roadmap, and roadmap dates it AFTER the optimizing backend it constrains.
- An invariant-cost rule. Quantified invariants checked on every `pub inout self` method silently make container operations O(n); no design bounds this.
- Ownership of the benchmark JSON schema and of the fairness/statistics functions. Three designs add fields and two designs each define the efficiency and aggregation formulas; the schema is frozen on day 19 and nobody owns it.
- A statement that the dev-tier image is not reproducible and that the reproducibility claim covers the release path only.
- Stdlib ergonomics for explicit allocator threading in `fmt`, `map`, `list` and `json`. 'No hidden allocation, allocators are values' is stated four times and demonstrated once (`str.concat(a, x, y)`); the APIs where it actually hurts are unaddressed.

### Improvements

- Unify vocabulary in one pass before any spec clause or test is written. Current collisions: `throws`/`raises`; `@relax`/`@fastmath`; `Program`/`World` as the authority root; `Span<T>`/`MutSpan<T>` vs `Slice[T]`/`SliceMut[T]`; `Box<T>`/`Buffer<T>` vs `Own[T]`; `@comptime_input(path)` vs `@embed("path")`; `vector_for`/`spmd(W)`/`simd for`; `vec<T,N>`/`vector<T,N>`/`Vec[N,T]`; `grain N` keyword vs `@grain(n)` attribute; `pir` vs FMIR; `fors-caps` vs `fors_pkg` vs `fors_sema` (hyphen/underscore). Each is trivial alone; together they mean four designs cannot cite each other.
- Freeze the benchmark JSON schema against ALL FIVE designs' fields on day 19, not against roadmap's alone. Missing from roadmap's M0 metric list but required later: parallel's per-core-class capacity weights and speedup/capacity efficiency, the determinism gate fields (thread counts, locale counts, bit-exact checksum equality), GPU and locale sweep axes, roofline calibration; safety's `pass_rate` and `false_positive_rate` for the security family plus C/C++/Rust baseline columns; surface's `fastmath` on/off column (strict-IEEE-by-default is a deliberate cost that must be visible); compiler's `--no-daemon` cold row as a distinct, labelled row. Every one of these is a schema migration if omitted, and the schema outlives the compiler.
- Surface's Bench Subset freeze (its M1) must land in days 1-5 of M0, not alongside it. roadmap writes the C/Rust/Zig/etc. kernels on days 6-12; if the subset is not frozen first, the baseline kernels get written in shapes whose Fors translation needs out-of-subset features, and the 'Fors joins kernel-by-kernel with zero harness changes' property is lost.
- Design the backtrace walk across a fiber boundary at the same time as the fiber switch, not later. compiler's entire unwind story is 'always maintain x29, walk the FP chain, emit no CFI'; parallel resumes stolen continuations on pooled fiber stacks, which terminates or corrupts that walk. Fix: the fiber base frame stores a sentinel FP plus a saved logical-parent record, and the walker recognises the sentinel. Cheap now, invasive after profiler and panic-printer exist.
- State a permitted-external-tool allowlist with pinned hashes, and stop claiming the build path is tool-free. roadmap's interface says 'no external tool may enter the default build path' while compiler uses ld64 for all release links, parallel shells out to `xcrun metal` for AOT metallib, and safety uses an external SMT solver. `xcrun` in particular consults developer-dir state and can fetch components. Restate as: no external tool on the incremental dev path; the release path may invoke a pinned, hash-recorded system linker and vendor GPU compiler, both recorded in build provenance and covered by `--check-repro`.
- Scope the reproducibility claim to the release path. The dev tier's image is produced by `clonefile` of the previous image plus dirty-page patches, so it is a function of edit history, not of source. roadmap's nightly 'build twice, compare hashes' gate would fail on the dev path by construction.
- Fix the manifest version syntax: surface's example uses `version: "^0.4"` while safety specifies minimal version selection. MVS takes exact minimums and has no upper bound; a caret implies one. Manifest versions are exact minimums with no operators.
- Collapse the two package-policy mechanisms. surface has `policy.deny: .{ exec, net, ffi, dyn.load }`; safety has per-dependency asserted capability sets plus `fors grant`. Keep the per-dependency assertion plus a target-level upper bound, and derive the deny list rather than authoring it, so there is one place a reviewer looks.
- Name the unsafe-checking artifact precisely and drop the sanitizer language. compiler says 'sanitizers are unnecessary in the safe subset; ship `--interp` and a trap-based debug allocator'; roadmap M8 gates on 'address/thread/UB sanitizer equivalents' catching '100% of a seeded unsafe-code fault suite'. Restate M8's criterion as the interpreter catching the seeded suite, and state the residual gap honestly: FFI-heavy and performance-scale unsafe code has no dynamic checker at all.
- Define what `fors run kernel.fors` grants. compiler promises zero-config single-file runs for the harness; surface requires a module header plus a manifest for capability policy. Without a rule, benchmark builds are silently more privileged than real builds. Fix: bare-file runs synthesise a manifest granting exactly the file's `needs` set, emit a warning, and the harness's Fors adapter passes the flag explicitly so the privilege difference is in the recorded provenance.
- Redefine the binary-size metric. compiler commits to 'static-by-default linking for the binary-size metric', but libSystem cannot be statically linked on macOS, so Fors binaries are dynamic on the first target while C baselines can be `-static` on Linux. Define it as stripped size excluding the platform libc, on one OS, with link mode recorded.
- Split the determinism gate by CI tier. It is a correctness gate, so parallel wants it pre-merge; roadmap caps pre-merge at 5 minutes on one machine. Run T in {1,2,8} on a fast subset pre-merge, the full thread x locale cross product nightly.
- Resolve atomics explicitly rather than by omission. parallel's runtime needs atomics for the Chase-Lev deque, MPSC remote-free stacks, the sync flag word and the device FaultRecord; safety gates them behind a capability that does not exist in its own lattice; surface routes them through a library `Shared[T]`. Make `Shared[T]` the single answer, define its sendability as a third explicit form, and state that `imm` means 'no safe mutation reachable' with `Shared[T]` as the one audited exception recorded in the ledger.
- Give the witness table the bits that transitive properties need. safety's `@no_alloc` is checked transitively, and surface's comptime callees must be `pure` — neither is provable through a shape-based indirect call. Either the witness record carries `no_alloc` and `pure` bits, or those attributes require `@specialize`. Pick one and put it in the witness layout that compiler and surface both reference.
- Forbid trapping integer arithmetic inside `@tensor`. Exported StableHLO/CoreML/ONNX graphs have no trapping integer semantics, so `@tensor` code's behaviour diverges from its native CPU/GPU lowering — and parallel's differential oracle is defined 'within a declared tolerance', which is not a meaningful notion for overflow. Restrict `@tensor` to floats plus explicitly wrapping/saturating integer ops.
- Document device contract violations as the one recoverable trap. parallel's device subset permits contracts but reports faults through a per-launch FaultRecord that the host converts to an ordinary Fors error, while every other trap is an uncatchable abort. This is a defensible, deliberate exception and should be written as one rather than discovered as an inconsistency.
- Specify authority across locales. `spawn on Locales[i]` runs code in another process; nothing says whether the remote locale's authority is its own or the initiator's, and a `Dir` or `Socket` handle must not serialise. Fix: every locale runs the same signed binary with the same baked-in policy section, authority is per-locale and identical, and capability values are non-serialisable by type.
- State that branded handles and owning heap values do not cross locales as-is. A brand is a nominal type minted at a lexical site, so the receiver's brand is a different type; and a moved `Own[T]` must be reallocated with the receiver's allocator, which means the derived deserialiser's signature needs an allocator parameter — `(inout Alloc, wire) -> T`. Neither appears in the structural-serialisation design.
- Make `addr()` unsafe-only and give `imm` no observable identity. safety's provenance model separates `ptr` from `addr()`; if address identity is observable in the safe subset, then `imm` values copied across locales, and comptime results, become address-dependent, which breaks both D1 determinism across locales and bit-identical rebuilds.
- Deduplicate and re-home Marc's contribution points; several are the same decision in different crates with different stated trade-offs. Comptime `charge()` appears in compiler (`fors-interp`) and safety (`fors_comptime`); the reduction constant appears three times (parallel, roadmap, surface); steal-victim selection appears twice (parallel, roadmap); the failure ABI appears twice (safety `fors_abi/failure.rs`, roadmap `fors-sema/failure.rs` — the latter re-opens unwinding). Also merge parallel's `capacity.py::efficiency` with roadmap's `aggregate.py::summarize` into one statistics-and-fairness file, since together they define every number Fors ever publishes.
- Create the normative single-owner files this review keeps needing, and add a CI check that other documents only cite them: spec/ch-qualifiers (the sharing lattice and taint axis), spec/ch-failure-abi (the register convention and trap mechanism), spec/ch-determinism (the reduction constant B and the fastmath scoping rule), spec/ch-capabilities (declaration sites, policy-vs-requirement, trusted-FFI allowlist), spec/ch-ir-levels (level table including tile ops, secret bits, alias-class sources), and bench/SCHEMA.md (the frozen metric schema). Every blocking issue above is one of these six facts having two owners with different values.

## Lens: feasibility

**Verdict.** The five designs are individually strong — genuinely better than the research pass that fed them, especially the harness-as-measurement-contract idea, the single-FMIR-interpreter-serves-three-roles decision, alias classes as mandatory operands, the clonefile plus dirty-page re-sign route, and capability-confined declarative builds. But as a program they do not currently close, and the gap is not small: the subsystem owners' own numbers sum to roughly 70 months of uncontingented work, which under the roadmap's own 1.6x contingency is 9-9.5 years to 1.0, not 6.5 +/- 1. The roadmap is 25-40% below its own owners on every shared milestone, so its contingency is not contingency. Second, and more urgent than the schedule: four of the five designs specify mutually incompatible core semantics. Three qualifiers versus four; branded arenas versus unbranded handles; deterministic-by-default versus opt-in versus mandatory-explicit reductions, with two incompatible tree-shape rules; three spellings and two register conventions for the failure ABI. Each of those is a rework bomb wired into the IR, the stdlib and both backends, and the roadmap compounds it by scheduling the dev backend BEFORE the memory model — you cannot build FMIR and hold two backends to identical behaviour before the semantics FMIR exists to carry are written. Fix the ordering (a 6-8 week semantics-on-paper milestone after M0) and fix the five contradictions as numbered RFCs before anyone writes a lexer; that is the highest-value two months in the whole plan. On the thing actually asked for — the harness — M0 is the right instinct and is not yet buildable as specified. It is two different harnesses totalling ~154 expert-quality kernel implementations in 21 days; it has one checksum field serving two mutually exclusive gates; its exit criterion (<=2% CoV) is stricter than the parallelism owner's own (<5% on 8 of 10) and is not achievable on a thermally throttled M1 Pro with no thread pinning, so the first gate the project breaches is its measurement-discipline gate; it cannot measure the flagship incremental-rebuild claim, because no cross-language edit-and-rebuild protocol exists; and compiler-architecture's own 50ms budget is a p50 budget labelled p95 — with module-granular cross-unit dependencies, a one-token change to a public signature in a core module retypechecks every dependent, and that is the real p95. Also: Tier A and Tier B are never enumerated anywhere, yet six numeric exit criteria depend on them, which makes every codegen gate retro-negotiable. Fix all of that inside M0, split it into M0 plus M0.P, and it becomes the permanent asset the plan claims it is. Nothing owner-mandated needs dropping, but almost everything needs a thinner v1: GPU with hand-written schedule artifacts instead of an automatic tiler; CoreML-only NPU export; distributed gated on checksum identity, not on scaling efficiency; no scalable vectors; curated .forsi artifacts instead of a C parser; SMT tier and hosted registry after 1.0. Three specific defects nobody caught: serial elision cannot be a bit-exact oracle under blocked-tree reductions, which invalidates two stated exit criteria unless reductions are lowered before parallel lowering; FP-chain-only backtraces plus continuation stealing on pooled fibers means parallel programs have broken backtraces; and fuzzing and benchmarking are both scheduled nightly on the one machine whose numbers every public claim rests on. On the AI-agent model: the three lanes and the two-session rule are right, but 'unbounded agent throughput' is the load-bearing falsehood under every estimate — review cost on a register allocator approaches writing cost, because you review it by reading its failures. Apply per-lane leverage factors and the schedule becomes credible. Net: feasible, in the sense that G3 and G2 are winnable and shippable by roughly Dec 2027 as a real public v0.1; not feasible on the stated 6.5-year, six-goals-at-once framing. Say 2035-2036 for 1.0 now, in writing, and the project keeps the one asset it cannot rebuild — the credibility of its own numbers.

### Blocking issues

1. **The schedule arithmetic does not close. Taking each subsystem owner's own milestone estimates: compiler-architecture C0-C8 = ~33 months; safety-security M-S1..M-S8 = 71 weeks (~16.5 months, and the owner says so explicitly: '60-80 developer-weeks'); parallel-heterogeneous M0.P..M7 = 93 weeks (~21.5 months); surface-language M1..M6 = ~42 weeks. Netting out the genuine overlaps (compiler C7 covers parallel M2-M4; compiler C3/C5 partly covers safety M-S1/M-S3) still leaves roughly 70 months of uncontingented content. Apply the roadmap's OWN 1.6x contingency and 1.0 lands at ~112 months, i.e. 9-9.5 years, not '6.5 years +/- 12 months'. The roadmap is systematically 25-40% below its own subsystem owners for identical work: roadmap M6 (5-6mo) vs parallel M2+M3+M4 (30 weeks); roadmap M3+M4 (7mo) vs safety M-S1..M-S5 (41 weeks); roadmap M9 (8-9mo) vs parallel M5 (18-20 weeks) PLUS SPIR-V PLUS PTX; roadmap M12 (10mo) vs safety M-S6+M-S7 (24 weeks) plus registry plus self-hosting. The 1.6x contingency is applied to numbers that were already lower than the owners' estimates, so it is not contingency at all.**
   - Where: roadmap-execution milestones vs compiler-architecture, safety-security, parallel-heterogeneous, surface-language milestones
   - Fix: Re-baseline the roadmap bottom-up from the subsystem estimates rather than top-down. Replace the 'agent-supervised week = 25h of Marc + unbounded agent throughput' unit with explicit per-lane leverage factors applied per milestone: ~3-5x on mechanical volume (ISA/ABI tables, ISLE rule sets, Mach-O/DWARF struct defs, M0 kernel ports, Juliet ports, .forsi artifacts, conformance-test bulk), ~1.2-1.5x on frontend/backend implementation where bug-rate dominates review, ~1.0x on semantics, spec, prover, and miscompile root-cause. Publish 1.0 as 2035-2036 with a named descope ladder (see resequencing), and state the weekly-hours assumption explicitly.
2. **The surface-language design and the safety-security design specify two DIFFERENT type systems, and the compiler and parallelism designs each assume a third. (a) Reference capabilities: compiler-architecture and parallel-heterogeneous both require FOUR first-class capabilities (isolated / exclusive-mutable / shared-immutable / read-only); safety-security specifies four (iso/mut/imm/ro) plus viewpoint adaptation plus a `recover` promotion rule; surface-language explicitly collapses to THREE (iso/imm/secret) and argues conventions subsume mut and ro. These are not naming differences: whether `ro` is a qualifier with viewpoint adaptation or is subsumed by the `let` convention changes the lattice, the sendability rule, and `recover`. (b) Arenas: safety-security requires comptime-generated nominal BRANDS with `Ref<Node, A>`; surface-language has unbranded `Handle[T]` and lists graph-shaped data as an unsolved hole. A brand is a second type parameter threaded through every arena-touching stdlib signature. (c) `secret`: surface makes it a third reference capability; safety makes it an orthogonal taint lattice — they compose differently (is `iso secret T` expressible?). (d) Interior mutability: safety permits `atomic<T>` inside `shared`-capability types, but `shared` is not one of its own four capabilities; surface instead has a library `Shared[T]` and no fourth qualifier. (e) Error keyword and failure ABI: surface says `raises E` with the error in x1; safety says `throws E` with {payload, tag} and tag 0 = success; compiler says 'errors are values returned in the normal register set via Fors's own internal calling convention' and does not say which register carries what.**
   - Where: surface-language vs safety-security, with compiler-architecture and parallel-heterogeneous interface sections depending on both
   - Fix: Stop everything and resolve these as five numbered RFCs before any IR op set, stdlib signature, or FMIR verifier rule is written. My recommendations: adopt surface-language's three qualifiers (safety-security's own top risk is that two orthogonal qualifier systems are too much surface for one person to keep sound), reduce safety's viewpoint-adaptation table to the 3x3 case, and rewrite the compiler and parallelism interface clauses to name three; adopt safety's branded arenas (the brand is what makes index confusion a type error, and unbranded handles leave the graph story with no safety argument at all); make `secret` orthogonal to capabilities per safety; adopt surface's `Shared[T]` library type and no fourth qualifier; pick one error keyword and pin the exact register assignment and success discriminator in fors-abi before any stdlib signature is authored.
3. **The parallel-determinism default is specified four different ways. parallel-heterogeneous: D1 run-reproducible is THE DEFAULT for the safe subset. safety-security: determinism is an OPT-IN `@deterministic` region and lists 'deterministic by default' under alternatives_rejected. surface-language: `reduce(+, order: tree)` is the default and is bit-reproducible. compiler-architecture: 'the compiler will not silently choose a reduction order' — i.e. no default, the programmer must spell `reduce.ordered` or `reduce.tree(width=W)`. Worse, the two designs that do specify a tree shape specify incompatible ones: parallel fixes it by leaf block size B = 4 * native_lanes (machine-dependent, so bit-identity across targets is structurally impossible and even parallel's own claim of identity 'across core class' is questionable if lane counts differ), while compiler fixes it by DECLARED width W independent of hardware (machine-independent, which is the only version that actually delivers reproducibility). This policy propagates into the M0 harness determinism gate, the spec, both backends, the reference interpreter, and the reduction lowering.**
   - Where: parallel-heterogeneous vs safety-security vs surface-language vs compiler-architecture
   - Fix: Decide now, in one spec clause. Recommendation: deterministic-by-default (parallel/surface win: it is the most differentiated G4 claim, the M0.P harness gate is already built assuming it, and an opt-OUT gets used while an opt-IN never does), but implemented by compiler-architecture's declared-width rule with a spec-fixed default width, NOT by parallel's native_lanes-derived B. Amend compiler-architecture's 'the compiler will not silently choose' to 'the compiler chooses by a spec-defined rule whose constant is published and results-visible'. Publish that constant in the reproducibility manifest before any number is published.
4. **Serial elision cannot be the bit-exact differential oracle the compiler design relies on. compiler-architecture makes `--serial-elide` the deterministic oracle and sets exit criteria 'interpreter's serial-elision run and the parallel run agree bit-for-bit on every parallel test' (C3-adjacent, parallel M2) and 'every optimizer pass validated under serial elision' (C7). But under D1, a reduction is a fixed-shape BLOCKED fold, which is not serial order — so eliding the parallelism produces a different (equally correct) float result. Every FP-reducing test in the corpus therefore fails a bit-for-bit comparison by construction, and two stated exit criteria are unachievable as written.**
   - Where: compiler-architecture (serial elision decision, C3/C7 exit criteria) vs parallel-heterogeneous (D1 reduction policy, M2/M4 exit criteria)
   - Fix: Make it an IR-ordering constraint: lower reductions to their blocked/fixed-tree form BEFORE parallel lowering, so serial elision removes the detach/reattach but preserves the fold shape. Then serial elision is bit-exact and both exit criteria stand. This must be a verifier-enforced invariant, not a convention, and it must be decided before the FMIR reduction ops are named.
5. **The M0 harness has one checksum field serving two mutually exclusive gates. roadmap-execution: FP kernels 'hash a quantized reduction (relative 1e-9)' so a legitimately different summation order still passes the correctness gate. parallel-heterogeneous M0.P: the determinism gate requires BIT-IDENTICAL checksums across thread counts and its exit criterion is that the gate 'demonstrably FAILS for C+OpenMP and Rust+Rayon float reductions'. With a 1e-9 tolerance the OpenMP reduction passes and the determinism gate has no teeth; with bit-identity every vectorized C baseline is scored as incorrect. The schema is frozen on D19, so this ships wrong and stays wrong.**
   - Where: roadmap-execution M0 (bench/kernels/checksum.py, fp_checksum) vs parallel-heterogeneous M0.P (determinism gate)
   - Fix: Two distinct fields in schema v1: `checksum_tolerant` (the correctness gate; quantized; a baseline failing it is a real failure) and `checksum_bitexact` (reported for every run and compared ACROSS runs of the same binary at different thread counts; a baseline failing it is recorded as non-deterministic, never as incorrect). Fix before the D19 freeze.
6. **The harness cannot measure the project's flagship metric, and the flagship budget is a p50 budget labelled p95. (a) 'single-token-edit incremental rebuild' has no cross-language definition: C/C++ is per-TU with make, Rust per-crate, Go per-package, Java a javac/gradle daemon, JS has no compile step. Comparing Fors's 50ms against 'the baselines' requires a per-language edit-and-rebuild protocol (which file, which token, which build tool, warm daemon or not) that exists in no design and is not in the 30-day plan. Without it the headline number has no denominator and is unfalsifiable — exactly the V-language failure the plan says it is defending against. (b) compiler-architecture's own 50ms budget table assumes an edit inside one 2k-line file touching ~40 declarations, but the same design states cross-unit dependencies are tracked at MODULE granularity. A one-token change to a public signature in a widely-imported core module therefore retypechecks every dependent module — that is the p95 edit, not the p50 edit, and it is nowhere in the budget. (c) The budget starts at 'client RPC', not at the keystroke, so file-watch latency and the LSP's concurrent work are excluded.**
   - Where: roadmap-execution M0 (D14 compile-speed corpus) and compiler-architecture (section 2 budget table, C4 exit criterion)
   - Fix: Define the incremental benchmark in M0 as a DISTRIBUTION over declared edit classes — comment/whitespace, function body, private signature, public signature in a leaf module, public signature in a core module — with a published number per class and the p95 taken over the declared mix, not over an author-chosen edit. Write the per-language rebuild protocol as an M0 deliverable and get it reviewed by someone who uses each build system. Measure from the write() of the edited file, not from the RPC. State the daemon and no-daemon numbers as separate rows.
7. **'Tier A' and 'Tier B' kernel sets are never enumerated anywhere in the five designs, yet at least six numeric exit criteria depend on them: compiler C6 (within 1.6x on Tier-A), C7 (within 1.2x), roadmap M5 (within 30% on Tier-A, no kernel worse than 2x), M7 (within 10% Tier-A / 15% Tier-B applications), safety M-S3 (safety-check cost <=6% geomean on Tier-A), M-S6 (>=90% of bounds checks on 'the benchmark kernel corpus'). The geomean of an 8-kernel set is extremely sensitive to membership — sha256 and integer sort are reachable for a young backend, blocked matmul against clang -O3 -march=native is where a solo backend loses 2-3x. Leaving the set unnamed makes every codegen gate retroactively negotiable, which is precisely the failure the 'measurement contract' exists to prevent.**
   - Where: compiler-architecture C6/C7, roadmap-execution M5/M7, safety-security M-S3/M-S6
   - Fix: Enumerate and freeze Tier A and Tier B in M0, alongside the exact baseline compilers, versions, flags (including the portable-baseline column), the geomean formula, and the rule for adding a kernel later (additive only, with all historical geomeans recomputed and republished). Put the list in bench/CLAIMS.md and treat changing it as an RFC.
8. **The critical path starts in the wrong place. roadmap-execution sequences M2 (dev backend, Mach-O, incremental link) BEFORE M3 (memory model, zero-UB semantics, error ABI, contracts). compiler-architecture builds FMIR and the reference interpreter in C3 — an IR whose entire purpose is to carry ownership, conventions, isolation domains and contracts — before safety-security's M-S1/M-S2 (conventions, exclusivity path-trie, escape kinds, capability lattice, branded arenas: 15-18 weeks of design work) has produced those semantics. You cannot name FMIR's op set, write its verifier, or hold two backends to identical behaviour before the trap set, convention conflict matrix, provenance model and failure ABI exist. Building C3/C4 first guarantees an FMIR rewrite, and the rewrite invalidates the dev backend, the interpreter and the fuzzer simultaneously.**
   - Where: roadmap-execution milestone order (M2 before M3) vs safety-security M-S1/M-S2 and surface-language M1/M3 as prerequisites of compiler-architecture C3
   - Fix: Insert a 6-8 week 'semantics core on paper' milestone immediately after M0, containing safety-security M-S1 plus the surface-language inference/convention rules plus the five contradiction-resolving RFCs above. Nothing downstream starts until the convention conflict matrix, capability count, trap set, error keyword/ABI and determinism default are decided and written. Cost: ~2 months before the first token is lexed. Benefit: one FMIR instead of two.
9. **M0 as specified is two different harnesses totalling ~154 kernel implementations in 21 days, and nobody reconciled them. roadmap-execution M0: 8 kernels x 8 languages = 64 implementations, with Marc personally expert-reviewing the C and Rust versions, ported in 6 days (D7-D12). parallel-heterogeneous M0.P: a DIFFERENT set of 10 kernels x 9 language/runtime configs (including OpenCilk, Kokkos, Java Vector API, Node Workers+Atomics, numpy+multiprocessing) = ~90 implementations, PLUS the P/E capacity table, PLUS the bit-exact determinism gate, PLUS roofline calibration, also in 3 weeks. Expert-quality numeric baselines are the entire credibility basis of every G1 claim, and 'expert-reviewed by Marc' for ~30 numeric kernels is alone more than 6 days of one person's attention. This is the first thing that slips, and what slips is the project's only public artifact and its permanent measurement contract.**
   - Where: roadmap-execution M0 (D7-D12, exit criteria) vs parallel-heterogeneous M0.P
   - Fix: One harness, two families, two milestones. M0 (3 weeks): the serial/perf family — 6 kernels x 6 languages (drop Swift and Java from the first cut, they add JIT/warmup methodology cost for little signal), runner, metrics, both checksum fields, provenance, noise floor, report generator, fors adapter contract co-authored with the compiler owner. M0.P (3 weeks, immediately after): the parallel family, capacity table, determinism gate, roofline, and the OpenCilk/Kokkos/Vector-API baselines. Do not pretend both fit in 21 days; the exit criteria are what make them worth anything.
10. **Parallel programs will have broken backtraces, and no design owns the problem. compiler-architecture deletes the entire unwind pipeline: 'always maintain the x29 frame-pointer chain... backtraces walk FP, no CFI emitted at all'. parallel-heterogeneous resumes stolen continuations on POOLED FIBERS with separate stacks. An FP chain walked from a stolen continuation does not connect to its logical parent — it runs off the end of the fiber stack or into an unrelated frame. So panic backtraces, the trap side-table diagnostic path, and profiler sampling are all broken inside exactly the parallel regions the language is being built for, and neither design mentions it.**
   - Where: compiler-architecture (frame-pointer/no-CFI decision, C4 trap side tables) vs parallel-heterogeneous (fiber pool, fors_fiber_switch, M1)
   - Fix: Design a sentinel frame into the fiber ABI in parallel M1: fors_fiber_switch pushes a recognisable frame recording (parent fiber id, parent FP, spawn-site pc), and the trap/backtrace walker and the sampling profiler both know to hop at the sentinel. ~20-40 lines, but it must be in the fiber ABI and in the compiler's backtrace printer from the first fiber switch, not retrofitted. Add an exit criterion to parallel M1: a trap inside a stolen continuation prints a correct logical backtrace through its spawn ancestor.
11. **The GPU tiling pass is budgeted at 18 weeks for work the same design describes as multi-year. parallel-heterogeneous M5 (16-20 weeks) contains: the tile-level IR, the tiling / shared-memory staging / coalescing pass, the @device subset checker with uniform-barrier analysis, the FaultRecord device error path, an MSL text printer with metallib caching and an AOT path, a SPIR-V binary emitter, launch-as-spawn with isolation-domain transfer, unified-memory transfer elision — and its exit gate requires BOTH Metal and Vulkan/SPIR-V working plus SPIRV-Cross cross-validation. The design's own risk section says the tiling pass 'is most of Triton's value and took a team years'. An 18-week estimate against a self-declared multi-year item is the single clearest underestimate in the set, and it sits on the critical path to the v1 GPU mandate.**
   - Where: parallel-heterogeneous M5 and its top_risks; roadmap-execution M9
   - Fix: Thinnest viable v1 GPU: NO automatic tiling pass. The .fsched schedule-artifact mechanism already exists in this design — use it to supply tile shapes, threadgroup sizes and shared-memory staging BY HAND per kernel, and let the vendor compiler do the rest. Ship Metal/MSL only, 3 named kernels (BabelStream/saxpy, stencil, GEMM), correctness gated by checksum equality against the CPU lowering, and a performance claim of 'portable single-source, hand-tuned via checked-in schedules'. Move SPIR-V and PTX behind a correctness-only gate in a later portability milestone, and the automatic tiler to post-1.0. This honours the owner's 'GPU single-source kernels in v1' mandate while removing the multi-year item from the critical path.
12. **The macOS incremental-signing mechanism is the gate on the project's most winnable headline claim, and it is both underestimated and scheduled where it cannot be de-risked. roadmap-execution calls it '~2-3 weeks'; compiler-architecture buries it inside C4 (3.5 months) together with copy-and-patch codegen, the Mach-O writer, the incremental linker with chained fixups, DWARF 5 emission, frame-pointer backtraces and trap side tables. Three specific gaps: (1) LC_CODE_SIGNATURE must be last and __LINKEDIT contiguous and page-aligned, so growing an atom shifts __LINKEDIT, shifts the signature offset, changes the superblob and changes the CodeDirectory's own hash — the design's 'reserved slack' has no stated policy for slack exhaustion, so the p95 has an unmodelled long tail where a full relayout and full rehash occurs; (2) there is no diagnostic story for a malformed patched image, and the failure mode is SIGKILL with CODESIGNING and no message, which for the weeks this is being developed is a brutal debug loop; (3) the claim that rename() to a new inode avoids stale-signature caching is the right instinct but is asserted, not tested, against AMFI's per-cdhash trust caching.**
   - Where: compiler-architecture C4 and the codesign decision; roadmap-execution M2 and its ~2-3 week estimate
   - Fix: Extract a standalone 3-week spike, run in parallel with the frontend (months 4-6), against a hand-written toy Mach-O with no other moving parts: clonefile, patch, dirty-page rehash, CodeDirectory rewrite, rename, execute, in a loop, across every macOS point release available. Explicit go/no-go before the 50ms number appears in any public text. Specify the slack-exhaustion path and measure its cost separately (it is part of p95). Build a `fors doctor --verify-signature` that validates the CodeDirectory offline so a malformed image produces a diagnostic instead of a SIGKILL. If the spike fails, the fallback (patch-to-temp plus full re-sign) is ~15-25ms for small binaries and blows the budget at 20MB — you want that fact in month 2, not month 14.
13. **Differential fuzzing and benchmarking are scheduled on the same single machine, which invalidates both. roadmap-execution puts the nightly tier on 'self-hosted': 8 hours of structure-aware fuzzing plus the full 3-way differential AND the benchmark run on the pinned bench box, while simultaneously banning cloud benchmarking because 'cloud runners have 10-30% variance, which is larger than every interesting effect the project will ever claim'. A fuzz run on the bench box poisons the benchmark numbers that all public claims rest on. Separately, compiler C6's exit criterion of 10M generated programs through interpreter + dev + three release configs is not a laptop-nightly workload; it is cloud CPU-hours, and the only cloud budget in the plan is $3-6k/year for GPUs from M9.**
   - Where: roadmap-execution (CI nightly tier, benchmark-execution decision) and compiler-architecture C3/C6 exit criteria
   - Fix: Fuzzing and differential testing go to cloud CI — they are throughput-bound and noise-indifferent, and they are the one workload where cloud variance costs nothing. The pinned box runs benchmarks only, never concurrently with anything, with a preflight that aborts if any other Fors process is running. Add an explicit cloud compute line to the budget from M5 onward; at 10M programs x 5 configs it is likely the larger bill than the GPU instances.
14. **The first gate the project will breach is its own measurement-discipline gate. roadmap-execution M0 exit criterion: '10-run variance for wall time <=2% and for compile time <=3% on the pinned box'. parallel-heterogeneous M0.P exit criterion for the same machine: 'CoV < 5% on 8 of 10 kernels'. On an M1 Pro with thermal throttling, 6P+2E asymmetry and — as the parallel design itself correctly notes — no thread pinning available on macOS (only QoS hints), <=2% CoV on multithreaded kernels is not achievable. So on day 21 the roadmap's stated exit criterion is missed, and the options are to slip M0 or to quietly relax the gate. Relaxing a numeric gate at the first opportunity, in the milestone whose entire purpose is to make gates unnegotiable, destroys the discipline before any language exists.**
   - Where: roadmap-execution M0 exit criteria vs parallel-heterogeneous M0.P exit criteria
   - Fix: Do not set a target CoV as an exit criterion. The exit criterion is 'the noise floor is MEASURED per metric and per family, published, and reproducible on a second 10-run pass within its own stated bound'. Whatever the number is, it is the number; the regression gate is then noise-floor-relative. Also state the two owners' numbers as one number: one harness, one noise-floor document, one owner (roadmap), additions RFC-gated.

### Resequencing

- Insert M0.5 'Semantics core on paper' (6-8 weeks) immediately after M0, before any lexer or IR work: safety-security M-S1 plus the surface-language convention/inference rules, plus five RFCs resolving the capability count (3 vs 4), arena branding, secret placement, interior mutability/Shared, and the error keyword plus exact failure-ABI register assignment. Nothing downstream starts until these are signed. This prevents a second FMIR.
- Run the Mach-O patch-and-sign spike as a standalone 3-week task in months 4-6, in parallel with the frontend, against a toy Mach-O — not inside compiler C4. Explicit go/no-go before the 50ms claim is published anywhere.
- Split M0 into M0 (perf family, 6 kernels x 6 languages, 3 weeks) and M0.P (parallel family plus capacity table plus determinism gate plus roofline, 3 weeks immediately after). The current plan asks for ~154 expert-quality kernel implementations in 21 days.
- Land the IR-level random program generator and the differential runner with the FIRST dev-backend instruction, not at the end of compiler C3. A two-tier backend is only honest if the oracle predates the second tier, and the cheapest bug to fix is the one found the day it is written.
- Split compiler C6 into C6a (exit 2.0x geomean) and C6b (exit 1.6x), publish the Tier-A geomean weekly throughout, and move PGO from C7 into C6b — it is the best quality-per-hour item and it de-risks the gate rather than being the response to missing it.
- Move the automatic GPU tiling pass out of v1. Ship Metal/MSL single-source with tile shapes, threadgroup sizes and shared-memory staging supplied by hand-written .fsched schedule artifacts, correctness-gated by checksum equality with the CPU lowering. SPIR-V and PTX move behind a correctness-only gate in a later portability milestone. This keeps the owner-mandated v1 GPU capability and removes a self-declared multi-year item from the critical path.
- Move x86_64/ELF ahead of GPU, and unbundle compiler C8. Currently C8 packs x86_64 plus ELF plus SPIR-V/MSL/PTX plus DWARF-at-O2 plus scheduling plus software pipelining plus the self-hosting review into 6 months. x86 first buys the second pinned bench box, NUMA and many-core scaling data without which every G4 claim is unfalsifiable, and proof that the backend and ABI layer are not accidentally aarch64-shaped.
- Drop the automatic C header importer from v1. Ship only curated, content-addressed .forsi interface artifacts for libc/POSIX/Darwin/Metal, generated OFFLINE by a throwaway authoring tool (which may use clang — a data-generation tool whose checked-in, human-reviewable output is a build input is not a compiler dependency, exactly like the .fmach and .fsched artifacts the parallelism design already blesses). Removes 15-20k lines and an unbounded triage tax from the critical path; add the real C parser post-1.0 when there are users to prioritise which headers matter.
- Drop scalable vectors (vec<T> / SVec[T]) from v1. There is no SVE or RVV hardware on the dev machine, so the design cannot be validated, and sizelessness infects the type system (aggregate fields, heap, generic containers) permanently. Fixed-width vector<T,N> plus predicated tails plus a compile-time-chosen width meets the mandate; width-agnostic binaries are a post-1.0 feature.
- Move the SMT prover tier out of v1 into a 1.1 line. Keep contract syntax from day one (it is a breaking change to add later), keep runtime checking, keep the stage-1 abstract interpreter (it is load-bearing for performance, not just verification). The external-solver tier has no dependents and the largest unbounded cost of anything in the plan.
- Move the public registry and transparency log out of v1; keep the lockfile capability pinning, the capability-change-is-a-build-error rule, `fors grant`, audits.toml, hermetic builds and --check-repro. The differentiated claim is the capability-confined build, which is language-and-toolchain work; a hosted registry with an append-only log is infrastructure operations and can follow adoption.
- Reduce NPU v1 to CoreML MIL export only, with the native CPU lowering as the differential oracle and a declared tolerance. It is the only NPU physically present, and StableHLO and ONNX printers add vendor-schema exposure with no local validation path. This turns a 5-6 month milestone into roughly 6 weeks while still honouring the mandate honestly as 'we export to NPUs'.
- Reduce distributed v1 to parallel-heterogeneous's M6 localhost-multi-process version plus one 4-node TCP run whose only gate is checksum identity across locale counts. Drop roadmap M10's '>=70% strong-scaling efficiency at 8 nodes versus MPI+C' from v1 — it is a performance claim requiring an interconnect and a tuned MPI baseline nobody has, and the two designs currently state exit criteria roughly five months apart in implied cost for the same milestone.
- Move safety-security M-S7 (secret types plus the post-regalloc CT verifier) to aarch64-only in v1 and schedule it after the release backend stabilises, not in the same window as the prover and self-hosting. Constant-time verification of a backend that is still being rewritten weekly is wasted verification.

### Missing

- A per-language incremental-rebuild protocol for the harness. Without it the sub-50ms flagship claim has no comparable denominator across C/Rust/Go/Java/JS, and it is the claim the whole project is most likely to win.
- Enumerated, frozen Tier A and Tier B kernel lists with baseline compilers, versions, flags and the geomean formula. Six or more numeric exit criteria across three designs reference sets that do not exist.
- Windows / PE. The brief names 'Mach-O/PE incremental linking' as a known gap; PE and Windows appear in no milestone in any of the five designs. It is silently dropped rather than explicitly deferred.
- A stdlib effort line. roadmap-execution's own risk list says stdlib breadth is 'comparable in effort to the compiler itself'; surface-language enumerates the v0.1 and v1.0 module sets with no estimate; no milestone in any design contains stdlib work. This is the largest unbudgeted item after the optimizing backend — realistically 18-24 months of agent-heavy work where every public API needs Marc-reviewed design because it freezes at 1.0.
- The scalar and vector libm. parallel-heterogeneous names it as 'a hidden multi-month project' with a per-function ULP matrix and no SLEEF/SVML fallback available, then folds it into M3 alongside the entire SIMD type system and SPMD lowering. It needs its own milestone, its own accuracy exit criterion, and its own harness column, because until it exists every transcendental-heavy benchmark loses visibly.
- The fiber-boundary backtrace design (see blocking issues). Nobody owns it and two designs contradict each other by omission.
- A named owner of the bench schema, and the amendment rule. Four subsystems want fields in one JSONL schema that is frozen on day 19.
- The verbatim public claim text that replaces 'most efficient in existence'. roadmap-execution mentions a 'retired claims list' in ADR-0000 but no design writes the three sentences the project will actually say. Write them before the first public artifact on day 19, because the harness release is the first thing anyone reads.
- A cloud compute budget line for differential fuzzing. The only budget stated is $3-6k/year for GPUs from M9; 10M generated programs across five execution configs from M5 onward is likely larger.
- The weekly-hours commitment stated as a risk with a mitigation. Every estimate rests on 25h/week of Marc's review attention sustained for 9-10 years. If it is 25h/week alongside other obligations, halve every agent leverage factor; if it drops to 10h/week the plan is a different plan. This is the single largest variance source and it is unstated.
- A second pinned benchmark machine before the parallel claims are published. parallel-heterogeneous's own top risk is that a 6P+2E laptop is 'structurally incapable' of supporting the >=90%-efficiency-to-64-cores target and cannot see NUMA, scaling knees or bandwidth saturation — yet the x86 box arrives at M8, years after the parallel claims. Either acquire a used many-core x86 box in year 1 or scope every parallel claim to 'up to 8 cores, one machine class' until one exists.
- An exit criterion anywhere that references external users or external validation. Every gate in all five designs is self-measured. For the v0.1 release, which exists precisely to get outside validation, add a criterion involving someone who is not Marc successfully building and running a Fors kernel from the published instructions.
- A decision on whether the automatic C header importer is in v1 at all (see resequencing). compiler-architecture budgets 2.5 months for an own preprocessor plus declarations-only C parser plus Apple SDK attribute coverage and then correctly identifies header-import triage as 'a permanent background tax' — an unbounded item on the critical path with no stated bound.

### Improvements

- Pull PGO and block layout forward, unconditionally and early, rather than keeping it as the M5 contingency response. It is the best runtime-quality-per-engineering-hour item in the whole optimizer (Ext-TSP layout plus inline weights plus cold outlining), it is measurable on day one, it does not depend on the aegraph or the allocator being good, and it de-risks the C6 geomean gate instead of being the thing you reach for after missing it.
- Split compiler-architecture C6 (6 months, highest variance in the plan, one exit gate) into C6a — inlining, SROA/mem2reg, aegraph, LICM, ISLE isel, chordal RA, exit gate 2.0x geomean — and C6b — check elision, unroll/peel/if-conversion, alias-aware store-forwarding/DSE/move elision, exit gate 1.6x. A six-month milestone with a single gate is exactly where a solo project loses a year invisibly. Publish the Tier-A geomean weekly from the first working instruction selection, so the trend is visible months before the gate.
- Make DWARF per-compilation-unit from the start. compiler-architecture names whole-segment __DWARF regeneration as 'the most likely reason the 50ms budget quietly erodes over year 2' and then adopts it anyway. Three weeks of per-CU design now beats a rewrite in year 2 inside the milestone that also owns x86_64.
- Do not emit pointer authentication in v1, and delete the associated fiber risk. Third-party macOS binaries target arm64, not arm64e; PAC instructions appear only if the backend chooses to emit them, so pacibsp-vs-fiber-resume is not a constraint the design must work around yet — it is a hardening feature not yet claimed. Verify this against current Apple docs before relying on it, but if it holds, parallel-heterogeneous's top risk becomes a documented non-claim and fors_fiber_switch gets simpler. Revisit if and when arm64e becomes a supported third-party ABI.
- Restructure the bench schema as a frozen ENVELOPE plus versioned per-family payloads, rather than freezing everything on D19. The envelope (run identity, machine_id, provenance, thermal state, sample list, both checksum fields) is genuinely permanent. The payloads are not yet knowable: parallel needs capacity/locales/device/determinism_tier/schedule_hash, safety needs pass_rate/false_positive_rate/baseline_lang, surface needs a fastmath on/off column, compiler needs the --timings phase enum and cold/warm/incremental mode. Declare payload fields additive-only and RFC-gated.
- Extend the harness's self-test discipline beyond the D16 regression injection. Seed three faults and verify all three are caught: a 5% slowdown (a sleep or an -O1 downgrade) must be flagged and a 1% one must not; a deliberately wrong checksum must fail the correctness gate and be reported as incorrect, not as slow; a thermally throttled or AC-disconnected run must abort at preflight. A harness that has never been shown to catch a fault is not evidence of anything.
- Add a FALSE-POSITIVE corpus to the race checker's exit criteria. safety-security M-S2 measures only false negatives (40 racy cases must be rejected) plus three reference data structures. The number that decides whether the language is usable is how often a legitimate race-free program is rejected. Build a positive corpus of realistic concurrent code (producer/consumer, halo exchange, work queue, read-mostly shared config, parallel histogram) with a target acceptance rate, and track it as a CI metric like the alias-precision metric.
- Define the denominator for the check-elision percentages. safety-security M-S6 claims stage 1 eliminates >=90% of bounds and >=80% of overflow checks, but 90% of 'checks a naive lowering would emit' and 90% of 'checks remaining after C6's structural elision' are wildly different bars, and the compiler design already removes most of the easy ones structurally. Pick the post-structural denominator (the harder, honest one) and state it in the exit criterion.
- Replace 'zero unsoundness found by adversarial review' (roadmap M12 prover exit criterion) with a mechanical criterion: over N generated programs, zero cases where an obligation discharged statically fails at runtime under the reference interpreter, with every statically discharged obligation remaining runtime-checked forever in the interpreter tier. 'No one found a bug' is not an exit criterion; it is the absence of one, and it is unboundable.
- Add a diagnostics-quality corpus with a gate. surface-language hand-authors five diagnostics and a stable code catalogue, which is right, but no design measures diagnostic quality anywhere and no exit criterion mentions it. For a language whose adoption thesis is C/C++ programmers replacing hot loops kernel-at-a-time, bad error messages kill adoption faster than 1.6x codegen. Build a corpus of ~100 realistic wrong programs, require a stable code plus a suggested fix for each, and have a human rate a sample each quarter.
- Put allocator quality on the measured axis and in a milestone. roadmap-execution's own risk list says allocator quality 'often dominates real-application performance more than codegen' and then no milestone owns it and no metric tracks it. Add an allocation-stress kernel plus a mixed-lifetime application benchmark to Tier B, and name the allocator work (size classes, per-worker caches, MPSC remote frees, MADV_FREE decay) as an explicit deliverable rather than a bullet inside the parallel runtime milestone.
- Tighten the two-session rule with two clauses: the acceptance-test-authoring session must not have seen the implementation diff (easy to violate accidentally on a resumed session), and the opus review gate on unsafe/spec diffs must be a different session from the author. Also record the lane and model per commit so the unsafe-inventory trend can be correlated with provenance later.
- Add a recurring 'a stranger can build this' CI job from a clean checkout on a clean machine image: the harness runs, the conformance suite runs, the spec builds. On a multi-year solo project with no co-maintainer, the spec plus conformance suite plus harness ARE the continuity plan, and they are only continuity if they are independently reproducible.
- Write down a kill/reposition criterion, not just re-sequencing gates. Proposal: if at month 30 the release-backend Tier-A geomean is worse than 2.5x best-of(clang,gcc,rustc) and the public v0.1 has fewer than ~20 external users, publicly retire the G1 parity claim and reposition permanently as 'the fastest-building memory-safe systems language with capability-confined reproducible builds and first-class structured parallelism'. Deciding this in advance is what prevents years 4-7 being spent defending a claim that the data already refused.

## Lens: goal-fidelity

**Verdict.** Two of the six targets are reachable as designed, one is reachable with methodology repair, and three are not reachable without design changes. Reachable: 100% undeclared-authority confinement (subject to renaming the metric and closing the inline-asm and artifact-binding holes) and the safety-cost target, both because they are architectural properties rather than research outcomes. Reachable with repair: the sub-50ms p95 incremental and the 3x-over-Go cold build -- the mechanisms are sound, but the p95 budget omits DWARF while the resign optimization depends on DWARF not dirtying pages, and 'cold' is undefined for the stdlib layer on both sides, so today both numbers would be correctly rejected by a skeptic before anyone argues about the compiler. Not reachable as designed: within 5% geomean of best-of(clang,gcc,rustc), for three independent and individually sufficient reasons -- no autovectorization or loop-nest transforms against baselines that have both, FMA contraction banned by default when the baseline contracts, and shape-based generic dispatch as the default in hot numeric code -- compounded by a 3-6% trap-overhead budget that alone consumes the entire 5% margin; and >=90% parallel efficiency, which is physically unattainable on the named bandwidth-bound kernels at 6 M1 Pro cores no matter how good the runtime is. The determinism ladder, which is the most differentiated parallel claim in the plan, is currently specified three incompatible ways (declared width, native lanes, grain), two of which make numeric results machine- or tuning-file-dependent and thereby falsify both D1 and reproducible builds; the CI gate as designed cannot detect the bug. The methodology attacks that would actually land are: we author both sides of every kernel, the suite is not pre-registered, the adversarial dependency suite is ours, the compile-speed corpus is generated by us, the headline incremental number is a daemon number with no comparator, and the reported win is build time rather than edit-to-test-result latency with dev-tier artifact runtime disclosed. Fix those six and the numbers survive contact with a hostile reader; leave them and every real engineering achievement here gets filed next to V's LoC/sec. Net: the plan's honest public position for the next four years is fastest builds, zero-UB safe subset, confined dependencies, competitive-not-leading scalar codegen, and best-in-class parallel determinism -- and 'most efficient in existence' plus 'fastest parallelization' should be retired from the vocabulary in writing, now, before the harness publishes its first row.

### Blocking issues

1. **No mechanism for idiomatic-loop performance. The compiler design explicitly refuses autovectorization AND polyhedral/loop-nest transforms, and defers scheduling to year 3. Every third-party suite named as the G1 baseline (SPEC, PolyBench, LLVM test-suite, Rodinia, NAS) is plain countable loops. Ported idiomatically to Fors they stay plain loops and clang/gcc -O3 vectorize and interchange them while we do not. If we instead rewrite them as simd-for, we hand-vectorized and the baseline did not, and the comparison is rigged the other way. Either way 'within 5% geomean of best-of(clang,gcc,rustc)' is unreachable by construction, not by execution quality. No document acknowledges this.**
   - Where: compiler-architecture s3 ('Deliberately not doing: autovectorization, polyhedral loop transforms'); parallel-heterogeneous SIMD decision; roadmap M5/M7 exit criteria
   - Fix: Ship a restricted autovectorizer in C6/M5 scoped to what mandatory alias classes make cheap: countable loops, trusted-length or affine access, no cross-iteration dependence provable from alias classes, integer plus FMA-contractable FP only (no reassociation). Dependence testing is near-trivial with structural alias classes, which is the one place that story actually pays. Add unroll-and-jam with accumulator splitting under an explicit relax(reassoc) scope. Publish G1 as two rows: idiomatic-port geomean and explicit-SPMD geomean.
2. **Strict no-FMA-contraction by default is a pure self-inflicted loss against the declared baseline. clang -O3 defaults to -ffp-contract=on (within-statement FMA, the C standard default) and gcc defaults to =fast. Fors forbids contraction unless a relax scope is opened. Contraction is deterministic given the IR: it changes results versus non-contracted code identically on every target, so banning it buys zero cross-machine reproducibility and costs up to 2x on dot/stencil/FMA-shaped scalar code before vectorization even enters. We pay a real percentage to be stricter than the thing we are trying to match.**
   - Where: compiler-architecture (FP determinism decision); surface-language (strict IEEE-754 default); safety-security (no FMA contraction unless lexically enabled)
   - Fix: Make within-statement FMA contraction the default (matching C) and record fusion decisions structurally in OIR so they are part of the reproducibility manifest; keep reassociation, reciprocal substitution, finite-math and nsz off by default. Reserve a no-contract mode for bit-compat-with-serial-C kernels and for the D2 portable tier only.
3. **Three incompatible definitions of what fixes the reduction tree shape, which falsifies the determinism claim that is the project's most differentiated parallel selling point. compiler-architecture: shape fixed by DECLARED width W, explicitly independent of hardware. parallel-heterogeneous: D1 leaf block B = 4 * native_lanes, i.e. machine-dependent. surface-language: reproducible 'for a given (n, grain)', where grain comes from a cost model plus checked-in .fmach calibration and can be overwritten by .fsched artifacts. Two of the three make numeric results depend on the machine or on a tuning data file, so cross-machine reproducible builds and the 'tuner only does result-preserving transforms' claim cannot both hold.**
   - Where: compiler-architecture (reduce.tree(width=W)); parallel-heterogeneous (D1, reduction_block_size); surface-language (reduce order: tree, per (n,grain))
   - Fix: Adopt compiler-architecture's rule as normative: tree shape is a function of declared W and n only, never of native_lanes, thread count, grain, schedule artifact or locale count. W and the tail rule become part of the reproducibility manifest. Grain and tiling may not appear in any reduction's value-determining inputs. Spec the tail explicitly: partial-block identity element, signed-zero and NaN behaviour for add/mul/min/max, and the combining order of the last partial.
4. **Strict-IEEE-no-reassociation and tree-reduction-by-default are contradictory, and the contradiction removes the safe-subset parallelism most users will write. A tree reduction IS reassociation. So a user-written 'sum += x' accumulator inside a parallel for is either rejected or unparallelizable under strict FP, while the C+OpenMP baseline gets reduction(+:s) whose order OpenMP leaves unspecified and is therefore allowed to be faster. The >=90%-efficiency target then only applies to code rewritten with the reduce combinator, which is a different program from the baseline.**
   - Where: surface-language (strict IEEE default plus reduce(+, order: tree) default); parallel-heterogeneous (D1 default); compiler-architecture (reassociation off by default)
   - Fix: Define reduce as a distinct primitive whose specified semantics ARE the declared tree (not sugar for a loop), state in the spec that a lexical accumulator loop is not auto-parallelizable, and make the diagnostic on a parallel-for accumulator name the reduce rewrite. In the benchmark report, disclose the semantic difference versus OpenMP reduction and publish both an ordered-reduction row and a tree row so the FP-order advantage is visible rather than hidden.
5. **Incremental DWARF collides with dirty-page code signing, and this interaction breaks the 50ms budget's load-bearing mechanism. The ad-hoc CodeDirectory page-hashes the whole file up to the signature, which includes the __DWARF segment. The design's stated initial approach is to regenerate a whole compilation unit's debug info per edit; DWARF is typically several times the size of the code it describes, so one edit dirties a large fraction of the file's pages and 'rehash only dirty pages' degenerates to rehashing most of the image. The 7ms link-plus-resign line item and the 21ms slack are both unbudgeted for this, and the p95 table does not contain a DWARF row at all.**
   - Where: compiler-architecture s6 (clonefile plus dirty-page resign) versus s7 and the DWARF decision ('regenerate the whole __DWARF segment for changed compilation units'); milestone C4 exit criterion
   - Fix: Keep debug info out of the signed image in the dev tier: emit per-CU DWARF into a separate companion artifact (split-DWARF .dwo set plus a skeleton, or an unsigned sidecar bundle lldb is pointed at), so DWARF churn never dirties a signed page. Reserve fixed per-CU slack for line tables and DIE offsets. Add an explicit DWARF-regeneration row to the p95 budget table and re-derive the slack before the 50ms number is published anywhere.
6. **Shape-based generics with witness-table indirect calls is the wrong default for G1 and the wrong default to discover late. An indirect cmp inside sort, or an indirect lane op inside a reduction, blocks the two passes named as the biggest release-backend wins (inlining, then everything downstream of it) and blocks vectorization entirely. The surface design names this as its own top risk with a fallback of 'auto-specialize all scalar-shape instantiations' -- but the default choice is baked into every stdlib signature, so flipping it after benchmarks means rewriting std.**
   - Where: surface-language (generics and traits decision, plus its top-risks entry); compiler-architecture C2 (shape-based lowering by default plus @specialize)
   - Fix: Flip the default now, before std is written: monomorphize any instantiation whose shape is scalar or <=16 bytes, and any generic body under an instruction threshold, with the content-addressed instantiation cache bounding the compile-time cost; make dyn the explicit opt-in. Keep shape-based lowering for large or pointer-shaped instantiations where code size dominates. Track instantiation count and binary size as CI metrics so the G3 cost of the flip is visible.
7. **Trap-on-overflow cost and the 5%-of-best-of-C target are arithmetically incompatible and no document reconciles them. The research budget for check overhead is 3-6% initially against a <=2% goal; safety-security's own risk list says tight integer kernels are the likeliest place to lose the 5% target and makes the stage-1 range discharger load-bearing for performance. You cannot be within 5% of clang -O3 while paying 6% for checks clang does not pay.**
   - Where: safety-security (UB-free semantics decision plus M-S6 exit criteria); roadmap M3 exit criterion (<=6% initially, <=2% by M7) versus M12 (<=5% geomean versus clang)
   - Fix: Split the claim and never state both at once: (a) safety cost = checks-on versus internal checks-off instrumentation build, target <=3%; (b) competitiveness = Fors-with-checks versus C compiled with equivalent trapping semantics (-ftrapv / UBSan-trap / Rust debug-assertions) for the apples-to-apples row, plus a clearly labelled row against plain clang -O3 that we expect to lose by the check cost. Publish per-kernel eliminated-check fractions so the discharger's contribution is auditable rather than asserted.
8. **Confinement is compile-time advisory, not artifact-bound, and inline assembly is an uncovered escape. Capability re-checking happens in our driver from signed BMIs, but release linking is system ld64, which knows nothing about capabilities -- so the guarantee is 'our driver checked', trivially bypassed by invoking the linker directly. Worse, no design names an asm capability: modules that legitimately declare 'uses unsafe' (allocators, the split primitive, atomics, SIMD kernels) can issue an svc/syscall directly. The 100%-confinement target is therefore not a property of the shipped binary.**
   - Where: safety-security s5 (link-time recheck from signed BMIs) versus compiler-architecture (system ld64 for release); safety-security unsafe-subset decision (no asm in the unlocked-intrinsic list)
   - Fix: Make asm and syscall capabilities distinct from unsafe. Because we own the assembler and the object writer, verify mechanically: scan emitted machine code for syscall-class instructions and reject them in modules lacking the capability (cheap, and it is real enforcement rather than a promise). Emit the resolved capability manifest into a Mach-O/ELF section hashed into the code signature, verify it at process start, and on macOS derive a sandbox profile or entitlement set from it so at least one enforcement layer is the OS rather than our build tool.
9. **100% on a self-authored adversarial suite is a tautology, and the suite as specified only covers ambient-authority attacks. It does not cover the 2026-shaped attack: a dependency that legitimately holds a granted capability and abuses it, or capability laundering (pure module A calls net-capable module B's innocuous upload_metrics), or a numerical backdoor in pure compute that needs no capability at all. Authority confinement is not information-flow confinement, and the design has no data-flow check between a pure module and a capable one.**
   - Where: safety-security S2 adversarial package suite plus M-S5 exit criterion; roadmap M4 exit criterion ('100% of the adversarial suite confined'); surface-language M4 exit criterion
   - Fix: Three changes before any 100% number is published: (1) port an external corpus (published npm/PyPI malicious-package payloads, Backstabber's-Knife-class dataset) so the suite is not ours, and cite provenance per case; (2) run a paid public red-team round and publish results including the escapes; (3) publish, adjacent to the number, the taxonomy the model provably cannot stop -- FFI subtrees, dlopen tier A, granted-capability abuse, capability laundering, pure-compute logic bombs -- and rename the metric 'undeclared-authority confinement' so it is not read as 'malicious dependencies cannot hurt you'. Note that in HPC the realistic graph (BLAS, MPI, vendor GPU) is mostly FFI, i.e. mostly unguaranteed; say so.
10. **Three mutually incompatible error models are specified across three documents, and the failure ABI is the one thing two backends plus an interpreter must agree on bit-for-bit. Keyword: raises (surface) versus throws (safety). Payload: 'normal register set via our own convention' (compiler-arch) versus {payload,tag} with tag 0 = success and a failure_class threshold (safety) versus 'second return register x1 / x8-sret plus flag' (surface). C++ across FFI: 'aborts, documented' (compiler-arch) versus a generated @catches_cxx shim that links the platform unwinder and converts to tags (safety) -- which contradicts 'no unwinder, no EH tables, ever' and silently reintroduces a libunwind link dependency and its binary-size and codegen cost.**
   - Where: compiler-architecture (error handling and failure ABI decision, s7); safety-security (failure ABI decision, s4, fors_abi::failure_class); surface-language (errors decision plus its interfaces note)
   - Fix: Freeze one normative failure ABI document owned by the surface/semantics lane before C4 and M-S3 start, including keyword, tag encoding, the register-versus-sret threshold as a single classifier function, and the C-interop mapping. Decide the C++ question explicitly: either abort at the boundary with no unwinder anywhere (keeps the no-EH claim intact) or accept a narrowly scoped shim and delete 'no unwinder ever' from the marketing. Add the failure ABI to abi-fuzz so interpreter, dev backend and release backend are differentially tested on it.
11. **Two incompatible memory models for graph-shaped data, and the richer one is a region system in disguise. safety-security specifies branded arenas where 'with arena A' introduces a comptime-generated nominal brand and Ref<Node,A> is only usable with that arena. surface-language has no brands at all -- only Handle[T], Own[T] and an explicit statement that graph data has no ergonomic safe encoding. A scope-introduced nominal type parameter that must not escape its binder is exactly a region variable, which strains both owner decision 'no region inference in v1' and the surface's own two-judgement, no-solver inference rules (escape of a brand-parameterized value out of the with-scope is a non-local check).**
   - Where: safety-security (branded arenas decision, brand_compatible, arena reset generation) versus surface-language (core types: 'No safe stored reference type in v1'; top-risks entry admitting the hole)
   - Fix: Pick one and put it in the surface spec: either brands are in the language (then specify brand introduction, the non-escape rule, and prove it is checkable in the two-judgement system with no inference variable outliving an expression) or they are not (then arenas are ordinary Handle[T] with a debug-only generation counter, and the expressiveness hole is documented). Also resolve the reset rule: the ergonomic option in safety-security's own contribution note makes a release-mode use-after-free a silent logic bug, which violates zero-UB in the safe subset -- so reset must either rebrand or keep the generation check in all modes.
12. **Three different reference-capability lattices with three different sendability rules. safety-security: four (iso/mut/imm/ro) with Pony viewpoint adaptation and recover. surface-language: three (iso/imm/secret), asserting conventions already cover mut and ro, and a sendability rule that additionally admits any value type with no interior references. parallel-heterogeneous: four (isolated/exclusive-mutable/shared-immutable/read-only) as first-class types. The disjointness judgement for spawn captures also differs: parallel wants a ranked ladder including an index-partition token, which is index analysis that surface explicitly refuses.**
   - Where: safety-security (race-freedom decision, viewpoint_adapt); surface-language (three-qualifier decision); parallel-heterogeneous (interfaces_to_other_subsystems, capture typing)
   - Fix: One RFC fixes the lattice, the viewpoint table and the sendability rule before M-S2 and M2 start, since the spawn capture rule is the soundness basis for both race freedom and the optimizer's disjointness assumption inside detached regions. Drop the index-partition token from v1 to match surface's projection-provenance-only rule, or add it to the surface spec with a decidable rule -- do not leave the checker's strongest tier undefined in the language it must check.
13. **>=90% parallel efficiency on 'regular kernels' at 6 P-cores is physically impossible for the named kernels on the dev machine and is set as a hard exit criterion. nstream, stencil and transpose are bandwidth-bound; on an M1 Pro a small number of P-cores already saturate a large share of memory bandwidth, so linear-scaling efficiency at 6 cores cannot reach 90% regardless of compiler or runtime quality. The M0.P milestone correctly adds roofline reporting, then the M2 exit criterion ignores it.**
   - Where: parallel-heterogeneous M2 exit criterion ('>=90% capacity-normalized efficiency on 6 P-cores for all three'); roadmap M6 exit criterion; brief target
   - Fix: Split the target by arithmetic intensity. For kernels below the machine balance point, gate on fraction-of-achievable-roofline (measured by a calibration kernel) and report scaling only as a curve. Gate the >=90% linear-efficiency claim on compute-bound kernels (dgemm tile, mandelbrot, nqueens, cilksort, UTS). State the capacity-normalized denominator in every published figure, and never merge P-only and P+E points into one curve.
14. **'>= Rayon' is unfalsifiable as written and is the easiest number in the plan for an outsider to reject. Naive par_iter is a strawman: the research's own data point is a 10x win from working around Rayon's splitting. If our Rayon baselines are not expert-tuned (with_min_len, explicit chunking, arena reuse) the comparison is worthless, and if they are, we must publish them.**
   - Where: parallel-heterogeneous M1/M2 exit criteria; roadmap M6 exit criterion; brief target
   - Fix: Require every Rayon and OpenMP baseline to be tuned and externally reviewed (upstream sources with commit hashes wherever they exist: PRK, NAS, GAP, ISPC examples), publish the full baseline source next to every number, and add a tuned-versus-naive baseline column so the size of the tuning effect is visible. Same rule for OpenCilk and Kokkos.
15. **Two targets that will be quoted together are measured on incomparable ground: the cold-debug-build >=3x-over-Go claim compares a Fors build that reads prebuilt content-addressed .forsi interfaces and instantiation caches against a Go cold build that compiles stdlib source into an empty GOCACHE. Neither the roadmap nor the compiler-architecture harness contract defines what 'cold' includes for the dependency and stdlib layers, and the compile-speed corpora on both sides are generated by us.**
   - Where: compiler-architecture s10 (--cache-dir, cache clear, --no-daemon) and s2 budget; roadmap M2 exit criterion; roadmap D14 corpus generator
   - Fix: Define and publish three cold variants for both languages: everything-from-source, stdlib-prebuilt-project-cold, and warm-incremental. Add real third-party projects for the competitor side (build Go's stdlib, ripgrep, sqlite via clang plus mold) and treat the synthetic generated corpus as a clearly separated row. Freeze the generator and publish it so the corpus is auditable. Report daemon RSS and first-build-after-start alongside the daemon p95.

### Resequencing

- Freeze the failure ABI, the reference-capability lattice, the reduction-determinism rule and the branded-arena question in one semantics RFC bundle BEFORE C4 / M2 / M-S3 start. Today three designs specify three versions of each, and all of them are inputs to the dev backend, the interpreter and the race checker simultaneously. This is a weeks-long document that prevents months of divergence.
- Flip the generic-specialization default to monomorphize-scalar-shapes before std is written (C2 / M3 era), not after benchmarks. Changing it later rewrites every stdlib signature, and the surface design already names the flip as its fallback.
- Move the restricted autovectorizer and unroll-and-jam into C6/M5 scope, ahead of scheduling and software pipelining. It is the only mechanism that makes the 5% geomean target reachable and it is cheapest precisely where the alias classes already exist.
- Pull a minimal x86_64/ELF correctness path (no tuning) forward to immediately after C6 exits, from C8/M8 in year 4-5. Three reasons: a single-microarchitecture G1 claim is dismissible; aarch64-only codegen bakes in Apple-specific assumptions (always-frame-pointers, OOO so skip scheduling, no masked stores) that are expensive to retrofit; and ELF gives a working fallback for the incremental claim if the Mach-O signing bet fails.
- Pull one Tier-B application port (JSON/protocol parser or LSM KV store) forward to immediately after C6, rather than leaving applications to M7/M12. Kernel geomeans are the easiest number to flatter; an application is where allocator quality, stdlib breadth and ABI cost surface, and it is where the 'works on the author's laptop' failure mode gets caught while there is still time.
- Schedule the vector/scalar libm as its own named milestone between C7 and M6-equivalent work, before any transcendental-heavy kernel enters the published set. It currently has no owner in the roadmap and blocks black-scholes, softmax and every ML-shaped kernel.
- Decide the DWARF-out-of-signed-pages design during C4, before the 50ms number is published. Publishing the headline first and discovering the DWARF interaction second is the sequence that costs credibility rather than time.
- Add the kernel-set freeze, the pre-registration statement and the external malicious-package corpus to M0 (day 17-19), not to M4/M8. Both are cheap now and both are unrecoverable later: a suite assembled after results exist cannot be made credible retroactively.
- Move the security red-team round to precede, not follow, the first public 100%-confinement claim -- i.e. into M4's exit criteria rather than M12's registry hardening.

### Missing

- A restricted autovectorizer and any loop-nest transform, i.e. any mechanism at all for the performance of loops the programmer did not hand-vectorize -- the direct blocker on the 5% geomean target.
- Our own scalar and vector libm. parallel-heterogeneous names it as a hidden multi-month project on the critical path for transcendental kernels; surface-language lists math in the v0.1 stdlib; the roadmap budgets it in no milestone. With no LLVM there is no SLEEF/SVML fallback, so every transcendental-heavy benchmark loses until it exists.
- An asm/syscall capability and mechanical verification of its absence in modules that lack it. Without this, any module declaring 'uses unsafe' (allocators, split, atomics) escapes confinement.
- An information-flow story: nothing prevents a pure-compute module's data reaching a net-capable module, so confinement covers authority but not exfiltration.
- Artifact-level binding of the capability manifest: the set is checked by our driver but is not verified in the shipped binary, and release linking goes through ld64 which does not know capabilities exist.
- A normative failure-ABI document. Three subsystems specify three different ones and two backends plus an interpreter must agree bit-for-bit.
- A decision on whether branded arenas are in the language, and a corresponding surface-spec rule for brand non-escape. Today one design depends on them and another says graph data has no safe encoding.
- A single reference-capability lattice, viewpoint table and sendability rule shared by all four designs that reference it.
- Edit-to-test-result latency, artifact-runtime-per-tier, daemon RSS, and first-build-after-daemon-start as harness metrics.
- A frozen, hashed kernel manifest and a stated pre-registration rule; plus a third-party reproduction protocol (one-command container, named external re-runner, published sources for every implementation on both sides).
- An externally sourced malicious-dependency corpus and a published list of attack classes the capability model cannot stop.
- A DWARF row in the incremental p95 budget and a design for keeping debug info off signed pages.
- Measured targets for release-mode contract cost, binary size, and startup -- two of which the design will win and is currently not claiming.
- A roofline-relative efficiency definition for bandwidth-bound kernels, so the >=90% gate is physically satisfiable on the dev machine.
- Tail semantics for the deterministic reduction (identity element, signed zero, NaN, last partial block ordering) for n not a multiple of the block size.
- A comparator for the incremental-rebuild target, so sub-50ms becomes a competitive claim rather than an absolute one.

### Improvements

- Report edit-to-test-result latency, not build time alone. Dev-tier code is -O0-plus (the research's corrected view: 2-5x slower than -O2 on compute-bound code), so a 3x build-time win can be erased by a 3x slower test run. A Pareto plot of (compile time, artifact runtime) per tier is the number a skeptic cannot dismiss, and it is the number that could lose -- which is exactly why publishing it buys credibility.
- Pre-register and freeze the kernel set. No document says the suite is frozen; kernels are added at M0.P, M3 and later Tier-A/Tier-B stages. Publish a hashed kernel manifest at day 19 and report any post-hoc addition as a separate, labelled set. Without this, 'geomean over our suite' is rejected on sight.
- Give T1 a comparator row. 'Sub-50ms p95' is not a competitive claim until it names who it beats: Zig's ELF incremental number, go build incremental, cargo check, tsc --watch. Also define the edit distribution behind p95 -- body-only edits make the number trivial; the corpus must include signature edits, a widely imported type, and a comptime constant, and must include the diagnostics work the daemon does in the same keystroke.
- Add a thermal canary instead of relying on PMU access. powermetrics needs sudo and is excluded, so frequency is unobservable. Interleave a fixed-duration calibration kernel every N measurements; a drift in its time is the throttle signal, and its trace is publishable evidence that a run was clean.
- Add a cross-width and cross-ISA determinism gate. Varying thread count and locale count cannot detect a reduction tree keyed on native_lanes, because the serial-elided reference on the same machine has the same width. Require bit-identity across at least two declared W values and, once x86_64 exists, across ISAs.
- Make the checks-off build an internal instrumentation mode only, explicitly unshippable. A flag that disables traps re-introduces UB and is not a valid Fors program; if it leaks into the toolchain it also becomes the first thing a benchmark-chasing user turns on, which destroys the semantic-uniformity argument for two backends.
- Measure release-mode contract cost. Keeping public-boundary preconditions in release is a branch on every public API call and appears in no performance target. Set a measured budget (suggest <=1% geomean) and publish it separately from bounds/overflow cost.
- Make no-unwinder a measured differentiator rather than an unclaimed side effect. Set targets for stripped hello-world static binary size and startup time versus C, Rust, Go, Zig, Swift. This is a claim the design will actually win, it is cheap to measure from M2, and it gives the pre-performance v0.1 release a second number besides compile speed.
- Publish an alias-precision and eliminated-check dashboard from the first optimizer pass, not later. Both the aliasing story and the safety-cost story are silent-degradation risks: a conservatively merged alias class and a missed range discharge each lose performance with no test failure. These metrics are the only defence and they only work if they exist before the passes.
- Bound the blast radius of the macOS signing bet by landing a minimal ELF path early. ELF permits Zig-style in-place patching without a signature problem, so a working x86_64/ELF or aarch64/Linux dev path is a functioning fallback for the flagship incremental claim if AMFI or chained-fixups behaviour changes under us.
- Fix the FP checksum gate's inconsistency with D1. A 1e-9 relative tolerance on a quantized reduction can accept a wrong-but-close result and contradicts the bit-identity selling point. Use bit-exact comparison against the declared tree for Fors-versus-Fors gates, and reserve tolerance strictly for cross-language comparison against a 256-bit oracle.
- Add an allocator-stress kernel and an allocator performance target to the frozen set. Real-application performance often turns on allocator quality more than codegen, the design writes its own size-classed allocator, and no milestone owns its performance versus mimalloc/jemalloc/Go's allocator.
- Name the GPU baseline authors. '>=70% of vendor-tuned' and 'within 15% of hand-written Metal' need a stated baseline (MPS and MLX are the honest Metal comparators) and a launch-overhead metric, since single-source abstractions usually lose on launch cost rather than on kernel body quality.
- Resolve the MVS-versus-capability-widening deadlock. Rejecting capability-widening patch and minor releases at the registry means a security fix that legitimately needs a new capability cannot reach MVS users at all. Add an explicit security channel that may widen capabilities with a recorded fors grant approval, so the policy that makes G2 strong does not block patching.
