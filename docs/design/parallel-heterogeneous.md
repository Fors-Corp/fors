# Fors design: parallel-heterogeneous

> **Status: design-panel draft, 2026-09-19.** Produced by one subsystem architect working alone. Where this conflicts with `docs/PLAN.md` (section 4, Resolutions), PLAN.md wins. Cross-design conflicts are catalogued in `reviews.md`.

## Summary

Fors gets one parallelism mechanism, reused everywhere: structured fork/join represented as first-class Tapir-style `detach`/`reattach`/`sync` instructions in a mid-level Parallel IR, with sibling-task safety proved by the reference-capability/parameter-convention system rather than by a race detector. A CPU work-stealing runtime with continuation stealing, compiler-generated fast/slow clones and pooled fibers gives Cilk-class spawn costs; Apple Silicon P/E asymmetry is handled by a two-class worker pool, QoS placement, a measured capacity weight per core class and lazy (steal-triggered) loop splitting, so heterogeneity is absorbed by stealing instead of by static partitioning. SIMD is explicit and two-layered: fixed-width `vector<T,N>` plus a sizeless `vec<T>` for SVE/RVV, with `mask<N>` as a distinct type and a hard spec rule that masked-off lanes never fault and never trap. Floating point is strict IEEE-754 by default with lexically scoped fine-grained fast-math, and the headline differentiator is a determinism ladder whose default tier D1 guarantees bit-identical results across thread count, steal pattern, core class and locale count via fixed-shape, schedule-independent reduction trees, machine-checked in CI by a steal-injection differential tester. GPU is single-source and tile-level (Triton-validated), with SPIR-V binary emission as the canonical device IR, a hand-written MSL text printer for Metal first on the dev machine, PTX text via the CUDA driver JIT second, and AMD reached through Vulkan compute rather than through LLVM-bound HIP. Kernel launches are not a new concept: a launch is a `spawn` whose captures undergo the same isolation-domain transfer, which is what makes device memory, Apple unified memory and host/device coherency fall out of the borrow rules for free. Distribution uses locales plus partitioned global arrays, made safe by the rule that only isolated or shared-immutable values cross a locale boundary (isolation gives structural serializability), and deliberately forbids implicit fine-grained remote gets to avoid the classic PGAS performance trap. NPUs are handled honestly: a restricted `@tensor` sub-language that *prints* textual StableHLO, CoreML MIL and ONNX (printing a dialect needs no MLIR dependency, unlike consuming one) with native CPU/GPU lowerings as the differential-testing reference. All search is exiled from the compiler into `fors tune`, which writes human-diffable, content-addressed schedule artifacts, and machine cost models are checked-in calibration data on the same footing.

## Decisions

| Decision | Choice | Rationale | Risk |
|---|---|---|---|
| Fork/join representation in the IR | CFG-embedded Tapir triple (`detach` / `reattach` / `sync`) in a mid-level Parallel IR, plus a verified side task-tree index and an explicit typed capture list on `detach` | Scalar optimizations (inlining, DCE, LICM, vectorization) keep working unchanged by treating `detach` as a branch, which is the whole Tapir payoff and what makes a 'fast compiler for parallel code' claim credible. The explicit capture list, typed by reference capabilities, replaces the race detector OpenCilk needs: sibling non-interference is a type-checked precondition, so alias analysis may assume disjointness inside detached regions by construction. The verified task-tree index (detach dominates reattach, sync post-dominates) prevents the alloca/escape bugs Tapir-on-LLVM had to retrofit with taskframes. | Every serial pass must be audited for a 'this is just a branch' assumption that is actually unsound across a detach (e.g. sinking a store past a reattach). Putting it at the call site under compiler control, and deferring the split until a steal request is actually observed, makes the no-contention path essentially free while keeping load balance. The cost model is fed by checked-in per-machine calibration data, so it is reproducible rather than a guessed constant. | A wrong cost estimate for an opaque body (FFI, indirect call) yields either spawn-overhead-dominated or badly imbalanced loops. A separate mask type lets each target pick its native representation (NEON lane-wise, AVX-512 k-register, SVE predicate) instead of forcing a `vector<Bool,N>` lie. Sizelessness (no aggregate fields, no heap, no generic containers) is the only sound way to admit scalable vectors into a language with full layout control. | Parallel determinism policy | A declared determinism ladder with D1 (run-reproducible: bit-identical across thread count, steal pattern, core class, locale count) as the DEFAULT for the safe subset, implemented via fixed-shape schedule-independent reduction trees over fixed leaf blocks; D0 and D2 opt-in | Race freedom is not determinism, and every competitor conflates them. Determinism does not require serial order, only a schedule-independent reduction tree, so we get it at roughly 2-4% bandwidth cost for a partials array, with better accuracy than serial summation (pairwise error O(log n eps)). The reduction leaf-block size becomes a results-visible constant that cannot be changed without invalidating published numbers. |
| Floating-point default | Strict IEEE-754, no reassociation, no FMA contraction, no reciprocal substitution; fine-grained lexically scoped `@fastmath(reassoc, contract, nsz, finite, recip)` as per-op IR attributes | Per-op attributes, rather than a module flag, mean inlining across a fastmath boundary cannot leak relaxed semantics into strict code, which a module-level flag cannot promise. Fine grain lets a kernel enable contraction (free FMA) without enabling reassociation (which would break D1). | Strict default makes us look slower than `-ffast-math` competitors unless benchmarks disclose flags on both sides. Metal comes first because it is the only local GPU; MSL is documented stable text, whereas AIR is undocumented LLVM bitcode and emitting it would violate both the letter and the spirit of the no-LLVM rule. | GPU programming model and its memory/capability mapping | Tile-level kernels (not thread-level) with a `@device` subset checked as an effect; a launch is a `spawn` whose captures undergo the same isolation-domain transfer, `Device` is a capability value, and Apple unified memory is a `Device` property that makes the IR `transfer` op lower to nothing | Tile-level is the validated route to near-hand-tuned GPU performance (Triton reaches 94-96% of expert kernels) and it makes lanes non-interfering by construction. Metal's shared-storage coherency rule (valid only outside a command buffer) is exactly the borrow scope, so the type system enforces it for free. One source then runs on unified and discrete memory with the copy elided where it is a no-op. | Writing our own tiling / shared-memory staging / coalescing pass without MLIR is the expensive part; that pass is most of Triton's value and took a team years. Warp specialization and async pipelining for compute-bound peak are further out. Honest targets: within 15% of vendor on memory-bound, 40% on compute-bound. |
| Distributed model | Locales plus partitioned global arrays (PGAS-style), safe because only isolated or serializable shared-immutable values cross a locale boundary; explicit `Transport` implementations (Loopback, UnixSocket, TCP first; RDMA and MPI interop later); NO implicit fine-grained remote element access | Isolation domains already guarantee no incoming aliases, which is precisely the precondition for sound structural serialization, so the compiler derives wire formats with no annotations and no reflection: the memory model pays for itself twice. Forbidding implicit remote gets avoids the documented PGAS trap where an innocuous `a[i]` in a loop becomes a microsecond-scale round trip; remote access must be spelled `a.remote[i]` or batched (`gather`). Structured concurrency spans nodes, so a `parallel` scope's sync waits for remote children and errors propagate home. | Purists will say this is not really PGAS, and the ergonomic hit could sink distributed adoption. Achieving Chapel-class performance parity also needs real communication-scheduling engineering, which is a multi-month runtime effort on its own. |
| Single-machine distributed development and testing | `fors run --locales=N` spawns N OS processes on localhost over the UnixSocket transport as the primary dev loop, plus a single-process Loopback mode with per-locale arenas for deterministic replay, plus a transport fault/latency/reorder/drop injector | Multi-process localhost catches the bugs that matter (accidental pointer sharing, serialization mismatch, epoch/ordering errors) on a 16 GB laptop; arena-separated Loopback makes distributed runs deterministically replayable for the differential tester; the injector tests adversity without a network. Acceptance gate: identical output at locales 1, 2, 3 and 8, which extends D1 determinism to locale count. | Localhost cannot expose interconnect bandwidth limits, congestion collapse or real partition behaviour; those need the rented multi-node runs. |
| NPU route | A restricted, pure, shape-checked `@tensor` sub-language (a StableHLO-subset op set) that PRINTS textual StableHLO, CoreML MIL protobuf and ONNX, with native CPU-SPMD and GPU-tile lowerings as the reference; no direct NPU codegen ever | No NPU has a published ISA, so the only portable authority is a graph IR consumed by a vendor compiler. CoreML reaches the M1 Pro's ANE, the only NPU we own. Having native lowerings means `@tensor` code is not NPU-only and gives a differential-testing oracle for the exported graphs. | Entirely gated on vendor toolchains: a CoreML or StableHLO schema change is unfixable by us, and the ANE offers no tiling or precision control and may silently fall back to GPU/CPU. The honest claim is 'we export to NPUs', not 'we compile for NPUs'. |
| Colorless async and the I/O layer | `Io` is an explicitly passed capability interface (blocking / io_uring / kqueue / iocp); suspension uses the SAME fiber mechanism as continuation stealing, so there is no async function coloring and no state-machine transform | One context-switch implementation serves both fork/join steals and I/O suspension, which halves the runtime's hardest code and means a single `parallel` scope can host CPU tasks, I/O tasks and GPU launches uniformly. Passing the implementation (Zig std.Io's approach) lets the same source target blocking or io_uring, with the documented syscall-count win. | Every task costs a fiber stack plus guard pages, so very high concurrency I/O is worse than state-machine coroutines; the per-task memory ceiling must be measured in M1, not discovered in production. On macOS raw syscalls are unsupported, so libSystem is a mandatory link dependency. |

Making both the schedule and the machine model into reviewable, version-controlled build inputs keeps the compiler deterministic, makes performance changes appear in code review, and puts them on the same footing as PGO profiles. A stale artifact is a warning that falls back to the cost model, never a build break. | Artifacts rot silently as kernels evolve, so tuned performance quietly regresses to cost-model quality. Mitigation: CI reports the fraction of tuned sites that are stale, and the tuner's search space is restricted to result-preserving transforms in D1/D2 so a schedule can never change answers (verified bit-for-bit against the cost-model schedule). |

## Design

## 1. Parallel IR: one mechanism, reused everywhere

`pir` (mid-level, SSA, flat SoA index-referenced) carries four instruction families that every execution mode lowers through:

- `detach(captures) -> spawned_bb, cont_bb` / `reattach` / `sync` — Tapir triple, CFG-embedded so scalar passes work by treating `detach` as a branch. A verified side task-tree index enforces: `detach` dominates its `reattach`, `sync` post-dominates all reattaches in scope, no allocation escapes a task frame.
- `spmd.region(width) { ... }`, `vec.*` ops, `mask.*` ops.
- `tile.load/store/dot/reduce/scan/sync` — the GPU and tensor level.
- `place.on(locale|device)` — a placement operand on `detach`, not a separate construct.

The capture list on `detach` is typed by reference capabilities, so *non-interference is a type-checked precondition*, not something a race detector recovers. Alias analysis may therefore assume disjointness inside a detached region. That is the structural advantage over Tapir-on-LLVM, which needed taskframes and a race detector retrofit.

**Serial elision is a spec guarantee**: erasing `spawn`/`sync`/`place.on` yields a program with identical observable semantics in the safe, non-`@fastmath`, non-`@nondeterministic` subset. This is the reference semantics for the Miri-class interpreter and the differential tester, and it is why debugging a parallel Fors program is tractable.

## 2. CPU runtime

Continuation stealing. Each spawning function is compiled twice:

- **fast clone**: `spawn` = store live-out into a heap-resident spawn frame, push frame pointer to the Chase-Lev deque tail, call the child directly. `sync` = load one flag word; if unstolen, fall through.
- **slow clone**: entered only by a thief, which takes a fiber from its per-worker pool, restores locals from the spawn frame, and runs the continuation there.

Target: spawn ≤ 3x a plain call (Cilk-5 class). Deque: Chase-Lev with LDAR/STLR; the seq_cst fence in `pop` is emitted only when the deque is nearly empty. Parking: `os_sync_wait_on_address` on macOS 14.4+, futex on Linux, `WaitOnAddress` on Windows.

**Asymmetric cores.** Worker classes from `sysctl hw.perflevel0/1.logicalcpu`. P workers at `QOS_CLASS_USER_INITIATED`, E workers at `UTILITY`. Each class has a measured `capacity` weight (E ≈ 0.35-0.45 of P on M1 — measure, never assume). Victim selection: same class first (locality), then cross-class. Static and SPMD partitioning uses P cores only; work-stealing loops include E cores, because lazy splitting lets a slow worker simply take fewer chunks. **NUMA**: one steal domain per node, `3*|domain|` same-domain attempts before crossing, first-touch arena allocation with a `Locality` parameter on the allocator, `DistArray` partitions aligned to domains.

**Parallel loops** lower to recursive divide-and-conquer with *lazy binary splitting*: a worker runs items sequentially and splits its remaining range only when it observes a steal request (polled every K iterations, K from the cost model). No-contention overhead is then near zero, which is the concrete answer to Rayon's split-granularity problem.

**Allocation**: the `parallel` scope *is* an arena scope — per-worker bump arena, reset at scope exit — which removes most allocator contention by construction. Shared heap: own size-classed allocator, per-worker caches, 4 MiB `mmap` spans, MPSC remote-free stacks drained on allocation, `MADV_FREE` decay, `MADV_HUGEPAGE` for arenas > 2 MiB.

## 3. SIMD

```fors
fn saxpy(a: f32, x: [f32], inout y: [f32]) {
  for (xv, yv, m) in zip_simd(x, &y) {      // yields (vec<f32>, inout vec<f32>, mask)
    yv = select(m, a*xv + yv, yv)
  }
}
```

`vector<T,N>` (fixed, comptime N), `vec<T>` (sizeless, SVE/RVV; forbidden in aggregate fields, on the heap, in generic containers; `vec_len::<T>()` is a target-runtime query that folds on fixed targets), `mask<N>` distinct from `vector<Bool,N>`. `simd_chunks` yields the tail as a *masked* iteration, not a scalar epilogue — the ergonomic core of the design and the reason one source is efficient on NEON, AVX-512 and SVE.

`spmd(W) { ... }` is the ISPC model: default `varying`, `uniform` inferred by a single forward dataflow pass (no backtracking, preserving the near-linear typing promise), divergent `if` compiled to masks with an all-false skip branch inserted when the cost model says the body is expensive, `break`/`continue`/`return` via a mask stack. `W = native` default.

**Masking rule (normative)**: masked-off lanes have no observable effect and cannot fault or trap. Masked loads/stores never touch inactive addresses (real masked instructions where available, never a speculative wide load). Trapping arithmetic under a mask ANDs the overflow mask with the active mask; checks merge per basic block, not per op. ARMv8.0 NEON has no masked store, so tails use select plus lane stores — state the cost.

`fors.math`: our own scalar and vector libm written in Fors using `spmd`, Remez coefficient tables checked in as data, documented ULP per function, `@fastmath` reduced-precision variants. Multi-month; without it every transcendental benchmark loses to SVML/SLEEF.

## 4. Floating point and determinism

Strict IEEE-754 default. `@fastmath(reassoc, contract, nsz, finite, recip)` is lexically scoped and lives as a per-op IR attribute so inlining cannot leak relaxed semantics.

Reduction policy is in the operator, not a flag:

- `reduce(+, a)` — **default, D1**: fixed leaf blocks of `B = 4 * native_lanes`, partials array indexed by block number, deterministic pairwise fold. Bit-identical for a given binary and input regardless of thread count, steal pattern, core class or locale count. Accuracy is *better* than serial (O(log n · eps)). Cost ~2-4% bandwidth.
- `reduce.serial` (C bit-compat) / `reduce.fast` (any order, reassoc) / `reduce.exact` (Neumaier; verification oracle).

**Determinism ladder**: D0 `@nondeterministic`, D1 run-reproducible (**default for the safe subset**), D2 portable-reproducible (no FMA contraction, our libm only). D1 is enforced in CI: every parallel test runs at T ∈ {1,2,3,7,8} and at locales ∈ {1,2,3,8} under a steal-injection fuzzer, requiring bit-identical checksums.

## 5. GPU

Canonical device IR: **SPIR-V**, emitted directly as binary (documented word stream, no relocations — tractable to write). Printers from `pir.tile`: MSL text (**first**, the only local GPU; content-addressed `.metallib` cache, AOT `xcrun metal` for release), SPIR-V binary (Vulkan → Linux/Windows/Android/AMD, plus Metal via MoltenVK), PTX text via `cuModuleLoadDataEx` (**second**; driver JIT does regalloc and scheduling, `mma`/`wgmma`/TMA reachable). AMD comes through Vulkan compute; HIP's peak path is LLVM-bound and we decline it at a stated 10-30% cost on some kernels.

**Device subset** (`@device` effect): value types with fixed layout, `vector<T,N>`, tiles, structured control flow, comptime/generics, contracts, atomics. Forbidden: heap allocation, runtime recursion, dynamic dispatch, FFI, any I/O capability, `spawn`, scalable `vec<T>`, unwinding. Faults write to a per-launch `FaultRecord` (first fault wins: kernel, lane, line); the host turns the flag into a normal Fors error. Barriers only in uniform control flow — statically checked by reusing the SPMD `uniform`/`varying` analysis.

**Memory and capabilities.** `Device` is a capability value derived from the module-declared `gpu` capability; no ambient device access. A launch is a `spawn` with `place.on(dev)`: `let` captures become shared-immutable on device, `inout` captures are moved into the launch's isolation domain and are statically unborrowable on the host until the scope syncs. `Memory.unified` vs `.discrete` is a `Device` property; `buf.host_view()` exists only when unified *and* unborrowed, which is exactly Metal's shared-storage coherency rule — the borrow checker enforces it for free. The IR `transfer` op lowers to nothing when source and destination spaces alias.

## 6. Distributed

`Locale` is a value; `on loc { }` and `spawn on Locales[i] f(x)` reuse fork/join, so structured concurrency and error propagation span nodes. Crossing a locale boundary is legal only for isolated (moved, `sink`) aggregates, serializable shared-immutable values, or global handles (`DistArray` descriptors, `Locale`, `Device`). Because isolated values have no incoming aliases, serializers are derived structurally — no annotations, no reflection.

`DistArray<T, Dist>` with `Block`, `BlockCyclic(k)`, `Cyclic`, `Replicated`, `Irregular(map)`. `forall i in a.local_indices()` gives provably local access; a non-provably-local subscript inside a `forall` is a **compile error** unless spelled `a.remote[i]` or batched via `a.gather(idx)`. Transport is an explicit interface: `Loopback`, `UnixSocket`, `Tcp` (v1); `Rdma` (libfabric) and `MpiInterop` later. Wire framing: 8-byte header (op, epoch, task id, length) plus a type-layout content hash reusing module-interface hashing to catch version skew; every message is an active message ("run task T in epoch E"), so there is no RPC server code.

Dev loop: `fors run --locales=8` (8 processes, UnixSocket, 1 worker each) plus arena-separated single-process `Loopback` for deterministic replay, plus `--inject=latency:200us,reorder:5%,drop:0.1%`.

## 7. NPU

`@tensor` functions form a pure, shape-checked closed op set chosen as a StableHLO subset (~80 ops: `dot_general`, `convolution`, `reduce`, `reduce_window`, `broadcast_in_dim`, `scatter`/`gather`, `dynamic_slice`, elementwise, `custom_call`). Export printers: textual StableHLO (consumed by `stablehlo-translate` / PJRT — printing a dialect needs no MLIR dependency), CoreML MIL `.mlpackage` protobuf (reaches the local ANE), ONNX protobuf. The same function also lowers natively to CPU SPMD and GPU tiles, which is the differential-test oracle for exported graphs within a declared tolerance. Honest framing: we *export* to NPUs; performance and precision are the vendor compiler's.

## 8. Benchmark harness: parallel kernels and scaling method

Kernels (each with serial reference, checksum gate, documented arithmetic intensity): PRK `nstream`, `stencil`, `transpose`, `dgemm`, `sparse`, `p2p`; NAS `cg`, `ft`, `mg`, `is`, `ep` (class S/W/A local, C/D on rented boxes); task-parallel `fib`, `nqueens`, `cilksort`, `UTS` (load-imbalance / E-core stress), GAP `bfs`+`pagerank`; SIMD `mandelbrot`, `aobench`, `black-scholes`, `convolve`, `softmax`; a reduction-determinism suite (`sum`, `dot`, `logsumexp`) on adversarial mixed-magnitude inputs scored against a 256-bit oracle.

Baselines: C+OpenMP (clang, gcc), Rust+Rayon, OpenCilk, Kokkos, Go, Java (Streams + Vector API), JS (Node Workers + Atomics), Python (numpy + multiprocessing, and pure Python as the honest floor), Zig, Swift. GPU: Metal/MPS/MLX locally, CUDA on rented CI.

Scaling protocol on 6P+2E — three curves (P-only 1-6, P+E 7-8, oversubscribed 16); efficiency reported **both** as speedup/cores and as speedup/**capacity** (Σ measured core weights), since the latter is the only honest number on an asymmetric machine; `caffeinate`, 3 discarded warmups, thermal state logged, CoV reported and flagged above 5%. Portable metrics only by default (`rusage`, `mach_absolute_time`); hardware counters only where a no-sudo path exists (Linux `perf_event_open`) — no macOS PMU dependency.

**Transfer honesty.** The laptop validates spawn/steal cost (scale-free), single-core efficiency vs C, SIMD utilization, determinism across thread counts, and relative regressions. It cannot validate NUMA effects, scaling knees, many-core bandwidth saturation, or interconnect behaviour. Results are JSON keyed by `machine_id`; the report generator refuses to plot two machines in one curve, and every published claim is tagged with the machine class entitled to support it. Scaling claims come from a weekly rented 64-core Graviton and 64-core Zen run.

## 9. Schedules and machine models as data

`schedules/<module>.fsched` keyed by (kernel IR hash, target triple, machine class) stores grain size, tile shapes, unroll factors, vector width, loop permutation, threadgroup size, shared-memory staging, prefetch distance, `Sched` policy, locale distribution. `targets/apple-m1pro.fmach` stores measured peak GB/s per level, cache sizes, spawn overhead, steal latency. The compiler never searches: missing entry → analytic cost model; stale hash → warning, never a build break. `fors tune --budget=30m` rewrites artifacts for human review, and in D1/D2 its search space is restricted to result-preserving transforms, verified bit-for-bit against the cost-model schedule.

## Interfaces other subsystems must honor

- Memory model / type system MUST provide: (a) parameter conventions let/inout/sink/set; (b) reference capabilities isolated / exclusive-mutable / shared-immutable / read-only as first-class types, not attributes; (c) a cheap syntactic disjointness judgement for sibling `spawn` captures, ranked distinct-variable < trusted-split < index-partition-token, with NO lifetime annotations and NO region inference (per owner decision); (d) a `@disjoint`-attributed stdlib split primitive (e.g. `split_at` returning two `inout` slices) whose disjointness the checker trusts because it is proved once in the stdlib; (e) a `@sizeless` type marker so scalable `vec<T>` can be rejected in aggregate fields, heap allocations and generic containers; (f) structural serializability derivable from isolated aggregates with no annotations or reflection (this is what makes distribution sound).

## Top risks

- Pointer authentication versus stack switching on Apple Silicon is genuinely undesigned territory: `pacibsp` diversifies the signed return address with SP, so resuming a stolen continuation on a different fiber stack breaks `autibsp`. Our answer (task-id-modified signing, or no PAC in compiler-generated spawning clones) trades ROP diversification for the ability to continuation-steal at all, and it must be validated by steal-injection fuzzing in M1 before anything is built on top of it.
- Two backends times parallel constructs multiplies the project's existing #1 risk of dev/release semantic divergence. A language whose pitch is safety cannot ship 'correct in debug, racy in release'. Serial elision as normative semantics plus differential testing across interpreter / dev backend / release backend at multiple thread counts is the only defence, and it must be in place before M3, not after.
- D1 determinism-by-default may prove to be a tax we regret: it forbids atomic accumulation and first-writer-wins patterns, requires partials arrays, and if the `@nondeterministic` escape hatch is at all awkward users will annotate everything and the guarantee becomes decorative. It is also the most differentiated claim we have, so weakening it later is expensive reputationally.
- Our own scalar and vector libm is a hidden multi-month project with an accuracy-versus-speed matrix per function. With no LLVM there is no SLEEF/SVML fallback, and until it is good every transcendental-heavy benchmark (black-scholes, softmax, any ML-shaped kernel) loses visibly.
- Three GPU printers (MSL, SPIR-V, PTX) plus three runtime APIs plus three validation environments, with no local NVIDIA or AMD hardware. CUDA and ROCm quality will lag, and there is a real chance every publishable GPU number is Metal-only for the first two years.
- The tile-level GPU pass (tiling, shared-memory staging, coalescing, later warp specialization and async pipelining) is most of Triton's actual value and took a team years. Building it without MLIR is the single largest unbudgeted engineering item in this subsystem.
- Forbidding implicit fine-grained remote gets will be read as 'not really PGAS' and may sink distributed adoption, while achieving Chapel-class parity still requires serious communication-scheduling work in the runtime. We buy predictability with ergonomics and have to defend that publicly.
- The NPU story is entirely gated on vendor graph compilers. A CoreML or StableHLO schema change is unfixable by us, the ANE gives no tiling or precision control and may silently fall back to GPU/CPU, and fp16-only op coverage limits what we can claim.
- Laptop-only data on 6P+2E is structurally incapable of supporting the >= 90%-efficiency-to-64-cores target, and NUMA, scaling knees and bandwidth saturation are invisible on it. The plan depends on a recurring rented-CI budget (weekly 64-core arm64 + 64-core x86, occasional GPU instances); if that lapses, the goal-4 claims become unfalsifiable and the project loses credibility the way V's LoC/sec numbers did.
- Using fibers for both fork/join and async means one stack plus guard pages per task. At 10^5 concurrent I/O tasks this is strictly worse than state-machine coroutines, and the per-task memory ceiling must be measured in M1 rather than discovered when someone writes a server.

## Decision points for Marc to code personally

- `runtime/src/deque.rs :: Deque::pop` — place the arm64 memory fence: relaxed load of `top` with `dmb ish` only when size <= 1, versus a fence on every pop. 6 lines. Trade-off: correctness of the race against a concurrent thief versus a fence in the hottest loop in the runtime. Writing this yourself is the fastest way to internalize the acquire/release model everything else rests on.
- `runtime/src/topology.rs :: WorkerClass::weights` — choose the E-core relative-throughput policy: measured at startup (accurate, adds startup jitter), checked-in per machine model (reproducible, can be wrong), or a hardcoded 0.4 (simple, dishonest). 8 lines. Trade-off: reproducibility of every published efficiency number versus adaptivity.
- `runtime/src/steal.rs :: choose_victim` — how many same-class steal attempts before crossing the P/E boundary. 7 lines. Trade-off: cache locality and avoiding slow victims versus latency to find available work when your class is idle.
- `compiler/src/pir/grain.rs :: grain_for_loop` — the constant converting estimated body cost (cost-model units) into a grain size. 5 lines. Trade-off: spawn overhead versus load imbalance. This single number moves most of the parallel benchmark suite; you should feel how sensitive it is.
- `compiler/src/pir/reduce.rs :: reduction_block_size` — the fixed leaf-block size B that DEFINES D1 reproducibility. 6 lines. Trade-off: partials-array memory and pairwise accuracy depth versus vector efficiency. Note it becomes a results-visible constant: changing B later invalidates every published number.
- `compiler/src/vector/mask.rs :: merge_trap_checks` — merge masked-overflow trap checks per basic block or per operation. 9 lines. Trade-off: the cost of trap-on-overflow inside SIMD kernels versus knowing which operation overflowed. This is where 'trap in all modes' meets 'fast vector code' and one of you has to give.
- `runtime/src/dist/transport.rs :: frame_header` — the 8-byte wire header field layout and whether the type-layout hash is 32 or 64 bits. 8 lines. Trade-off: bytes per small message (fine-grain distributed performance) versus collision risk on version skew, which would corrupt silently.
- `compiler/src/gpu/tilemap.rs :: default_threadgroup` — the default tile-to-threadgroup mapping when no schedule artifact exists on Metal. 10 lines. Trade-off: occupancy versus shared-memory footprint per threadgroup.
- `bench/harness/capacity.py :: efficiency` — the published efficiency formula: speedup/cores versus speedup/capacity. 6 lines. Trade-off: intellectual honesty on an asymmetric machine versus comparability with everyone else's numbers. You should write this one personally; it is the credibility of every parallel claim Fors ever makes.
- `runtime/src/fiber_arm64.s :: fors_fiber_switch` — the callee-saved register set (x19-x28, d8-d15, sp, fp, lr) and the PAC/LR handling on a fiber switch. 10 lines of assembly. Trade-off: security diversification versus the ability to resume a continuation on a different stack at all — the crux of the whole continuation-stealing design.
