# Fors design: compiler-architecture

> **Status: design-panel draft, 2026-09-19.** Produced by one subsystem architect working alone. Where this conflicts with `docs/PLAN.md` (section 4, Resolutions), PLAN.md wins. Cross-design conflicts are catalogued in `reviews.md`.

## Summary

The Fors compiler is a persistent-daemon, query-driven, six-level pipeline written in Rust with zero LLVM: SoA tokens → SoA AST → FIR (typed semantic IR, also the binary module interface) → FMIR (checked mid IR: ownership, isolation domains, contracts, structured parallelism) → OIR (CFG-SSA optimizer IR with mandatory alias classes and Tapir-style parallel terminators) → LIR/MC (machine IR, Mach-O/ELF atoms). Two backends share everything above OIR: a copy-and-patch dev tier for sub-50ms incremental rebuilds and an optimizing release tier built as CFG-SSA plus a Cranelift-style acyclic e-graph mid-end, ISLE-style declarative instruction selection, and SSA chordal register allocation. The single biggest lever for goal G3 is not the backend but the architecture around it: content-hash per-declaration queries, no textual include, a resident daemon that is simultaneously the LSP server, and our own atom-based incremental Mach-O writer that re-signs only dirty code pages via APFS clonefile plus incremental CodeDirectory rehashing — the concrete answer to "in-place patching breaks code signatures on macOS". One FMIR interpreter serves three roles (comptime VM, Miri-class reference semantics, differential-testing oracle), which is the highest-leverage engineering decision in the plan. Errors are values with a cold-outlined failure path and panics are `brk` traps with a side table, so there is no unwinder, no landing pads, and no EH tables in the hot codegen path. Determinism is bought structurally: reduction tree shape is specified in the IR by declared width, not by the machine's vector length, so vectorized float reductions stay bit-reproducible across targets. Honest codegen forecast: ~1.6x of best-of(clang,gcc,rustc) at month 15, ~1.2x at month 24, 1.05–1.10x geomean on the pinned suite at month 36–48, with named SoA/SPMD kernels beating clang earlier because structural aliasing and explicit SIMD are things LLVM still cannot get from C. Everything is instrumented for the Milestone-0 harness from the first commit: stable phase-timing JSON, deterministic reproducible builds, explicit cold/warm/incremental modes, and a `--no-daemon` switch so compile-speed numbers are never quietly flattered by a warm resident process.

## Decisions

| Decision | Choice | Rationale | Risk |
|---|---|---|---|
| Release optimizer architecture | CFG-SSA with a Cranelift-style acyclic e-graph (dedup-on-insert, no fixed-point saturation) as the scalar mid-end; explicit loops preserved throughout | HPC transforms and Tapir-style parallel regions need explicit loop structure and program order, which sea-of-nodes destroys; the aegraph removes the phase-ordering problem for algebraic simplification/GVN/strength reduction at bounded compile cost and is already production-proven in Cranelift; CFG-SSA is also vastly better documented, which matters for a solo dev with AI agents. | Traditional CFG-SSA passes are individually weaker than a fully saturated e-graph; some cross-loop algebraic wins are left on the table. Mitigated by running the aegraph twice (pre- and post-inlining). |
| Register allocation | SSA-form chordal-graph coloring (Hack-Goos) with loop-boundary live-range splitting and Boissinot SSA copy coalescing; dev tier uses a fixed template register discipline, no allocation | SSA interference graphs are chordal, so optimal coloring is polynomial and needs no build-coalesce-spill iteration loop; delivers within a few percent of LLVM greedy at roughly a fifth of the engineering, and the spill placement is easy to reason about. | Spill-cost heuristics are where real quality lives; a naive implementation can lose 5-10% on register-pressure-heavy kernels. Needs a dedicated tuning milestone against the harness. |
| Instruction selection | Declarative ISLE-style pattern DSL compiled to Rust at build time; aarch64 first, x86_64 second | arm64's shifted/extended operands, addressing modes and fused forms are a large mechanical win best expressed as rules; rules are individually testable, AI-agent-friendly to author in bulk, and keep the hand-written Rust surface small. | Writing the rule compiler is upfront cost (~4-6 weeks) before any instruction is selected; rule-set overlap bugs cause silent miscompiles, so the differential tester must exist first. |
| Aliasing information representation | Alias class + disjointness set as a MANDATORY operand on every memory op, derived structurally from parameter conventions and affine ownership; verifier rejects memory ops lacking it | Ten years of LLVM noalias experience shows droppable metadata gets dropped, and that is precisely where the remaining performance gap to hand-tuned C lives. Making it an operand makes information loss a compile error rather than a silent slowdown. | Every pass must maintain classes correctly; a pass that merges disjoint classes conservatively degrades silently rather than failing. Mitigate with a per-pass 'alias precision' metric tracked in CI. |
| Error handling and failure ABI | Errors are values returned in the normal register set via Fors's own internal convention with cold-outlined error paths; panics/contract violations are brk traps plus a static pc->info side table. No unwinder, no landing pads, no EH tables, ever. | Deletes an entire subsystem (personality routines, CFI/compact-unwind for EH, cleanup landing pads), keeps the optimizer CFG simple, keeps check instrumentation at one instruction, and makes the zero-UB trap-everywhere semantics cheap. | No recovery from contract/bounds violations: a server cannot isolate a failing request without process/domain boundaries. Needs an isolation-domain-level restart story from the parallelism/runtime architect. C++ exceptions crossing FFI must abort. |
| Backtraces and frame pointers | Always maintain the x29 frame-pointer chain on arm64; backtraces walk FP, no CFI emitted at all | Apple platforms already keep frame pointers by convention; walking FP removes the need for .eh_frame/__unwind_info generation entirely in the dev path and makes panic backtraces and profiler sampling work by construction. | Roughly 1% codegen tax in leaf-heavy code and one fewer allocatable register. Provide an opt-in -fomit-frame-pointer release mode later, which then requires a real CFI emitter. |
| macOS incremental rebuild vs code signing | APFS clonefile of the previous image, patch dirty pages in the clone, recompute SHA-256 for dirty pages only and rewrite the ad-hoc CodeDirectory plus trailing LC_CODE_SIGNATURE, then rename over the target | arm64 macOS refuses unsigned binaries and in-place writes risk both an invalid CodeDirectory and a stale kernel vnode signature cache; clonefile is O(1), per-page hashing is proportional to the change, and rename gives a new inode so no cached signature is reused. This is what makes Zig's ELF-only ~30ms result reachable on macOS. | Depends on undocumented-in-practice details of the signature superblob layout and on dyld chained-fixups stability; Apple can change either in a point release. Mitigated by a CI conformance suite per macOS version and an ld64 fallback path costing 150-400ms. |
| Linker strategy | Own Mach-O/ELF writers plus our own incremental linker for the dev tier; system ld64/ld.lld for release builds until year 3 | The incremental dev path is the one that must be milliseconds and must be ours; release linking needs dylib stubs, TLV, objc sections, exports tries and chained fixups where the system linker is already correct. Spend the saved months on codegen, which is where G1 is won. | Two link paths can diverge in layout and symbol semantics, producing 'works in debug, breaks in release' bugs. Mitigate by running the differential test suite through both paths. |
| Comptime execution engine | A single FMIR interpreter serving comptime, const-eval, the Miri-class reference semantics and the differential-test oracle, with tier-up to the dev backend for hot comptime | One engine instead of three; the reference interpreter is required anyway for correctness infra, so comptime is nearly free. Flat typed IR plus tier-up avoids Zig's ~20x-slower-than-CPython comptime, which stems from AST walking and allocation churn. | In-process JIT on macOS needs MAP_JIT and pthread_jit_write_protect_np, and any hardened-runtime distribution of the compiler needs the allow-jit entitlement. Also couples comptime correctness to backend correctness; the interpreter must remain the oracle. |
| CLI process model | Resident fors-driver daemon that is simultaneously the LSP server; fors CLI is a thin socket client; --no-daemon exists for honest benchmarking | Process start, cache mmap and interner warmup are a third of the 50ms budget; a daemon amortizes them and gives IDE responsiveness for free from the same query DAG (rust-analyzer's proven route). | Daemon staleness and cache-coherence bugs are a classic source of 'clean build fixes it' distrust; needs an aggressive self-check mode and a documented kill switch. Also risks flattering our own compile-speed numbers if reported carelessly. |
| GPU device code emission without LLVM | Emit SPIR-V binary ourselves; emit MSL source text for Metal; emit PTX text for NVIDIA; vendor runtime compilers do the final step | SPIR-V and PTX are documented formats we can write directly, so most of the pipeline stays ours. Metal's AIR is LLVM bitcode, so source-level MSL through newLibraryWithSource is the only non-LLVM route on the dev machine's GPU. | Three divergent device paths, and MSL text emission loses our OIR-level optimizations to Apple's compiler; peak kernel performance will trail vendor-tuned kernels (the honest G4 position). Also exposes us to vendor compiler bugs we cannot fix. |
| C header import mechanism | Own preprocessor plus a declarations-only C parser (function bodies brace-skipped), with curated content-addressed .forsi interface artifacts for libc/POSIX/Darwin/Metal as the fast common path | Skipping function bodies more than halves the C frontend scope (~15-20k lines instead of ~50k); pre-translated interface artifacts mean the common build never parses a header at all, which serves both G3 and the declarative-build-graph principle. | Apple SDK headers lean hard on clang extensions (__attribute__, availability, _Nullable, __asm renames, __builtin_*); coverage gaps will surface as import failures on real libraries and will need continuous triage. |
| Parallel construct representation across lowering | Structured spawn/sync regions in FMIR lowered to Tapir-style detach/reattach/sync terminators in OIR, with serial elision guaranteed legal and exposed as --serial-elide | Scalar optimizations see through parallel regions instead of stopping at opaque runtime calls (the OpenCilk/Tapir result), and serial elision gives the differential tester a free deterministic oracle for race and determinism testing. | Every dataflow pass must respect parallel dominance rules; one pass that forgets is a data race the type system promised could not exist. Requires a verifier check plus fuzzing with --serial-elide comparison on every pass. |
| Float determinism under vectorization | Strict IEEE-754 default with no FMA contraction and no reassociation; reduce.tree(width=W) fixes the reduction tree shape by DECLARED width, independent of the machine's actual vector length; relaxations only in lexical @relax scopes | Resolves the reproducibility-versus-vectorization conflict structurally: a vectorized reduction is bit-identical across a 128-bit and a 512-bit target because the IR, not the hardware, determines the summation order. Verification also needs defined FP semantics. | Costs performance on wide machines where the declared width does not match native width (extra shuffles/partial vectors), and users will be tempted to widen W for speed, silently changing results across builds. W must be part of the reproducibility manifest. |
| Debug info format and path | DWARF 5 emitted directly into a __DWARF segment of the final image in the dev path (no dsymutil, no debug maps); dsymutil only for release artifacts built through ld64 | lldb reads DWARF from the executable natively, so the dev tier avoids a whole external step in the incremental loop, and debug info becomes just another set of patchable atoms. | Incremental DWARF patching is genuinely hard: line tables and DIE offsets shift when a function grows. Initial approach is to regenerate the whole __DWARF segment for changed compilation units, which costs budget as project size grows and may force a per-CU DWARF design earlier than planned. |

## Design

## 1. Pipeline and IR levels

| Lvl | Name | Form | Owns |
|---|---|---|---|
| L0 | Tokens | SoA arrays (`kind: Vec<u8>`, `offset: Vec<u32>`) | lexing, no preprocessor |
| L1 | AST | SoA, index-referenced, per-decl subranges | syntax, `imports-first`, order-independent decls |
| L2 | **FIR** | typed semantic IR per declaration, generic-still-generic (Carbon SemIR/ZIR style) | name res, local syntax-directed inference, comptime calls; **serialized verbatim as the binary module interface** |
| L3 | **FMIR** | CFG, typed values, explicit moves/conventions, isolation domains, contracts, bounds checks, `spawn/sync`, `vector_for`, `kernel` regions | ownership/move check, race check, contract discharge, reference interpreter, comptime VM |
| L4 | **OIR** | pure CFG-SSA, low types (scalars/`vec<T,N>`/ptr+provenance), **mandatory alias classes**, Tapir `detach/reattach/sync` terminators | all optimization, target-independent |
| L5 | **LIR** | SoA machine IR, target opcodes, vregs → pregs | isel, regalloc, scheduling, frame layout |
| L6 | **MC/Atoms** | encoded bytes + relocs, one atom per function/global | Mach-O/ELF emission, incremental patching |

FIR is the interface format: no header re-parsing, no textual include (the TCC data point: 77k lines → 1.95M after includes). FMIR is the semantic ground truth — the reference interpreter, the comptime VM, the race checker and the contract prover all read *it*, never the AST. That single choice removes three would-be engines.

## 2. Query DAG, daemon, compile-time budget

Own query engine (~2.5k lines, no Salsa): interned keys, per-revision arenas, recorded deps, red-green invalidation keyed on **BLAKE3 content hashes of each declaration's token subrange**. A whitespace or comment edit, or an edit inside a function body, hashes to a changed *body* key but an unchanged *signature* key, so downstream typechecking stops at the first equal hash. Cross-unit deps are module-level (coarse, cheap); intra-module deps are per-declaration.

`fors` CLI is a thin client over a unix socket to a resident `fors-driver` daemon that is also the LSP server (rust-analyzer's lesson: this is architecture, not a feature). Budget for a single-token edit in a 100k-line project, p95 target 50ms:

| Phase | ms |
|---|---|
| client RPC + revision bump | 1 |
| read + lex changed file (2k lines) | 1 |
| parse changed file | 1.5 |
| resolve/typecheck ~40 affected decls | 9 |
| FMIR build + ownership/race/contract checks | 6 |
| dev codegen (copy-and-patch, ~6k instrs) | 3 |
| incremental link + dirty-page re-sign + clonefile/rename | 7 |
| slack | 21 |

Cold build parallelism: work-stealing over declarations (crossbeam-deque), sharded interners, per-thread bump arenas merged at phase end, zero `Rc`/`RefCell` in query outputs. Target ~4.5x on 6 P-cores. Parallel front-end from day one — retrofitting it is what has kept rustc's version unstable for a decade.

## 3. Release optimizer: CFG-SSA + acyclic e-graph

**Decision: CFG-SSA, not sea-of-nodes, with a Cranelift-style acyclic e-graph (dedup-on-insert, no fixed-point saturation) for the scalar mid-end.** Sea-of-nodes dissolves loop structure and program order — exactly the things HPC transforms (tiling, unroll-and-jam, SPMD widening) and Tapir's serial-elision rule need — and it is hostile to debug info. The aegraph gives phase-order-free algebraic simplification/GVN/strength-reduction at bounded compile cost, and it is production-proven.

Pass list, ordered by runtime-perf per unit of engineering:
1. **Inlining** (size+callsite heuristics, comptime-known-arg bonus) — largest single win.
2. **SROA/mem2reg** — mandatory given mutable value semantics; most `inout` params become registers.
3. **aegraph simplification** (fold, identities, GVN, strength reduction, reassoc only under `@relax`).
4. **Alias-aware store→load forwarding, DSE, move/memcpy elision** — affine moves make this unusually profitable.
5. **LICM** + invariant address hoisting.
6. **Check elision**: symbolic range + dominating-predicate analysis kills bounds and overflow traps. This is where "safety is free" is actually earned, and it is structural, never `unsafe`.
7. **Unroll + peel + if-conversion** (arm64 `csel` is cheap).
8. **Explicit SIMD lowering** with tail predication.
9. **isel** via ISLE-like rule DSL compiled at build time; arm64's shifted/extended operands and addressing modes are a large, mechanical win.
10. **Regalloc + coalescing** (§4).
11. **PGO**: instrumented edge counters → Ext-TSP block layout, inline weights, cold outlining into `__TEXT,__text_cold`. Profiles are content-addressed build inputs.
12. Scheduling last: M-series cores are out-of-order, so list scheduling buys little; software pipelining is a year-3 item.

Deliberately **not** doing: autovectorization (explicit SPMD instead), polyhedral loop transforms (checked-in schedules instead), heavy IPO beyond inlining.

## 4. Register allocation and aliasing contract

**SSA-form chordal-graph coloring** (Hack–Goos: SSA interference graphs are chordal, so optimal coloring is polynomial and needs no build-coalesce-spill iteration), with live-range splitting at loop boundaries and Boissinot-style SSA copy coalescing. Quality lands within a few percent of LLVM's greedy allocator at roughly a fifth of the engineering. Dev tier does no real allocation: fixed scratch-register discipline baked into the copy-and-patch templates.

Aliasing is an **operand, not metadata** — the recurring Rust/LLVM `noalias` failure is that metadata is droppable:

```
%v = load.f64 %p  alias=c7  disjoint={c3,c9}    // verifier error if alias= is absent
```

Alias classes come from parameter conventions (`let` = immutable, `inout` = exclusive, `sink` = owned) and affine ownership, computed once per function into a bitset matrix; `may_alias(a,b)` is an O(1) bit test. Any pass that produces a memory op without a class fails `--verify-each`. This is the concrete mechanism by which "structural aliasing closes part of the gap to clang" stops being a slogan.

## 5. Parallel / SPMD / GPU IR contract (for the parallelism architect)

FMIR: `spawn`/`sync` are *structured region ops*. OIR lowers them to Tapir terminators `detach L_task, L_cont, @sync_region` / `reattach` / `sync`, so dominance is parallel-aware and every scalar pass sees through parallel regions. Two hard rules: (a) **serial elision must always be legal** — `--serial-elide` rewrites every `detach` to a branch, giving the differential tester a deterministic oracle for free; (b) no value defined in a detached region may be used after its `sync` except through memory owned by the sync region. LIR lowering outlines detached bodies to a fixed runtime ABI `fors_rt_spawn(fn, frame*)`.

SIMD: `vec<T,N>` with comptime `N`; inside `vector_for` regions, `lane<T>` variables are SPMD with an explicit mask register. Scalable vectors (SVE/RVV) in v1 are handled by *choosing* a width at compile time plus predicated tails, not by sizeless types — honest cost: no width-agnostic binaries until `vec<T,?>` lands post-v1. Float determinism: `reduce.ordered` vs `reduce.tree(width=W)`; tree shape is fixed by the declared `W`, not by hardware vector length, so a vectorized reduction is bit-identical on a 128-bit and a 512-bit machine. FMA contraction and reassociation are off by default, enabled only in lexical `@relax(...)` scopes.

GPU: `kernel` regions are outlined at OIR level into device modules. We emit **SPIR-V binary ourselves** (documented format, no LLVM), **MSL source text** for Metal (AIR is LLVM bitcode, so source + `newLibraryWithSource` is the only non-LLVM route), and **PTX text** for NVIDIA. Vendor runtime compilers are the justified external dependency.

## 6. Object emission, code signing, incremental linking on macOS

Own Mach-O and ELF writers (`fors-obj`), own incremental linker (`fors-link`) for the dev tier, **system `ld64` for release** initially — a production Mach-O linker with dylib stubs, TLV, objc sections and chained fixups is months better spent on codegen.

Dev tier writes the executable directly: one atom per function with padding, cross-atom calls through an indirection stub table so growth never triggers relayout, and `LC_DYLD_CHAINED_FIXUPS` binds against libSystem. arm64 macOS refuses unsigned binaries, and patching a file in place risks both an invalid CodeDirectory and a stale kernel vnode signature cache. The rebuild sequence:

1. `clonefile()` the previous image (O(1) on APFS),
2. apply dirty-page patches to the clone,
3. recompute SHA-256 **only for dirty 4KB pages**, rewrite the ad-hoc CodeDirectory (32 B/page: 80 KB for a 20 MB binary) and the trailing `LC_CODE_SIGNATURE` blob with reserved slack,
4. `rename()` over the target — new inode, so no cached-signature kill.

Measured cost should be 3–7ms, inside budget. Fallback if dyld's format churns: shell out to `ld64` (adds ~150–400ms) — CI runs both paths against every macOS release.

## 7. ABI, C interop, debug info, errors

**ABI** (`fors-abi`): AAPCS64 with Apple's deltas (all varargs on the stack, HFA ≤4 elements in v-regs, aggregates >16 B indirect, `sret` in x8, i8/i16 argument promotion), then SysV AMD64. Expressed as a declarative table plus one classifier, validated by **`abi-fuzz`**: generate random C aggregate signatures, compile the peer half with clang, cross-link, compare values. 100k signatures green is the exit criterion. This is the unglamorous cost that stalls hobby languages; automating it is the only defense.

**C import without libclang**: our own preprocessor plus a *declarations-only* C parser — function bodies are balanced-brace-skipped, which cuts scope by more than half (~15–20k lines). Must handle Apple's `__attribute__`, availability macros, `_Nullable`, `__asm` renames, `__builtin_*`. Common path avoids parsing entirely: curated, content-addressed `.forsi` interface artifacts for libc/POSIX/Darwin/Metal, checked in as declarative data.

**Errors/failure ABI**: errors are values returned in the normal register set via Fors's own internal calling convention; cold error paths are outlined. **No exceptions, no unwinder, no landing pads, ever.** Panics/contract violations are `brk #1` plus a static pc→(message, source-loc) side table — one instruction of code growth per check. C++ exceptions crossing an FFI boundary abort, documented.

**DWARF/debugger**: DWARF 5 emitted straight into a `__DWARF` segment of the final image (no `dsymutil` in the dev path); lldb reads this natively. Frame pointers are **always** maintained on arm64, so backtraces need no CFI at all — a ~1% codegen tax bought in exchange for deleting the entire unwind-table pipeline. Sanitizers are unnecessary in the safe subset; instead ship `--interp` (Miri-class) and a trap-based debug allocator.

## 8. Comptime, reference interpreter, differential testing

One engine: the FMIR interpreter. Threaded dispatch over a typed slot arena, deterministic allocator, step/alloc/byte budgets, declared inputs only (`@embed` reads become build-graph edges; zero I/O capabilities), results memoized by BLAKE3 of (decl id, argument values, declared inputs). Hot comptime tiers up through the dev backend and runs natively in-process (needs `MAP_JIT` + `pthread_jit_write_protect_np`; flagged risk under hardened runtime). Zig's comptime being ~20x slower than CPython is a consequence of AST walking plus allocation — flat IR plus tier-up is the fix.

Correctness infra before v0.1: the interpreter with UB detection (provenance, uninit bits, convention-violation tracking), an **IR-level typed random program generator** (bounded loops, UB-free by construction, checksum output), a differential runner across {interp, dev, release -O1/-O2/-O3, PGO, `--serial-elide`}, and SoA-level delta-debugging reduction. Csmith-style differential testing is the only method with a track record here.

## 9. Cargo workspace

`fors-cli`, `fors-driver` (daemon+LSP), `fors-base` (arenas/interners/BLAKE3/diagnostics), `fors-query`, `fors-lex`, `fors-parse`, `fors-sema`, `fors-fir`, `fors-mir`, `fors-interp`, `fors-oir`, `fors-isle` (build-time rule compiler), `fors-codegen-dev`, `fors-lir`, `fors-target-aarch64`, `fors-target-x86_64`, `fors-abi`, `fors-obj`, `fors-link`, `fors-dwarf`, `fors-gpu`, `fors-cimport`, `fors-fuzz`, `fors-bench` (harness adapter), `xtask`. Many small crates, hand-written binary serialization (no serde derive in hot crates), no proc macros in the pipeline — Roc rewrote away from Rust over exactly this; keep bootstrap incremental builds under 10s.

## 10. Benchmark-harness contract (Milestone 0)

The compiler is instrumented for the harness from commit one: `--timings=json` with a versioned, stable phase enum; reproducible deterministic output (no timestamps, sorted iteration, content-addressed cache); `--cache-dir` and `fors cache clear` for honest cold runs; **`--no-daemon`** so cold numbers are never flattered by a warm process, with daemon numbers reported as a separate, clearly labelled row; `-O0..-O3`, `--cpu=host`, `--target`, `--threads`/`FORS_NUM_THREADS`, static-by-default linking for the binary-size metric, `--emit=obj,asm,oir`, `--pgo-gen/--pgo-use`; and `fors run kernel.fors` with zero project config so Fors can join the suite kernel-by-kernel. The compiler itself plus a generated 100k-line corpus are the compile-speed benchmarks; never report LoC/sec.

## 11. Honest codegen forecast

| When | State | vs best-of(clang,gcc,rustc) |
|---|---|---|
| m6 | dev backend only | 2–4x slower |
| m15 | release v0 (inline/SROA/aegraph/LICM/unroll/isel/RA) | ~1.6x geomean |
| m24 | + SIMD, checks elision, PGO, parallel lowering | ~1.2x geomean; SoA/SPMD kernels 1.3–3x *faster* |
| m36–48 | + scheduling, pipelining, better IPO | 1.05–1.10x geomean on the pinned suite |

Parity within 5% on a SPEC-class suite is a 4–5 year outcome, not a v1 outcome, and individual C++-idiom-heavy benchmarks will stay 1.5x+ behind. Say this publicly before anyone benchmarks us — the V language's reputational damage came from unreproducible claims, not from slow code.

## Interfaces other subsystems must honor

- PARALLELISM: FMIR must receive spawn/sync as structured regions, not runtime calls. The compiler guarantees (a) Tapir detach/reattach/sync terminators in OIR, (b) legal serial elision at all times, (c) no value defined in a detached region used after its sync except through sync-region-owned memory. Runtime must expose exactly one task ABI: fors_rt_spawn(fn_ptr, frame_ptr) plus fors_rt_sync(region_id).
- PARALLELISM: SIMD type surface is vec<T,N> with comptime N plus lane<T> inside vector_for regions with an explicit mask value. No sizeless/scalable vector types in v1. Reductions must be written as reduce.ordered or reduce.tree(width=W); the compiler will not silently choose a reduction order.
- PARALLELISM/GPU: kernel regions are outlined at OIR level; the parallel model must express launch geometry as explicit grid/block operands and must not assume a unified address space. Device targets are SPIR-V (ours), MSL source (Apple), PTX text (NVIDIA).
- MEMORY MODEL: parameter conventions (let/inout/sink/set) and affine ownership must be decidable per-declaration with no whole-program analysis, because they are the sole source of OIR alias classes. If a convention cannot be checked locally, the optimizer loses its aliasing advantage and G1 regresses.
- SECURITY/BUILD: the build graph must deliver capability sets and content hashes as declarative data the query engine can hash as inputs. The compiler enforces capability checks over the module graph at FIR level and at link time, and marks FFI subtrees unguaranteed; it does not execute build code, ever.
- SECURITY/VERIFICATION: contracts arrive in FMIR as pre/post/invariant ops with runtime checks emitted by default. Static discharge is an out-of-process SMT query with a timeout, keyed by content hash; on timeout the runtime check stays. The SMT encoding must use machine types matching FMIR types exactly (Verus-style), not idealized integers.
- PACKAGE MANAGER: module interfaces are FIR blobs addressed by content hash; the resolver must give the compiler an immutable, fully-pinned input set before any query runs. A dependency's capability set change must be a resolution-visible event, not a compile-time surprise.
- STDLIB/RUNTIME: allocators are explicit values threaded through APIs; the compiler assumes no hidden allocation and no global allocator. Panic/contract failure path is brk plus a static side table, so the runtime provides only a trap handler and a backtrace printer that walks the frame-pointer chain.
- BENCHMARK HARNESS (Milestone 0): the compiler commits to a versioned --timings=json phase schema, reproducible deterministic output, --cache-dir plus cache clear for cold runs, --no-daemon for honest cold-start measurement, -O0..-O3, --cpu=host, --threads/FORS_NUM_THREADS, static-by-default linking, and single-file `fors run kernel.fors` so Fors can join kernel-by-kernel with no project config.

## Top risks

- Release-backend codegen quality is the pivotal unknown and nobody has a published cost model for a solo-built optimizing backend. If month-15 geomean lands at 2.5x instead of 1.6x of best-of-C/Rust, G1 is unreachable on the stated horizon and the public claim must be narrowed to 'parity on named kernel classes' rather than general parity. Early warning signal: the C6 exit criterion; treat a miss as a scope decision, not a schedule slip.
- Mach-O plus dyld dependence on semi-documented behavior (chained fixups layout, ad-hoc CodeDirectory superblob details, kernel signature caching) makes the flagship sub-50ms incremental claim hostage to Apple point releases. The ld64 fallback keeps us correct but costs 150-400ms, which breaks the headline number, not the product.
- Two backends will diverge semantically (Zig has documented exactly this on pointer provenance and inlining). Without the C3 differential harness landing BEFORE C4, we will ship 'works in debug, wrong in release' bugs, which is the single fastest way to lose credibility for a systems language.
- Incremental DWARF is under-designed here on purpose: regenerating a whole compilation unit's debug info per edit is fine at 100k lines and may not be fine at 1M. This is the most likely reason the 50ms budget quietly erodes over year 2.
- Mandatory alias classes are only as good as the pass that preserves them. A pass that conservatively merges classes degrades performance silently with no test failure. The alias-precision CI metric is the only defense and it must exist from the first pass, not be added later.
- ABI and C-interop work is large, unglamorous and unbounded at the edges (Apple SDK clang extensions in particular). It is the classic place where hobby languages stall at 'works for my own code'. abi-fuzz plus curated interface artifacts bound it, but header-import triage will be a permanent background tax.
- Compiler parallelism plus an incremental query DAG is where rustc has had unstabilized race conditions for a decade. Doing it correctly from day one is right, but it means every query must be provably side-effect-free, and a single interner mutation bug produces nondeterministic builds that also destroy the reproducibility and supply-chain story.
- In-process JIT for comptime tier-up needs MAP_JIT plus JIT write-protect toggling on Apple Silicon and an allow-jit entitlement for any hardened-runtime distribution of the compiler; if that becomes untenable, comptime falls back to the interpreter and heavy comptime code gets slow, which is a visible G3 regression.
- Owner decision 3 ('everything in v1') combined with this pipeline means the release backend, GPU emission and distributed support all compete for the same solo-developer months. The sequencing above is honest about which of them slip: GPU quality and x86_64 land after CPU parity work, and vendor-tuned GPU kernels will beat us at peak regardless.

## Decision points for Marc to code personally

- crates/fors-abi/src/aarch64_apple.rs :: classify_aggregate() - write the 5-10 line predicate deciding register vs indirect passing: the <=16-byte threshold, the HFA <=4-element rule, and x8 sret. Trade-off: a more aggressive register threshold speeds small-struct calls but diverges from clang and breaks C interop. This is the line where ABI compatibility is either exact or subtly wrong.
- crates/fors-oir/src/alias.rs :: may_alias() - write the O(1) bitset disjointness test and the rule that two distinct inout parameters are unconditionally disjoint. Trade-off: the stronger the rule, the more vectorization you unlock and the more you depend on the convention checker being sound. This is the single line that most determines how much of the clang gap closes.
- crates/fors-query/src/revision.rs :: hash_eq_early_exit() - write the comparison that stops invalidation propagation when a declaration's content hash is unchanged. Trade-off: hashing signature and body separately costs a second hash per declaration but makes body-only edits free downstream. This is the mechanism behind the sub-50ms target.
- crates/fors-mir/src/lower_arith.rs :: emit_checked_add() - choose the aarch64 overflow-trap sequence: adds + b.vs + brk versus a pre-check compare. Trade-off: 2 instructions and a cold branch versus branch-predictor pressure in hot loops. This decides whether 'trap on overflow in all modes' is actually free.
- crates/fors-link/src/codesign.rs :: rehash_dirty_pages() - write the loop from the dirty-page set to updated CodeDirectory page hashes. Trade-off: rehashing only dirty pages is fast but the page-to-hash-slot mapping must be exactly right or the kernel kills the binary with a confusing SIGKILL. This is the load-bearing line of the macOS incremental story.
- crates/fors-lex/src/token.rs - choose the token SoA packing: (kind: u8, offset: u32) with length recomputed by re-scanning, versus (kind, offset, len) at 9 bytes. Trade-off: cache footprint during parse versus recompute cost in diagnostics. Measure it on the 100k-line corpus; this is the exact class of decision that gave Zig a 20% wall-clock win.
- crates/fors-interp/src/budget.rs :: charge() - decide the comptime step-accounting granularity: per instruction, per basic block, or per loop back-edge. Trade-off: coarse accounting is faster but lets a pathological straight-line comptime function overrun its budget. This defines the comptime denial-of-service boundary.
- crates/fors-codegen-dev/src/regs.rs - fix the copy-and-patch scratch-register discipline (which of x9-x15 templates may clobber). Trade-off: more scratch registers means better templates and worse template reuse across call sites. Everything about dev-tier code quality flows from this constant.
- crates/fors-oir/src/fp.rs :: contraction_allowed() - write the rule for when a mul+add may fuse into FMA inside a @relax(fma) scope, specifically what happens at a scope boundary mid-expression. Trade-off: lexical scoping is predictable but forbids the fusion users expect at the edges. This is where reproducibility is either honest or hand-wavy.
- crates/fors-bench/src/timings.rs - author the phase enum for --timings=json v1. Trade-off: fine-grained phases give better optimization signal but freeze internal structure into a public schema the harness depends on. Pick the ~10 phases you are willing to still support in 2031.
